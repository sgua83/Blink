# Blink 软件版本

根 `VERSION` 是 Blink 软件版本的唯一事实源，采用 `主版本.次版本.补丁号` 三个十进制整数。它是语言工具链与执行框架的软件版本，不使用 P4 全局 changelist 或 Git hash 充当版本号。首次建立该机制为 `0.2.0`；当前仍为研发版本。

## 提交公式

设 P4 最后成功提交版本为 `(M,m,p)`，每次正式提交计算一次：

| 本次变更 | 下一版本 | 提交选项 |
|---|---|---|
| 修复、性能、内部重构、文档或台账 | `M.m.(p+1)` | 默认 `patch` |
| 向后兼容的新功能 | `M.(m+1).0` | `-Bump minor` |
| 不兼容语言规则或公共接口变化 | `(M+1).0.0` | `-Bump major` |

开发者根据本次实际语义选择升级级别，脚本不猜测描述；默认补丁自动加一，不逢十进位。其他项目提交不影响 Blink 版本。

将任务文件放进实际 pending changelist 后，在对应 P4 用户／client 的工作区运行：

```powershell
powershell -NoProfile -File Tools/Submit.ps1 -Change 12345
```

编号替换为本次实际编号；兼容功能增加 `-Bump minor`，不兼容变化增加 `-Bump major`。正式项目提交统一使用该入口。脚本从 P4 已提交 `VERSION#head` 计算，将版本与本次文件同一 changelist 提交，不读取本地候选值作为上次成功版本，不在提交后再补一笔版本提交。首次引入本机制同时建立 VERSION 和入口，此后按本规则执行。

提交被拒绝时没有新的已提交版本；候选与真实错误保留，解决原冲突后再次调用入口重新计算，不自动重试。并发由同一 VERSION 文件的正常 P4 revision／resolve 处理，不建立计数服务或额外锁。其他任务在本 client 打开的 VERSION 不被覆盖。直接运行 `p4 submit` 不经过脚本，工程约定禁止绕过正式入口；没有安装服务器 trigger 或后台监控。

成功后仍由调用方立即按 AGENTS 异步启动一次既有 `Tools/PublishGit.ps1`，PA3 提交、本机发布同理；失败不启动发布。Git 复制同一已提交 VERSION，不再次递增，失败不回滚 P4。两本台账只留 P4。

## 构建、缓存与兼容身份

`blc --version`、`bllink --version`、`blrun --version` 及 `blanguage::VERSION`／`blcompute::VERSION` 读取同一构建版本。已发布 Git 源码可离线构建，不要求查询 P4、Git 或网络。Rust Cargo 包的既有 `0.1.0` 是内部包元数据，不作为 Blink 软件版本。

VERSION 更新工具内嵌显示，但不加入 BLINK_COMPILER_ID 或原生框架输入身份；仅版本或文档变化不使 B 对象／入口缓存全部失效。实际实现、源码依赖、公开合同、目标、工具链及配置继续按原规则失效。软件版本不替代 BLCO／BLRI 等实际格式和 ABI 身份，不承诺不同版本的产物一定兼容。

## 稳定版本与自举

版本递增、Release 档位、P4 提交与稳定发布分别记录。目前没有已验证的稳定 B 编译器发布，不能把新编号称为稳定版。以后由 B 实现编译器部件时，固定使用已实际发布、可独立取得的稳定 B 编译器精确软件版本与产物身份；开发编译器不能成为自己唯一的构建前提。稳定发布、B 自举及 CPU／GPU 协作编译仍需各自实际实现和验证。
