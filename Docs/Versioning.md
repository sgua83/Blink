# Blink 软件版本

根 `VERSION` 是 Blink 软件版本的唯一事实源，采用`用户段.进位段.变更段.提交号`四个十进制整数；当前用户段为`0`。它是语言工具链与执行框架的软件版本，不使用 P4 全局 changelist 或 Git hash 充当版本号。源码主线持续研发，正式发行身份以GitHub Releases的实际发布记录为准。

## 提交公式

设P4最后成功提交版本为`(U,R,C,S)`，每次正式提交计算一次：

| 本次变更 | 下一版本 | 提交选项 |
|---|---|---|
| 修复、性能、内部重构、文档或台账 | `U.R.C.(S+1)` | 默认 `patch` |
| 向后兼容的新功能 | `U.R.C.(S+1)` | `-Bump minor` |
| 不兼容语言规则或公共接口变化，C小于999 | `U.R.(C+1).0` | `-Bump major` |
| 不兼容变化，C已经为999 | `U.(R+1).0.0` | `-Bump major` |

普通提交和兼容功能只增加第四段。大改动增加第三段并清零第四段：第三段从998变为999时，第二段保持；第三段999再递增时，第二段才加一，第三／第四段归零。第四段没有99或999进位规则，不能自行推动第三或第二段。提交以当前P4版本为起点，不搬移已有各段数字、不重新编号。

例如，普通提交为`0.14.8.25→0.14.8.26`，大改动为`0.14.8.25→0.14.9.0`；进位为`0.14.999.25→0.15.0.0`。第三段已经999时的普通提交仍是`0.14.999.25→0.14.999.26`。

首段U由用户指定，普通提交原样继承已提交首段；patch、minor、major均不得改变它。当前固定为0，只有用户明确要求提升并指定新值时，才可由调用方传入`-UserStage <用户指定值>`；不得根据提交次数、不兼容变更或自判成熟度提升。后续计数仍按本次Bump计算，提升用户段不隐式重置它们；用户另有要求时以用户指定版本为准。软件编号与实际稳定发布分别记录。

开发者根据本次实际语义选择升级级别，脚本不猜测描述；patch与minor都自动增加第四段，major沿上表增加第三段及必要进位。其他项目提交不影响 Blink 版本。

将任务文件放进实际 pending changelist 后，在对应 P4 用户／client 的工作区运行：

```powershell
powershell -NoProfile -File Tools/Submit.ps1 -Change 12345
```

编号替换为本次实际编号；兼容功能增加 `-Bump minor`，不兼容变化增加 `-Bump major`。正式项目提交统一使用该入口。脚本从 P4 已提交 `VERSION#head` 计算，将版本与本次文件同一 changelist 提交，不读取本地候选值作为上次成功版本，不在提交后再补一笔版本提交。

提交被拒绝时没有新的已提交版本；候选与真实错误保留，解决原冲突后再次调用入口重新计算，不自动重试。并发由同一 VERSION 文件的正常 P4 revision／resolve 处理，不建立计数服务或额外锁。其他任务在本 client 打开的 VERSION 不被覆盖。直接运行 `p4 submit` 不经过脚本，工程约定禁止绕过正式入口；没有安装服务器 trigger 或后台监控。

任意节点成功提交后，由GUA／192.168.10.5的中央计划任务每天09:00和21:00调用 `Tools/PublishGit.ps1`，提交方不再启动Git发布，不需要GitHub凭据。每次读取GitHub远端main的P4-Change水位，覆盖其后所有节点的已提交变更；一次失败不推进远端水位，下次独立运行自然包含上次未发布范围。Git复制同一已提交VERSION，不再次递增，失败不回滚P4。两本台账只留P4。安装与操作见 [中央镜像发布](../Tools/README.md)。

## 构建、缓存与兼容身份

`bc --version`、`blink --version`、`brun --version`及`blink-setup --version`由各自命令行入口在编译时直接嵌入同一根`VERSION`。已构建工具报告自身构建时的版本，不在运行时读取工作区或查询版本库。编译库与执行库不消费显示版本，也不导出显示版本常量；只有工具因VERSION变化重新生成，必要的SDK目标库仍由原Cargo输入决定是否重编。已安装可用稳定Blink种子及Rust／Windows构建工具后，已发布Git源码可离线构建，不要求查询P4、Git或网络。Rust Cargo包的既有`0.1.0`是内部包元数据，不作为Blink软件版本。

VERSION 更新工具内嵌显示，但不加入 BLINK_COMPILER_ID 或原生框架输入身份；仅版本或文档变化不使 B 对象／入口缓存全部失效。实际实现、源码依赖、公开合同、目标、工具链及配置继续按原规则失效。软件版本不替代 BLCO／BLRI 等实际格式和 ABI 身份，不承诺不同版本的产物一定兼容。

## 每周正式发行

只保留P4研发主线。中央机每周日北京时间21:00先执行当轮源码镜像，再固定远端已确认Git提交及其P4快照，Release编译通过后打包发布。首次计划2026-11-01；21:00是启动时间，不是构建、上传或节点安装完成时间。没有新提交不重复发行；小bug与功能修改累计到周发行，不按提交次数逐个发包，不建立候选池、评分或稳定维护分支。

正式发行沿用快照中的VERSION，不再次递增。编译失败如实结束，沿原研发流程修复并通过Submit.ps1提交；修复后再针对新快照构建。新功能未完成时说明当前限制，不以所有长期Issues清零作为发行条件，也不把Release构建成功写成所有能力已完成或无bug保证。

PublishRelease.ps1从实际P4 client Root及Cargo target_directory取得路径，不固定开发盘符。正式构建输入是本轮Git镜像的精确快照，临时源码在原target/dist/source，输出复用原target。版本与平台包分别命名，同一个VERSION可以对应多个平台／架构资产；当前实际交付Windows x64的target/dist/Blink-Setup-windows-x64.exe，其他平台包尚未实现。GitHub Releases标签为v<VERSION>，关联原Git提交。

Windows包是原生自解压EXE，嵌入同源bc、blink、brun、Rust源码SDK、标准库及release.json；安装使用Rust标准库与Windows原生压缩／权限／环境接口，不需要用户执行PowerShell脚本或另装解压软件。源码SDK编译运行框架仍需要Rust MSVC、C++构建工具和Windows SDK；GPU使用实际系统Vulkan驱动。Git main源码镜像与正式发行分别记录。

-BuildOnly只构建当前工作区并标明working tree，不发布、不宣称已提交快照；正式定时入口不使用此选项。

## 安装与环境变量

普通用户从GitHub Releases下载本机平台的安装资产；Windows x64用户双击Blink-Setup-windows-x64.exe，由Windows正常管理员授权后安装。EXE把内容直接解压到本机%ProgramFiles%/Blink，新版覆盖旧版，只有当前安装，不建立版本目录。安装文件清单仍由同一release.json拥有；只移除上一包清单中已退出的文件，不清理工程、target或用户资料。下载文件由下载者持有，运维自动安装成功后清理本次下载，历史发行留在GitHub。

安装末尾自动把实际Blink/bin加入机器PATH，保留已有环境项且不重复追加，并向桌面广播Environment更新。新终端可直接使用bc、blink、brun；已运行进程持有原环境，不能把注册表已写入冒称所有既有终端已刷新。源码SDK的原显式工具路径不改。

同一个EXE支持--quiet管理员静默安装，返回真实退出码和INSTALLED／ALREADY_INSTALLED及PATH_CONFIGURED。--quiet不弹窗、不发起UAC；权限由既有管理员运维入口提供。普通用户会话通过同一EXE的--refresh-environment完成桌面通知，运维随后清理下载，不分发脚本、GitHub写凭据或新增服务。

## 节点运维与构建输入输出

中央机与所有节点从同一GitHub Release下载对应平台／架构资产。中央普通用户从GitHub下载该版本的平台资产到原target/dist，再由现有BLSupervisor put分发同一EXE至节点真实普通用户TEMP；system-exec／BLAdmin执行--quiet安装，普通用户通知桌面与清理本次文件。节点只需要现有运维网络，不要求额外外网或代理。下载路径来自节点真实执行结果，不嵌入中央开发路径，不复制代理配置。消费者由Matrix真实节点登记与BLanguage P4工作区Owner／Host及项目关系取得，不固定节点清单。

源码SDK的普通构建不启用installed特性，仍从原源码根读取SDK并使用原SDK target。默认compiler功能提供完整源码工具；B资源包装的SDK路径依赖关闭该功能，沿同一次Cargo依赖图和原target/dll生产实际运行角色，不调用词法种子或装入源前端。正式发行启用blanguage/installed：SDK从%ProgramFiles%/Blink读取，临时单元和运行框架输出写当前工程target。正式Compiler会话持有安装VERSION的真实只读使用句柄，直到最后共享消费者结束；原生安装器取得同一文件的排他使用权后才覆盖。占用失败明确结束，不杀进程、不伪造成功，不在使用中覆盖输入。部分覆盖失败撤销安装VERSION，避免把残缺目录作为可用SDK。

中央发布与节点安装分别输出PUBLISHED及INSTALLED；离线或安装失败不否定已发布事实，也不能宣称全体已采用。各节点独立执行，一台失败继续其他节点，最终汇总真实失败，不重试。没有新发行不重复发包，但仍可沿原维护入口使消费者安装当前版本；安装器遇到相同发行记录与VERSION时报告ALREADY_INSTALLED并确认PATH配置。

## 正式工具与后续自举

正式发行（本项目采用的稳定发行身份）是按每周流程编译并发布的确切版本，不保证全部新功能可用。由B实现的编译器模块使用已安装的稳定bc／blink生成并静态链接到工具，现行B／Rust职责以[架构文档](Architecture.md)为准；完整自举及CPU／GPU协作编译按实际实现记录。自举使用正式安装的工具与库作为本轮输入，研发源码是待编译内容，新工具写工程target；本轮输入消费者结束后，才由独立原生安装器覆盖正式目录。开发产物不能成为自己唯一的构建前提。
