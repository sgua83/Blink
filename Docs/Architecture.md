# Blink 语言架构

Blink（简称 B）提供独立的原生并行计算语言与执行基础，不依赖 BLEngine。接口 `.h`、实现 `.b`；词法扫描由B实现，解析、检查、原生代码生成、平台与物理资源生命周期仍由Rust实现。当前实现目标为 Windows x64 CPU 与 Vulkan GPU，不引入第三方编译器、Shader 编译器或并行运行时。

B 也寓意 Base。Blink 希望像 C 语言为上一个计算时代所做的那样，成为 AI 超算时代的基础语言。架构围绕并行计算、数据关系与协作展开，使算法意图能够由编译器与执行框架兑现为原生异构计算；具体能力与规模由当前实现和真实消费者推进。

## 软件版本与稳定自举

根`VERSION`是Blink软件版本的唯一来源，编译器、链接器、运行工具及安装器各自的命令行入口在构建时直接嵌入该版本。显示版本只由工具消费，不进入编译库或执行库的Rust接口和构建依赖；SDK实现、模块ABI及编译产物身份分别由其实际代码、合同和生产输入确定。正式提交在同一P4 changelist内自动递增，Git沿用原版本；编号不代替模块ABI或稳定状态。版本及文档变化不进入编译语义缓存身份，实际实现、源码、合同、目标和工具链继续决定失效。规则与实际入口见[Versioning.md](Versioning.md)。

自举以已经实际发布、可独立取得的稳定B编译器、链接器、所需运行库和标准库为种子；具体种子须核对其实际发行和可表达范围，不能只凭VERSION或安装成功认定可自举。稳定种子编译研发中的B编译器得到第一代工具，第一代工具再编译同一份编译器源码得到第二代工具；分别记录两代构建、实际语言／原生消费者与资源结果。研发产物写工程target，正在消费的种子不被覆盖，开发中的编译器不成为自己的唯一构建前提。正式发行仍沿现有每周流程、单一当前安装和独立安装器进行，不新增稳定分支或自举发布器。

编译器用B重构时保留原职责：源码与接口装入、类型／合同检查、并行IR、优化及x64／SPIR-V生成由编译器持有；独立blink只读取已编译对象、符号、合同和重定位；blcompute持有实际存储、提交及最后消费者。逐个真实模块以B接管后退出对应Rust消费，不逐字复制Rust容器／trait结构，不在B入口后继续调用Rust词法、检查或代码生成冒充自举。内部图可使用B现有数据组合、普通值序列和明确索引组织；只对真实不能表达的关系补语言能力，不将全部递归容器、其他平台或热更新作为自举前置。

CPU／GPU协同编译指编译器本身把适合批量计算的编译工作交给GPU，而非仅生成GPU代码。CPU持有源码、模块身份、依赖与诊断顺序，GPU消费明确批次的数据并交回计算结果；二者消费同一语义关系，不各存一套权威事实图。词法扫描、事实查询、数据流与代码发射中的候选工作须先确认真实热点、可独立输入及精确结果，再逐项实施；有依赖的解析、绑定、递归求解和最终链接保留其实际顺序。编译目标和编译时使用的设备分开，面向CPU的程序也可由GPU辅助编译，面向GPU的程序不因此要求编译设备就是运行设备。

编译器需要的GPU内核必须在其编译阶段形成原生产物；启动编译时装入已有映像，不要求先调用正在构建的编译器生成自己的必需内核。blcompute通过原blanguage依赖消费共同表示、ProgramImage／ExecutionPlan和资源编码。默认compiler功能保留完整Rust编译接口与bc／blink／brun；编译B资源包装时两个SDK依赖关闭默认功能，源解析／检查、模块装入、对象／链接构建不进入执行库。现有显式Rust原生生成与运行期助手仍需原后端，不能反向依赖整个blcompute为编译器引入环；完整后端预编译与运行库改用B继续分别交付，不另造运行时或编译服务。

编译器自举、blcompute改用B、CPU／GPU协作编译、计算域编译和域运行是分别闭合的能力。自举以B编译器主体真实接管、由独立稳定种子构建第一代并重建自身为准；正式调试、观察与分析工具同样纳入逐职责B研发和真实消费者，不用百分之百B或源码占比判定。保留的Rust运行库／独立本机支持、构建依赖及采用范围如实标明；完整工具链脱离Rust源码构建另行报告，需要实际覆盖所用运行库、链接和SDK等产物，不能把它当作自举的同义词或统一前置。域编译复用本次构建图及单节点编译器，域运行复用原生计划和资源所有者，不建立自举专属Domain／Node。详细实施范围与依赖唯一记录在Issues的C-032、C-033、C-034和原C-021.9／C-022.6至C-022.8；当前B词法模块已接管扫描，B前瞻模块已接管原泛型尖括号平衡扫描，完整编译器自举、运行库B迁移、GPU实际参与编译及计算域能力仍未完成。

系统互操作与自举分别判断。B应具备独立编写完整Windows及后续其他64位系统程序的能力；Windows接口沿真实x64 ABI直接生成系统DLL调用，后续平台沿各自实际ABI建设，不要求重新实现操作系统。接口声明以及承担类型、路径编码、错误与句柄寿命的B系统库有实际职责，应复用已有B接口；它们不等同无意义的语言外壳。Rust可承担确有独立价值的本机支持或库算法，边界和实际保留职责明确；仅为把B参数再次转交相同系统API而增加Rust中转没有必要。既不能把B外壳后仍由Rust承担的核心算法算成B接管，也不为提高B比例强制重写成熟独立库。语言能力、工具主体接管、原生支持保留及完整脱离Rust构建分别记录，具体实现仍沿原C-032和C-034，不另建迁移链。

## 长期系统设计目标与语言边界

本节记录已确定的长期目标与设计原则。B以成为AI超算时代的基石语言为目标，面向完整通用与系统编程，以顶级原生效率、原生分布式编译、编译器可控的原生并行与调度、稳定热更新为核心。编译、调试、观察与基础量化工具以AI为唯一直接使用者，顶级架构师和工程师通过AI取得事实与控制能力；原语言和模块接口仍支持实际消费者与上层编译器。B 不采用面向对象；这一点是确定的语言边界，不再作为候选或待论证方向。本节记录研发目标，不声明相关语法、后端、跨机执行、热更新、完整工具或目标性能已经实现。

BLEngine当前保留Rust＋B混合架构，是当前实现事实。B编译工具当前由B词法／泛型前瞻／对象元数据及栈字段读写、符号绑定、标准COFF结构及逻辑节／COMDAT／Target恢复与对象／归档格式生成，以及Rust其余语法构造、AST、检查、IR及后端组成；归档输入I/O、最终语言对象拥有容器与合同内部恢复、归档目录读取／抽取与执行框架仍由Rust实现，不构成语言的永久能力边界；B长期应能独立构建应用、系统软件、编译器、运行库与执行基础，具备自举能力。长期系统目标不变；当前阶段以BLEngine迁移和B编译器自举共同反查完整语言缺口，具体范围与次序见下节。语言能力交付、引擎实际迁移和编译器自举分别按真实结果记录。

### 当前阶段目标：完整语言支撑 BLEngine 纯 B 迁移与编译器自举

本节明确既有完整语言目标在当前阶段的优先实施范围，**不改变长期系统目标**。语言研发以BLEngine和B编译器两个真实消费者反查缺口，支持各自Rust职责实际由B接管，覆盖普通CPU组织、数据与资源管理、系统接口及CPU／GPU计算。现有Rust＋B分工是实现状态，不是把平台、资源生命周期或普通系统编程永久留给Rust的语言边界。

需求从BLEngine及B编译器最新已提交源码的真实职责向上推导：实际值宽度与布局、地址与别名、回调与原生ABI、动态数据结构和字符串、文件／系统接口、错误与资源交接、完整函数／模块／库、实际执行与部署。逐项区分已经可用、仅部分可用、确实未实现和仍待复现的范围，共用的语言／系统库缺口仍归Issues的C-020／C-021／C-022／C-024；编译器迁移、异构编译及运行库迁移分别归C-032／C-033／C-034。Rust中出现某种写法本身不证明B缺能力，应先确认现有B机制能否保持同一职责、语义和生命周期。

当前研发按每项先达到工程合格、整体能力组合完成、再统一深度优化推进。单机编译先将事实、IR、DAG和产物的生产／消费、调用寿命及依赖理顺，修正明显冗余和已证实问题，确认现有真实输入能够正确、稳定、完整结束；冷生成、缓存复用、原生验证和消费者采用分别记录，语义、精度、功能与资源关系保持。当前以主要逻辑合理、必要正确性和实际可用结果作为阶段收口依据；耗时继续实测，进一步预算随完整消费者确定，不以局部秒数或追求极限长期阻断后续能力，也不提前固定仍会随完整架构演进的内部组织。

继续按真实迁移阻塞补齐语言基础、标准库、原生平台边界和完整函数／模块／执行能力，并推进原生域编译、域运算及真实引擎消费者的组合。B具备可独立交付的稳定版本后，以稳定版为基础推进自举及CPU／GPU协作编译，完整收益以端到端结果确认。各能力先合格，再完成整体系统，随后统一深入优化；顶级效率、机器控制力、原生并行与稳定热更新仍是长期目标。具体能力及真实缺口沿原Issues分别记录，不把当前Rust实现当作永久语言边界。

语言、编译器和通用执行基础由 BLanguage 拥有；场景、资产、几何、渲染、窗口／输入等引擎职责仍由 BLEngine 拥有。实现语言迁移不改变唯一资源所有者和最后 CPU／GPU 消费者的完成责任，也不以把引擎 Rust 实现转入语言框架、外部包装或宿主逐元素回调的方式伪装成纯 B。操作系统及 Vulkan 等真实平台接口仍按原职责消费。

每项沿现有构建和实际产品命令记录：语言能力已实现，B 已实际编译并原生运行，引擎的对应职责已用 B 接管，旧 Rust 消费和重复实现已退出，功能／效果与性能结果，以及 P4／Git 交付。目标、文档和 B 源码比例都不代替这些事实；未闭合能力继续保留未完成状态。本阶段不新增常驻测试、断言、审核或证明流程。编译器自举等长期目标按原路线推进，不把本阶段迁移目标误写为全部长期能力已经交付。

### 确定的CPU运行目标：仅64位

BLanguage只考虑64位CPU运行，不支持32位CPU。CPU代码生成、原生执行框架和系统ABI只按64位目标建设，不设计或维护32位CPU后端、运行库或兼容路径。当前已有Windows x64；其他64位架构／操作系统仍需各自的实际实现，不能据此宣称已经支持。

这一范围不改变数值类型的位宽：u32、i32、f32和实际需要的8／16／32位数据仍可在64位CPU上使用；平台结构布局、文件格式与GPU数值语义按各自真实合同定义。原生address值为独立的8字节／对齐8的CPU本地地址身份，usize／isize分别复用u64／i64；所指位置访问、系统布局及回调继续按实际能力交付。不能把地址宽度等同于所有数据、dataset索引或GPU运算宽度。

### 确定的大小写敏感边界

B 的关键字与标识符区分大小写，与 C 一致。`value`、`Value` 和 `VALUE` 是三个不同名称，关键字使用语言规范的精确拼写。此项是语言规格及名称身份的确定边界，词法、名称解析、模块接口和生成的互操作接口共同遵守；内部编码与目标语言名称转换必须保留合法名称的区别。

除非用户明确要求变更语言规格，重构、优化、缺陷修复或跨平台适配不得改为忽略大小写，不增加大小写归一化别名或兼容路径。本项沿用现有语义，只明确事实源与修改权限，不新增运行时判断、测试或审核流程。具体规则见 [语言规范的词法与名称身份](BLanguage.md#词法与名称身份)。

### 长期设计原则

1. **完整通用。** 支持应用、系统软件、编译工具、数据库、网络服务及计算基础设施所需的值类型、顺序控制、动态数据结构、模块、泛型、错误处理、内存与资源管理、系统接口、独立编译、链接和部署。CPU 通用能力不能被 GPU 可表达子集永久限制；各执行目标按明确语义提供自身能力。
2. **顶级效率与机器控制力。** 同时追求高质量机器代码，以及顶级工程师对指令、布局、寻址、存储层级、向量化、同步和通信的理解与控制。保留从源码、IR、生成代码到实际执行的可追查关系，发展必要的硬件内建、底层接口和目标专门化。原生代码、自研后端、源码减少或内核减少本身不证明高效率；关键性能不能完全依赖编译器自动猜测。
3. **确定的非面向对象边界。** 不设计类、类的数据／实现／接口继承、虚函数、对象行为覆盖、类层级 RTTI 或基于对象类型的运行时动态派发体系；不换名称重新引入等价对象模型、通用类型擦除动态对象或反射驱动调用。数据、函数、模块和执行域是基本组织单位，数据的身份、布局和所有权显式定义，不附带可由派生类型替换的行为。这一取舍与静态关系优先具有相同目的：尽量让类型、调用、访问、副作用和生命周期问题在编译阶段暴露，减少必须依赖运行时绑定和调用者约定的关系；不能仅因没有class或虚函数拼写，就认定另一种动态绑定符合该目的。
4. **完整封装与大规模复用。** 通用软件的封装、共有数据与行为复用、局部修改和扩展需求仍须完整解决。普通B通过数据组合、函数组合、编译期泛型与特化、明确的模块接口和访问控制建设这些能力；函数显式表达所操作的数据及访问关系。高阶组合优先静态确定函数目标和捕获关系，不以通用动态闭包或对象派发作为补齐复用的必经机制。不能以取消面向对象为理由，要求大量重复定义或逐项手写转发，也不能把方案名称当作已解决复用需求的事实。
5. **原生单机与计算域内多机并行。** 覆盖 CPU 多核、SIMD、GPU、单机多设备及同一计算域内的多台计算机。一次执行使用域内选定资源；跨域级联由上层应用组织，不把整个超算系统的全局计算与治理纳入执行框架。数据域、访问权限、协作、分片、通信、依赖与完成关系进入语言和编译表示；编译器生成计算及必要通信，原生执行框架负责真实连接、传输、设备提交、完成观察和失败报告。单机与跨机执行遵循一致的所有权、访问、可见性、顺序及完成规则；真实目标能力、通信与失败须明确表达，远端数据不被假定为本地同一物理存储。
6. **编译器可控并行与调度。** 静态关系是普通B的默认：尽量在编译期确定类型、具体实现、访问范围、副作用、生命周期、执行目标和依赖条件，采用编译期多态及目标专门化，使接口能够独立检查。必要动态性集中在实际输入和资源调度、明确的外部ABI、模块装载及执行版本切换边界；不为一般复用额外引入运行时类型对象或可任意改派的实现。运行时根据实际输入、设备与节点选择合法的执行映射和调度，不要求提前固定全部数值、节点数或执行次序。插件在明确模块边界为新执行绑定代码及合同，普通调用不逐次查询全局当前实现。外部实现和原生资源中不能静态证明的事实由其真实受信任边界承担，不以签名或非零检查冒充代码及资源寿命已经证明，也不把当前证明器能力作为通用程序的永久表达上限。
7. **稳定热更新。** 模块版本、执行版本、状态迁移和资源交接从设计之初共同考虑。更新发生在明确边界，每次执行绑定确定的代码及接口契约，派生任务、异步回调和 CPU／GPU／远端消费者遵守本次版本关系。新版本接收新工作，旧版本完成已有工作；同一可变状态在真实所有者处交接，迁移期间写权限和提交点明确，不形成两份可独立改写的权威状态。资源和旧代码保持到最后一个真实消费者完成。系统持续服务与受影响任务／分区的必要协调分别定义，不承诺任意代码或状态都可瞬时替换。
8. **访问、效果与所有权一致。** 普通函数、模块接口、并行阶段和异步消费采用能组合的访问与效果契约。明确权威数据来源、共享借用、独占修改、必要副本及版本交接；两个不同的数据入口不自动证明其引用范围互不重叠。CPU 返回、GPU 阶段结束、通信完成和远端计算完成分别观察，不能用无关计数或作用域结束代替。
9. **布局与数值语义明确。** 区分逻辑数据、物理布局、执行映射和资源所有权。数据重排、传输、精度变化、转换、运算重排、融合和近似计算具有明确许可与成本；逐步覆盖实际需要的整数宽度、低精度、单／双精度、混合精度及量化。跨后端结果、误差、可重复性与性能分别说明，归约顺序和数值约定明确，不承诺任意并行浮点计算逐位一致。
10. **开放组合、互操作与可移植性。** 通过可组合机制支持新类型与算法，发展编译期约束、库与模块接口、ABI、资源交接、独立产物和上层语言调用。当前操作系统、CPU 架构、设备／队列数量、索引宽度和证明器推导能力，不能未经论证成为永久语言边界。安全前提必须成立；仅缺少某项优化依据时，不把未做该项优化等同于算法不可表达。
11. **面向AI的可编程观察与优化实验。** 工具直接服务AI，架构师通过AI掌握实际源码、数据、代码与执行。支持基础查询和原生控制，并使AI能编写观察／分析程序、表达明确机器方案、用真实输入组合实验；原所有者交接完整可追查事实，原检查器约束类型、访问、效果和生命周期，AI负责分析与选择。优化策略、调试信息与运行采集独立，正式执行保持精简。具体能力逐项有唯一架构职责和台账，设计不增加自动瓶颈判断、评分、常驻全量采集、第二状态权威或调度器，不以当前工具或证明器限制合法程序和优化上限。
12. **依据真实消费者和实现事实发展。** 保持语言与消费者职责独立，自研前端、IR、优化、后端与执行基础，依托必要平台和标准接口。真实需求推动能力扩展，保留真实失败，区分能力缺口与已证实缺陷；源码实现、编译成功、原生执行、产品使用与性能达标分别记录，不以目标文档代替交付。
13. **计算域内原生编译与独立运行。** 将本机并行、增量和域内分布式编译作为工具链正式能力，按真实模块依赖、泛型、目标代码与产物复用组织构建。编译域和运行域可以不同，产物按目标平台、ABI 与指令要求部署，不依赖原编译域在线。Blink 只负责各次构建或执行所选计算域内的工作，跨域级联由上层应用组织，不以千万节点统一编译或计算为目标。配套独立运维底座面向大规模机器管理，提供远程控制、必要特权和自身更新；管理规模与一次并行计算范围分别兑现，具体能力按实现与原生证据记录。

### 面向AI的基础工具与全流程观察

本节是B作为AI超算时代基石语言的工具设计总原则与能力契约，包含已确认的长期方向，不声明下列能力均已实现。工具以AI为唯一直接使用者，架构师通过AI分析和操作；B的完整通用／系统编程、非面向对象、静态关系优先、原生并行及机器控制目标保持。AI可以编写本次需要的观察与分析程序，表达不同机器实现方案，并沿真实编译与执行取得事实、比较结果和成本；工具提供基础原语与关系，不内置AI决策，不代替AI判断瓶颈、选择优化或裁决性能。

#### 工具设计总原则

1. **原始能力完整，交互按问题组合。** 支持定位、查询、执行控制与基础量化，可从模块、具体实例、阶段、数据和资源深入到实际指令与字节，并能反查来源。每次请求选择实际对象、范围、字段和事件，允许一次取得有关事实及继续展开原始载荷。结构化参数／结果、可调用说明与真实目标支持由各入口提供，不能只把传统文本命令包装成JSON就认定AI使用高效；也不为了统一接口新建服务、登记中心或全局协议。
2. **唯一权威与静态绑定。** 源码／类型／合同、IR／变换、Object／链接、Executable／管线、Frame／存储及原Execution各自生产真实事实，查询只引用或组合。普通B仍以数据、函数、模块和执行域组织；观察绑定确定的代码、输入与来源，不引入对象反射、通用动态对象、逐次全局实现查询、第二资源拥有表或另一执行／依赖图。布局、别名、顺序、位置及最后真实消费者的合同共同适用，当前证明器范围不成为通用表达边界。
3. **观察与分析可以由AI编程。** 以普通B函数、类型、编译期泛型／特化、模块和原生后端组织小型观察程序，原前端检查实际类型、访问、效果与生命周期。被观察输入保持只读，结果由观察消费者独立拥有，不能借查询执行业务副作用、改写／释放目标或偷偷求值用户函数。CPU、GPU、设备及域内节点在数据所在处沿原执行入口处理请求，只交接所需统计、样本或字节；常见分析由AI组合，不要求产品预置固定检查器。具体语法、数据形式和命令随真实能力设计，本节不预设新关键字、DSL、解释器或第三方编译运行基础。
4. **真实现场、事实层次与范围明确。** 源码、生成表示、实际字节、装载地址与执行版本相互追查，多对多映射、内联、合并和消除如实表达。静态事实、估算、实测、未采集、被消除、不支持与读取失败分别交接；结果注明单位、来源、时点、实际覆盖及完整性，不静默截断。暂停线程、CPU接收、设备提交、实际完成及结果可用不同，不把不同设备／节点时钟或多次读取拼成同一快照。GPU读回是明确完成后的CPU结果；SPIR-V、驱动最终ISA、模拟、插桩版本与原硬件现场各自说明，不能猜造缺失状态或自动重跑正式工作来补齐证据。
5. **实现自由通过明确方案与许可表达。** AI及工程师可控制布局／寻址、分块、向量宽度、融合、驻留、复用、重计算、设备映射和通信，常见选择可结构化交接，复杂算法仍能直接写B代码。原类型、访问、ABI、别名、顺序、数值精度／重排／近似及资源合同约束所选方案，工具不把选择压缩成永久固定参数表。编译器按请求报告实际变换和消费的条件，明确非法、无法确认与尚未实现分开；编译通过不证明任意算法等价、数学性质、终止或业务正确。数值许可沿原规范与C-024／C-004演进，不由工具写死epsilon或自动降低精度。
6. **优化、调试信息与运行采集独立。** Debug／Release等优化策略是B产物的明确编译选择，与符号生成／保存／剥离、运行控制／插桩／计量各自独立；Cargo构建工具的档位不等于这些B接口已经交付。完整优化的Release应能带匹配调试信息，符号开关不隐式禁用内联、删除、向量化或改变链接优化，也不强制变量保活。优先使符号和观察材料分离，正式包可直接交付已验证的同一执行代码；构建缓存中的来源／复用记录不因此成为部署执行前置，部署映像按原资源ABI交接必要代码、计划和合同。剥离只处理调试内容，保留必需ABI、导入导出、重定位、栈展开与资源完成信息。采集按明确请求启用，正常运行不默认插入观察工作或要求计量能力。新增指令、带宽、存储、等待与传输及实测范围如实交接，不能笼统承诺零开销；去符号主要改变体积和信息暴露，不自动证明运行更快。GPU移除非语义调试描述不自动证明驱动最终ISA或性能相同，结论落到实际发布SPIR-V及真实管线。
7. **真实输入实验沿原编译与执行组合。** AI提出假设、编写观察程序或明确实现方案，再调用原Compiler／构建图、产物装入、CPU／GPU执行和分析函数取得结果及成本，最后由AI或用户选择。各方案持有实际代码、输入、配置、硬件、数值许可和测量范围，编译／装载、传输、设备阶段与端到端成本分开，结果差异只覆盖实际输入。可独立取得输入的纯计算片段可保存必要输入并再次执行；可变状态、随机源、浮点、并发和外部I/O边界明确，不宣称任意应用或全域确定重现。不增常驻实验调度器、评分裁决、隐藏在线调优、自动切换在途代码或普遍全量记录；实验输入和结果各有真实消费者与结束条件，正常版本寿命沿原C-023。
8. **架构合同约束交付，内部实现持续演进。** 每个台账叶项对应本节的明确职责、输入／输出、唯一所有者、生命周期及语义边界，认领时再核对最新生产函数和区间；原则不通过冻结内部算法、文件格式、阈值或新增审核／证明／常驻测试来落实。调试／观察主体按真实职责纳入B接管与自举消费者，系统接口声明和有职责的B库封装正常保留，必要独立原生支持可使用Rust；源码比例和B外壳不替代实际接管，保留的Rust实现必须明确。实现变更直接同步本节对应合同和现行规范／入口，不能靠命令包装、宿主转发、旁路状态、静默替代或缩小目标冒充交付。通过真实消费者记录调用次数、读取量、关系拼接、正确性与扰动，结论仅覆盖实际任务；工具不因此成为语言研发前置。硬件语义标记、采样关联及新设备能力先调查支持与代价，编译器能做的映射、驱动／硬件真实支持和未来研究分别记录，不用模拟填补未知。

接口允许原API、CLI或工具调用直接组合，不要求人类GUI，也不要求一个集中工具进程。请求限定本次对象和实际有效期；返回可以是类型化记录、二进制载荷及按需文本，AI可用普通分析程序处理大量数据，不要求模型逐条阅读完整日志。调试描述作为原编译输出的可选交付，平台符号是其中一种投影，不成为另一类型／代码权威。观察不会赋予新的数据权限；暂停、完成及只读关系不足时应说明实际限制，不能隐式冻结全程序或全计算域。

#### 当前基础与设计范围

当前bc inputs及Rust build::input_facts直接查询实际COFF／BLBI保存的构建输入，bc layout／Ty布局JSON和接口布局查询交接实际类型与字段，bc ir及原编译结果的ir_json按需交接实际程序、普通函数和阶段IR，bc x64及native::instructions_json可解码明确指令字节范围，bc spirv及spirv::module_json可只读查询原单模块SPIR-V全部指令结构，生成期NativeCode／StageCode／ProgramImage的code_json沿原发射事实区分主／辅助代码、对齐和字面量；bc build已有.x64／.reloc／.spv及其配对.spv.json／.layout导出，bc／blink已有静态CPU栈报告，运行库已有部分分配查询、GPU阶段计时与真实完成入口。这些基础不等于完整来源映射、平台符号、运行控制、可编译观察、明确方案及实验接口已实现。GPU时间戳默认关闭；GpuProgram／GpuTemplate通过with_timestamps显式请求，普通执行不要求队列支持时间戳。计时只复用原查询池及完成生命周期，未采集或无阶段返回None，实际零值保留在Some中。

下列逐项职责同时覆盖已交付基础和当前设计目标，实际支持按规范及原生事实区分；未完成范围唯一在Issues，闭合范围及历史只在FixedIssues。基础原生调试、可编程观察、机器方案和真实实验可以按依赖分别推进。CPU／GPU栈耗尽仍归C-021.7.3／.4，静态栈需求归C-024.1.1，数值与精度归C-004／C-024.2，域／节点程序及API归C-021.9／C-022，热更新归C-023；不复制职责。暂未实现的命令、候选语法、硬件和程序不得写成现有能力。

#### 基础编译事实的架构职责

<a id="tool-3"></a>

##### 类型与字段布局的结构查询

原源码类型请求通过Compiler::type_layout调用Parser／World得到原Ty；Ty::layout_json和独立ir::interface_layout_json按需交接大小、对齐、偏移、步长、标量／资源字覆盖，以及字段、数组、变体和引用元素布局。bc layout选择具体类型或静态字段，bc build导出.layout.json；已有执行接口可以脱离源码直接查询，具体字段和使用规则见[规范](BLanguage.md#类型与字段布局的结构查询)。值描述与所引用存储、静态布局与活动现场分开，不重做布局计算，不增加ProgramInterface虚表入口或资源ABI。查询只借用原编译结果／实际产物并返回所选值，不保留无人消费的IR或另一拥有状态；变更继续受工具总原则约束。闭合记录见[FixedIssues](FixedIssues.md#c-021-7-9-3)。

具体源码类型请求沿原Parser／World实例化确定Ty，已生成程序或执行映像的查询则消费其原Ty／ProgramInterface，二者明确各自来源。结构化导出复用原大小、对齐、字段／数组／变体寻址和标量分量，描述值的布局与view／dataset引用的元素存储分别交接；资源四字节存储覆盖不代表硬件寄存器。字段选择只解释静态布局，活动变体和值仍需实际运行数据。

<a id="tool-4"></a>

##### 实际IR的按需结构导出

原Compiler::compile_entry、compile_application_with_modules和compile_native_module分别生产本次优化后的Program、完成函数／资源整理的Application与Module；查询由这些原消费者持有的值直接输出，不再次检查／优化／发射，不复制另一编译图。Program／Stage、ValueCode／FunctionBody的ir_json按需序列化实际指令和类型；Application／Module的ir_json交接原入口体、保留函数、明确导入／导出及资源程序，function_ir_json只选择确实保留的完整函数名。原ProgramInterface与对象／资源ABI不增加查询状态或虚表入口。

bc ir读取明确源文件与模块根，默认按普通模块编译，可选具体--program或--entry；模块沿原--import和--instance输入，普通应用使用原已编译模块API，阶段选择仅作用于实际优化后Program。一次请求调用一个原编译入口，随后从同一返回结果选择函数／阶段；产物已不含IR时不重新解释对象或假造历史IR。本次源编译路径、模式、入口、显式导入和实例随JSON返回，原产物构建身份继续由bc inputs／原SDK持有，路径本身不冒充完整历史输入证明。

IR结果保留原寄存器Scalar表、局部Ty及结束分量、嵌套控制流、调用实参／位置／别名／内存效果、原子序、集合值函数和tile关系。所有Inst变体按字段交接，常量Bits使用十六进制字符串保存完整64位及浮点原位，不经宿主浮点转换；寄存器／binding／阶段编号是对应IR容器中的逻辑引用，不冒充物理寄存器、运行地址或实际进度。CLI说明实际优化／整理阶段；公开值类型可由调用者构造，直接ir_json不为调用者宣称其生成阶段。当前只查询返回时保留的最终IR，不重建被消除变量或优化前快照。

##### CPU实际分配字节与存活范围查询

AI检查内存占用时，数据字存储直接由`Dataset::memory()`交付当前`count*stride`的逻辑记录跨度、`words.len()*4`的存储长度与`words.capacity()*4`的可用容量。声明布局／记录填充、最后u32尾填充和保留容量分别表达；容量不等同OS页承诺、工作集、分配器开销或全对象图。`ReadDataset`／`CpuDataset`沿原Deref查询同一实际Dataset，不复制存储或维护累计计数。

`Frame::cpu_data_memory()`同步读取原当前CPU数据槽，按本次借用内的实际Dataset对象分组，返回原Frame句柄和同一字节快照；本次临时分组不是新的资源身份或常驻拥有表。GPU槽不参与该CPU数据范围，查询不等待、不下载，也不推断在途传输或其他CPU分配已释放。零载荷可以仍保留容量；释放后的槽不再出现在新查询中，旧结果只是当时的元数据，不保持存储、设备或完成点。

`DomainBindings<D>::datasets()`共享借用原`Vec<D>`，沿原Frame::data或带域结果查询实际槽位容器的len、capacity与当前槽存储，不另生成容量报告或分配表。len包含已初始化None空槽；对于非零尺寸D，len与capacity分别乘本次Rust布局size_of::<D>()，得到已初始化槽跨度与原Vec可用槽容量字节。它们不含D内部的数据字、代码、类型嵌套分配或设备对象，不能与子载荷重复计数；容量尾部尚未初始化，不能据capacity读取。零尺寸D按Rust Vec实际容量语义交接，槽字节仍为零；空Vec的指针不证明存在分配。共享借用不能写入、移动或跨拥有者改写；返回的原容器不是新的资源身份，调用者自行克隆会遵循Rust及D的实际克隆语义，不属于本查询。

#### 实施与演进边界

先复用实际输入、布局、代码与原完成基础，逐项贯通来源和原生控制；再形成受原访问／效果约束的CPU观察、GPU就地分析、选定事件及明确方案实验。布局、分块、SIMD、融合、驻留、复用和重计算由C-024的相应语言／后端所有者实现，工具只消费其实际选择；数值许可、跨设备／域及热更新继续沿原编号。硬件协同调查和深层轨迹不阻断已能交付的基础能力，全部工具不成为BLEngine迁移或自举前置。各叶独立认领、实现、原生验证和交接，完成状态只在双台账；不以父项笼统占用文件，不增额外校验、评分、审核或证明链。

### 数据、执行与模块演化的共同边界

非面向对象是确定方向；函数与模块契约、数据表示、原生执行和热更新之间的具体规则仍须完成设计与实现。以下约束不构成现有能力声明，也不重新开放类继承或对象派发的取舍。

| 场景 | 设计边界 |
|---|---|
| 同一数据类型和函数用于顺序、并行或不同设备 | 由访问、生命周期、数据表示及目标能力确定适用条件 |
| 多个调用通过不同入口引用共享状态 | 必须检查真实访问范围和依赖，不能仅凭不同参数名或数据身份推定独立 |
| 插件在运行期间加入或更新 | 在明确模块装载边界为新执行绑定目标能力、访问契约和版本；已有执行及派生消费者保持既定关系，普通调用不逐次选择全局当前实现 |
| 原生地址、字段地址或外部 ABI 跨更新边界保留 | 明确其有效期、布局保证与交接方式，不能同时任意重排或迁移存储 |
| 数据跨 CPU、GPU 或机器使用 | 明确代码目标、数据表示、分片、传输、资源归属及完成，不传递本地调用地址冒充远端能力 |
| 运行期间的动态能力 | 将变化集中到声明的绑定、调度和更新边界，必要成本能够观察与控制 |

共同规则必须具体处理以下交汇点：

- **函数、泛型与模块契约。** 接口表达必要的读取、写入、副作用、生命周期、顺序和目标条件，具体实现由编译器检查。静态特化不自动证明数据无别名；取消虚函数也不消除共享状态。接口访问范围或目标保证改变时，相关依赖者重新检查、编译或绑定，不能沿用已失效的并行结论。
- **数据表示与引用。** 数据身份、原生地址、字段地址、外部 ABI、数据域布局及视图的保证分别定义。允许编译器在语义许可下选择布局；模块内部的直接寻址与跨更新边界的引用各有明确保证，不为所有数据访问强制增加运行期的间接访问，不增加可独立改写的权威状态镜像。
- **执行版本与真实完成。** 一次执行及其派生消费者持有所需的代码、数据与资源，不能因入口返回或模块入口切换就卸载旧代码。已内联或静态特化的实现更新，需要重新生成并切换包含该实现的执行版本，不能仅替换一个函数地址就宣称更新完成。
- **状态迁移与失败。** 定义可更新的代码与状态范围、兼容条件、迁移逻辑、可变状态的独占交接点，以及失败后的真实状态和处理责任。状态含义的业务转换由其实际定义者提供，编译器不能凭字段名称推断。稳定接口和状态迁移目标不等于冻结全部内部布局。
- **跨机协作与版本推进。** 装载可按节点逐步推进，任务使用其绑定的代码、通信接口和状态版本。需要共同切换的分片在真实依赖边界协调，节点及通信失败显式进入执行语义；不以全局当前版本、节点数量或宿主作用域冒充实际完成。

运行期复杂度应通过提前确定关系、限制动态变化范围和清晰所有权减少。动态输入、动态容器、显式变体、普通任务和合法资源调度不因其数据或规模运行时变化而被禁止；必要C函数地址及系统回调按真实ABI和最后消费者处理，不增加“是否用于FFI”的业务用途白名单。不得用隐藏锁、复制、隐式等待、额外权威状态或假完成掩盖尚未解决的关系。设计与真实消费者研发共同推进，不据此新增常驻测试、资产、断言、审核关卡或独立证明流程。

### 长期框架

| 部分 | 主要职责 | 必须共同定义的边界 |
|---|---|---|
| 数据 | 类型、状态、结构、布局、身份、所有权、借用及生命周期 | 逻辑数据、物理地址与资源所有权的关系 |
| 函数 | 操作、顺序控制、数据与函数组合、编译期泛型及特化 | 输入、输出、访问、副作用、目标与错误契约 |
| 模块 | 封装、公开接口、独立／增量／分布式编译、链接、装载、版本与状态迁移 | 接口兼容、执行版本绑定、更新交接及卸载 |
| 执行域 | 并行工作、协作、依赖、分区、异步、多设备及多机 | 合法调度、通信、可见性、失败和真实完成 |

编译器与原生执行基础共同落实上述四部分：前端、IR、优化与后端检查契约并生成可追查的机器代码，执行框架拥有真实存储、传输、提交及完成后的释放。优先明确通用基础、访问契约、数据表示、资源生命周期和版本交接，再按真实需求完善单机、异步、多设备、多机及热更新实现；互操作、工具和文档与实现一起成长。普通管理程序可以使用顺序函数、模块及动态数据结构，不要求改写为批量计算。


### 统一函数、结果与执行位置

普通值计算和整域计算统一使用返回类型函数定义。`parallel` 显式表达并行域；`on cpu`、`on gpu`、`on compute` 声明目标能力；`target(cpu, call(...))`、`target(gpu, call(...))` 选择本次执行位置。源语言不使用独立 program 类别或手写 launch 许可；内部 Program、Stage、ExecutionPlan 和 CLI 的 --program 仍有各自职责。 参与要求沿实际执行及调用推导；设备整域的局部编译期普通值由原阶段常量环境交接，声明本身不构成宿主控制。原类型、词法作用域与真实输出初始化仍由各自所有者检查，CPU运行期局部与宿主操作保持原语义，不引入新的求值器或运行阶段。

CPU 主流程可以直接 parallel，也可以同步调用独立模块的整域 CPU／GPU 入口。参与要求、初始化效果和输入／输出资源关系随已编译合同交接。GPU target 当前接收借用 dataset 和普通统一参数组成的整域 void 调用，等待本次真实提交完成，结果保留在 GPU；download 执行显式传回。普通值跨 GPU 返回、GPU／CPU 元素阶段的普通原生调用、选择性内联和异步应用语法仍待实现。

enum／result 是数据表达。无载荷编号枚举直接使用声明整数标量的实际布局并保留名义身份，不另设标签；带载荷变体使用原32位判别字和重叠载荷。match 选择实际活动载荷，提取值按声明类型与分量消费当前路径的已有数值事实；try 只传播显式业务 Err；业务结果、运行库失败和进程退出码分别处理。普通应用入口仍为无参数 u32／i32 main；result 入口适配、平台失败映射和完整错误资源阶段继续开放。精确规则见[语言规范](BLanguage.md)。

### 计算域内的原生编译与运行（设计边界）

计算域内多机编译和运行是长期目标，具体程序、协议、接口及部署尚未实现。编译域和运行域可以不同，一次构建／执行只使用所选域内资源；跨域级联、业务流程、汇总和故障策略归上层应用。

设计采用四类独立程序：BLAdmin 持有本机特权，BLSupervisor 持有普通用户维护及受管进程生命周期，规划的 blink-domain 持有域成员、分片和构建／执行图实例，规划的 blink-node 持有本机计算资源和工作。计算职责不进入维护程序，也不以插件混入；Node 不等同于 Matrix BLNode。blcompute 是执行进程内的运行库，brun 是按需工具，均不构成第五个常驻计算服务。

正常计算路径为客户端→Domain→Node→原生工作，数据直达真实消费者；运维通过 Supervisor／Admin 独立完成。底座自身更新需要 OS 稳定启动／恢复根和可替换工作版本，计算授权不授予维护权，底座恢复不重放计算工作。B、C/C++、Rust 的正式 API／CLI、完成／取消／未知状态、数据引用及生命周期须共同设计。完整方案和明确标为候选的语法见 [ComputeDomain.md](ComputeDomain.md)。独立本机编译和应用不依赖域程序在线。

## 源码装入、检查与原生生成

词法生产由`src/bootstrap/lexer.h／.b`拥有，泛型尖括号前瞻由`src/bootstrap/parser.h／.b`拥有。前瞻直接借用同一Source字节与原Vec的TokenSpan，B完成嵌套尖括号、>>及括号内表达式扫描，Rust仅交接原游标与Option结果；其余Parser仍构造唯一AST。COFF静态归档的布局、两个链接成员、长名称、符号排序及原对象字节输出由`src/bootstrap/archive.h／.b`拥有。Rust仅将现有名字／对象／符号交为同步C ABI借用视图，B布局阶段写入同一视图的实际成员／名称位置，编码阶段直接填原Rust Vec的唯一输出存储；原Rust格式计算和字节生成退出。符号按名称及原成员顺序排序，同名仍选择原首成员；对象载荷不复制为另一输入或重新编译，B不保留地址。读取、目录容器及成员抽取继续由原static_library.rs处理，未写成已由B接管。

对象符号选择与重定位绑定由src/bootstrap/bindings.h／.b负责：原Object继续拥有节、名字、定义与原始引用，Rust仅交接借用字段并提供按实际条目上界分配的存储。B在同一节点区内维护名字与DLL／名字两棵有序树，保留原定义顺序、重复定义的最后绑定、首次未解析名字及导入的UTF-8字节确定顺序；辅助行计入真实COFF索引，COMDAT关联与全部重定位由同一目录绑定。准备阶段只生成一次符号目录并计算派生名字长度；原COFF布局确认实际格式宽度后，B消费同一目录物化派生名字，不重新选择或复制原始名字。

标准COFF对象的包络写出由src/bootstrap/coff.h／.b负责：B借用已选择符号、原节载荷与已绑定重定位，计算文件布局并直接填充原Rust Vec的唯一输出，写出AMD64头、节头、COMDAT辅助行、重定位溢出、符号及字符串表。原Rust符号选择／绑定及对应字节生产退出。各输入、调用方存储与输出保持到同步消费结束，B不保留地址，不跨Rust私有容器；不引入Frame、运行库、分配回调或另一份符号权威。最终语言对象拥有容器、合同内部恢复及其余对象语义／合同／栈记录生产继续由原Rust所有者负责。

对象元数据外层与栈字段由src/bootstrap/metadata.h／.b布局并直接填充同一个Rust Vec，包含对象身份／种类、接口参与要求、库／导出、既有资源描述、函数合同及真实Frame／Call。对象语义、合同冲突和栈调用事实仍由原所有者生成，资源描述内部继续使用共同codec；Rust只交接本轮同步借用视图，不克隆合同载荷，不预格式化栈字节或保留第二份元数据。B保留直接／尾调用、间接调用及未报告原因，原Rust对应word／string写出退出；当前对象格式身份由coff.rs的FORMAT唯一给出并传给B，读取沿同一身份检查，不绑定软件VERSION。

对象元数据外层读取由src/bootstrap/metadata_read.h／.b负责。原Cursor位置移入同一借用输入上的B游标，B直接读出BLCO头、三类对象前缀、参与要求、长度前缀字节、合同记录、Frame及四类Call；Rust只消费已解码值，构造原Kind、字符串、Vec及BTreeMap。资源blob在原位置交给共同codec，合同blob逐项交给原规范化消费者，再读取后续记录；库／导出及帧列表继续按原拥有容器组装。字符串与二进制字段复用同一长度前缀读取，不生成中间目录、额外阶段状态机或事件协议；B不分配对象、保留输入地址或创建Frame。FORMAT由原coff.rs唯一传入，物理读取职责不绑定软件VERSION；COFF逻辑映射与Target解释由B对象读取入口交接，最终拥有容器、其余对象语义、合同内部编码与栈验证仍由原所有者负责。

标准COFF结构读取由src/bootstrap/coff_read.h／.b负责：Reader持有原文件快照，B解释AMD64头、节范围、短／长名字、符号及辅助记录、重定位溢出与物理字段，并交回同一输入的同步借用视图。Rust只转换实际字符串及容器，名字的UTF-8和最终拥有表示仍由其真实消费者处理；原始节载荷在恢复最终Section／Archive前沿快照借用，不另建拥有载荷副本。构建入口先仅读取.blbuild，未决定复用前不完整解析代码及Blink元数据。必要物理范围与COFF格式检查由同一读取入口承担；B不保留地址、分配另一目录或取得Frame。共享资源／合同内部编码与最终Object拥有容器保留原Rust职责；逻辑加载关系由B对象读取入口交接，结构读取不代表完整对象恢复或自举。

COFF逻辑加载关系由src/bootstrap/object_read.h／.b负责。B在原始节读取时同时生产加载索引：.blmeta、.blrt及.blbuild不装入，其他节在同一本次借用记录中保存其一基索引；Rust的独立mapping表退出，导出和栈也直接消费该记录。B沿同一记录判定COMDAT选择、关联所有者及真实标志，并解释重定位的Section／DLL Import／模块Symbol；DLL字节长度、数字及UTF-8边界属于这一原目标格式解析。Rust继续持有原文件快照和原raw记录分配，按物理顺序处理名字UTF-8、构造实际Section／Archive／Target及associated，合同表与栈验证仍由原拥有者消费。B只借用明确C布局的定宽记录，不取得Rust String／Vec、保留地址或建立第二对象／目录。物理读取、逻辑解释、共同codec与最终拥有对象各自交接必要产出；旧Rust逻辑映射、COMDAT选择及DLL目标解析不再并存。

完整compiler角色构建时，原`build.rs`使用已安装稳定发行的`bc`逐模块编译无Frame的B引导对象，再由同一次`blink`归档并静态链接到Rust编译器；输入VERSION使用句柄保持到全部B模块编译及统一归档子进程结束，研发target工具不作为唯一种子，不增加blcompute或Cargo反向依赖。编译器身份包含B源码和实际生成的原生对象，软件显示版本仍不参与语义身份。仅运行角色没有源码编译器身份的消费者，不生成该身份或调用前端种子；共同IR、原生／SPIR-V后端及映像编码仍由原语言crate持有，唯一字节编码位于codec.rs。

Rust词法入口只持有原Source及Vec，按同步C ABI借出原UTF-8字节和输出存储，消费B返回的Span与B001至B004诊断；B不分配或保留地址。n字节最多形成n个非空token及EOF，输出容量沿该数学上界提供。Token只保存原源码字节范围；Parser读取同一Source切片，在AST需要独立名称或数字文字时取得拥有文本。普通引号token由Parser解码为UTF-8字节，直接构造既有array<u8,N>及明确u8类型的Construct／Number节点，N为实际字节数，允许零长且不隐式追加NUL；不经过用户同名函数，不增加AST／IR类别、运行期String或资源所有者。链接元数据继续由原link_string执行自己的严格ASCII合同。类型中的`>>`仅推进原Span，表达式右移保持原义。Rust逐字符扫描和每token文本副本均不保留。

稳定种子可构建该B模块，包含该模块的新工具可再编译同一模块；这不是完整编译器的两代自举。解析、类型检查、IR／后端、运行库迁移与GPU实际参与编译仍按原缺口推进。

`.h` 是接口来源，实际存在的 `.b` 持有实现及私有声明。纯类型、常量、外部声明模块不需要空 `.b`。普通函数必须有真实匹配实现，实际读取错误直接报告。模块来源表闭合合法导入环；按值布局递归、常量求值环与缺失实现分别由原所有者处理。

记录、枚举、typeset 及函数名称遵守直接 import 和接口可见性；限定名不绕过访问范围。泛型调用在调用者作用域绑定实际名义类型，后续实例化传递该完整身份，不在被调模块重新解析调用者私有类型的名字。有限实例按允许组合检查；开放类型／const 在实际实例化时检查正文，不宣称已经符号证明全部可能实例。

前端在真实访问点检查类型、位置、初始化、资源和参与关系，形成 Program／Stage／函数 IR。阶段融合只合并同域、同前缀／选择且不存在真实跨元素冲突的阶段；协作、外部效果及显式 phase 保留必要边界。优化、布局与代码生成消费同一已检查关系，不在运行时再构造另一份语义权威。

ProgramImage 在编译侧一次拥有最终 CPU 机器码、重定位、SPIR-V 和 ExecutionPlan。集合的主遍历、递归摘要、传播、排序及间接启动代码均在此生成。ExecutionPlan 只保存执行需要的接口、布局、访问、前缀及设备要求；编译结束不保留无消费者的 IR 函数体。

CPU的NativeCode同时交接真实主函数末端与Windows x64展开字节；普通应用、范围及集合辅助入口共用原序言发射与展开编码，PE／COFF和内存装入分别消费同一输出。内存代码、对齐的展开字节及函数表属于原Executable的同一VM。完成复制、重定位、RX权限与指令缓存刷新后登记Windows函数表，成功后才交付可调用入口；最后一个实际代码消费者后，原Drop先撤销函数表，再释放VM及DLL引用。尾部无帧探栈叶辅助和常量排除在主函数范围外，大帧逐页触及复用同映像叶辅助。该平台展开能力与静态栈预算、源码调试、B异常处理语义及耗尽定位分别承担原职责。

### 条件图、事实与编译期寿命

Proof／Domains 持有真实值快照、类型化范围、来源及访问关系；Clause 以共享 DAG 表达实际路径。各引用由原Clause持有，最后引用的节点及其Condition两分支沿同一引用计数迭代释放；仍被共享的节点保留到最后检查消费者结束。图的释放使用局部迭代工作栈，保持原条件、事实、节点身份与编码，不另持一份图。分支只合流真实继续边，循环区分入口、继续、break、自然结束和返回。原Below与同一实际值的类型化数值界、Zero及无符号NonZero共同判定路径矛盾；零按原Scalar有序编码参与，不新增关系图或推导轮次。整数除余在值自身非零事实不足时，按每个实际分量的字节范围复用原Value::nonzero_bytes与当前完整Clause，要求原路径仍可执行；不以矛盾环境、未选侧常量零值或另一分量的非零取得许可。整数域合流沿同一真实快照保留双方共有的Upper：一侧精确等于界、另一侧严格小于界时保留非严格上界，两侧已有距离取共同可保证的距离；一侧最大值不大于另一侧最小值时，较小侧也保证后者已有的上界。普通值和已知选支复用同一Proof合流，数值身份与原存储版本分开。数值循环沿同一写效果分析交接常量位移与独立赋值，确定位置的u32分量只保留入口和实际继续边共同保证的界，不恢复旧相等身份；while与有界for共用原数值保留入口，seek按真实Continue交接，break保留实际出口。数值事实与资源存储版本分别维护：值快照可以继续有效，旧版本的索引许可不能用于新存储。

变体物理载荷仍由共用的4字节分量表示。完整宽整数／地址／函数地址已知非零时，原判别字条件持有覆盖分量至少一个非零的析取关系；普通整数标签按零／非零分区并保留准确类型化数值范围，不把多个非零编号当作相等的bool。match／try比较消费判别字原条件，载荷重组在原路径中排除覆盖分量全部为零，取得原Proof非零事实。关系只引用本次真实值快照，沿既有返回／模块条件编码交接，不改布局、ABI或运行期执行。

函数返回与write／inout输出在各自实际出口内映射路径、值及初始化关系，然后沿原模型合流。函数级接口身份只命名真实输入和最终合流输出；某一出口的私有快照别名不进入其他出口，不另存一份全函数别名汇总。

路径查询、模块投影、输入／输出代入及借用重叠消费原共享图。未改变实际身份的投影保留原节点；单条借用来源直接持有其条件，完整相同的借用合流复用原关系。只有真实选择不同才生产选择关系，不先展开全部路径组合，再在下游消除冗余。循环出口对普通地址／view和资源槽消费同一完整来源定义：先删去直接自身边，识别与入口完全相同的输入，再沿原resolve将已知不变输入代入其他定义；完整Borrow与入口相同的槽按原成立条件交回入口，真正改变的来源、条件、存储版本及其他作用域输入仍由原LoopDefinition表达。

共有事实在当前查询中按共享节点汇合并迭代至稳定；临时查询位置、已解析输入和必要的等价根交给实际消费者，查询结束释放。事实交集不等于来源路径重叠，借用重叠入口沿原矛盾关系查询实际可能路径。 模块条件仍由原事实域规范化：无符号下界一／非零及上界零／零采用同一原子，更强下界已蕴含的非零不重复保留；条件项的覆盖消费原关系查询，不把字面事实子集当作全部数值蕴含。已知整数零的比较直接消费原零／非零事实，不再生成小于零／大于零的冗余分区；实际Zero已蕴含的数值界退出。有符号零位置沿原Scalar::order_bias与已求值范围确定，原有有序范围和浮点谓词保留各自语义，真实不同的读取条件仍进入严格模块合同。这里不增加全局事实缓存、运行时状态、截断阈值、另一套求解器或公开条件编码。

函数实参和构造字段按源码顺序求值，已产生的值／位置在后续实参和真实调用期间保持有效。编译阶段的临时元数据按实际消费期持有，表达式检查和下层函数体不携带无须存活的宽载荷。合法 B 调用深度不由当前编译器临时存储方式规定。

## 本机编译工作与产物复用

冷编译的语义、优化和代码生成成本与缓存命中分别处理。先消除重复装入、重复 DAG／关系生产和无人消费的中间工作，不削弱语义、精度、借用或源码覆盖；缓存不替代首次冷编译优化。

### 共享编译会话与本机资源

SDK 调用方持有 Compiler，其 clone 共用同一 CPU 活动许可预算。Compiler::available 使用实际可用并行度，with_workers 显式设置预算，Windows on_processors 使用 processor group 和组内编号选择实际 CPU。普通调用使用调用方线程的许可；临时 worker 使用同一预算，不在每层重新扩增整机线程数，不固定为三十二核。

本次新生成参数布局的容量由同一Compiler的max_parameter_bytes配置持有，with_max_parameter_bytes显式选择、默认128字节；Worker／World直接消费该值，编译图及现有缓存沿同一真实输入交接。blcompute的PhysicalDevice公开其已查询的max_push_constant_bytes，调用者可据此配置编译并继续使用同一物理句柄；编译器不承担设备枚举或创建。产物只交付实际uniform_bytes要求，独立加载仍由原Device对真实限制负责，不新增目标状态、运行时登记或链接时生成路径。完整使用规则见[规范ABI章节](BLanguage.md#abi-与代码生成)。

完成装入与参与推导的定义作为只读输入。每个实际工作持有自己的 const 求值栈、Builder、事实和发射上下文；独立具体实例、入口、函数和阶段在依赖允许处并行，融合后的 Stage 局部优化也使用同一预算。声明展开和结果按原稳定顺序交接，保留最早源顺序的真实诊断。

Compiler 只拥有编译工作资源，不持有 Frame、Device、常驻线程池或新的产物权威。错误停止领取未开始工作，已经开始的工作在原身份下结束，最后一个真实消费者结束后才释放输入；线程与绑定错误直接报告，不重放工作。

### 本次构建图与源码输入

build::Unit、UnitKind、Dependency 和 Compiler::build_graph／build::compile_graph 组合本次明确请求的单元、依赖与输出。图先固定实际 `.h`／`.b` 及解析声明，缺少可选实现也是本次事实；共享文件不重复读取／解析，后续文件改写不混入同一次图。

就绪工作沿真实依赖立即分发，等待依赖不占 CPU 许可；内层并行和 Cargo 子工作使用同一会话预算。返回结果按请求顺序交接正式对象或入口映像。图不自动把每个 import 拆成模块，不合并重复输出请求，也不构成跨次 IR 缓存。

算法DLL的CPU范围及集合入口直接编入同一算法对象的COFF代码节、符号和Windows展开信息；原链接器完成其重定位与依赖绑定，原CpuCode仅借用已链接入口并执行原阶段与线程调度，不再把本路径CPU机器码编码进Rust源码后动态复制／重定位／登记展开。执行布局仍由同一编译产物的ExecutionPlan交接；所属DLL及代码依赖保持到最后真实CPU工作和程序消费者结束。独立SDK动态映像仍归原VM所有者，不把它与已链接算法对象混为同一代码归属。

普通模块、应用和算法库对象共用已有对象／归档的模块接口来源。算法库可消费所选模块的类型与常量；CPU范围及自定义归约／扫描可按已编译合同调用无需Frame的普通CPU函数，交接实际值、聚合结果及read／write／inout／atomic位置。已闭合的导入合同直接决定真实参数，不建立应用上下文或暂存Frame参数；本地源码函数仍沿原需求闭包裁剪暂存参数。范围与集合产生的导入合并到所属Program并写入同一算法COFF，链接器在原符号选择处核对一次合同，按实际依赖抽取对象／归档成员；算法DLL将所选原COFF及附属静态库直接交给原MSVC链接，不重组其展开节、不重读同名B实现。GPU-only库无需伪造CPU入口。CPU范围可将真实可读dataset及其字段投影借给无需Frame的普通CPU只读参数，基址和usize stride直接来自原BufferAddress；需Frame的资源操作与可写dataset借用仍待实现，GPU算法不能调用这些普通CPU符号；独立CPU／GPU入口映像仍不接受COFF导入。机器码和已编译公开接口不复制成第二权威。SDK 和受管工具链由安装所有者保持一致；任意并发改写 Rust SDK／外部工具的固定输入与域内分发尚未实现。

BLEngine 的 viewer、editor、资产和执行准备在实际可独立的工作之间共享 Compiler。编译 worker 只返回编译数据；设备、Rc 资源、窗口及最终输出归原线程和产品所有者。最终产物不携带编译会话；真实资源初始化依赖不能因追求并行而拆开。

### 已完成入口映像与对象复用

build::compile_entry／build_entry 使用明确源码位置、模块根、大小写敏感的具体入口、目标及输出目录。COFF与BLBI共用build/identity.rs的原输入记录，编译器生产身份、必要接口／声明与实际消费的实现决定是否重编。当前混合编译器的生产身份包含稳定种子实际静态编入的B前端对象、实现源码、Cargo提供的有效目标／档位／flags和真实rustc -vV；Cargo管理自身配置与工具链失效，构建脚本消费有效值。新增／删除可选.b及import变化沿原装入器体现；不使用时间戳、P4号或显示软件版本充当实现身份。

正式COFF的.blbuild与BLBI原identity字段使用同一构建输入记录，现行编码以语言规范“原生目标文件的增量复用”为准。原source字段直接持有实际入口／模块根、工作目录、选择的入口／显式实例／目标、编译器生产身份、有效参数容量及来源模块／路径／覆盖范围与摘要；同一记录参与原复用比较并供AI查询，不另存旁路清单。来源覆盖范围区分完整源码、模块前部和前部加函数签名；实际消费的声明／实现及本机代码仍沿原摘要与查询集合交接。Declarations唯一持有声明与绑定规则，记录不复制值、布局、正文、IR或候选表。当前源码根的正式模块仍独自发布完整.h，依赖不能代替它；源闭包保留接口、模块／import及全部必要函数声明身份，实现正文不再整文件绑入每个产物。声明身份来自原AST字段，排除正文、注释和源码位置，保留函数类别、C ABI、泛型／const、参数名／类型／访问、返回、目标及规范化合同。新增或改变必要声明仍进入原检查，开放模板正文仍按实际实例检查，不能用缓存跳过必要的有限实例或函数体检查。

bc inputs与原Rust构建输入查询直接读取实际COFF／BLBI记录，在创建Compiler、读取源文件或调用后端之前返回结构化事实；相对来源名称按原工作目录解释，嵌入的接口名称保持原来源标记，不假称磁盘文件。原始路径编码与可表示的文本分别交接，来源摘要不能冒称完整文件内容指纹。不能取得当前记录时如实拒绝，不读取当前源码补造旧产物输入。该查询不装入或执行代码，不成为链接／运行前置，也不代表其余调试工具已经交付。

原generics::instantiate把实际普通、C ABI及cooperative实现交给同一本次输入集合；每个对象／映像保留自己消费的实现键与原Source完整Span，以及原推导执行参与合同。具体类型／const选择仍属请求身份；改变某模板实现会重编实际使用该定义的实例，条件选择不同被调实现的实例各自保留真实依赖。未消费的实现变化保持产物字节与mtime；真实嵌入／调用实现变化使实际消费者重编。模块自身还拥有所有公开声明的参与要求，未导出的开放模板合同改变也必须更新模块；独立入口不存储无关模块导出合同。普通已编译外调只消费真实声明、推导合同和参与要求，提供者私有实现变更且合同保持时调用对象可复用后重链。选择性内联策略和完整泛型模板分发分别保持原未完成范围。

常量、记录、类型集合、外部C声明以及值／记录／集合名称查询继续使用原类别、key、Source Span和Declarations解析。限定名、本地优先、可见性、歧义与无绑定保持；构造与变体父类型、family_members及参与推导仍消费同一查询。源码与已编译依赖头共同保持原模块／import前缀及实际符号／声明粒度，纯类型.h不因没有目标文件依赖而散列整份文本；未消费声明／变体和名称变化不因此重新耦合。当前根模块仍发布并依赖自己的完整接口，全部声明仍先由原装入阶段检查合法性。World及原并行结果汇合实际输入；没有另建名称规则、签名表、IR缓存或运行状态。

附属本机代码的生产输入来自实际 SDK 源、manifest、受管工具链、配置和环境；原子工作的 cwd 属于 SDK 根，生成单元只持有生成源和输出。显示 VERSION 不进入编译器／本机框架输入身份。文件缺失产生正常构建工作，存在但不可读或解码失败直接报错，不暗中重新编译。

入口映像、COFF、显式多单元图及实际泛型定义／嵌入实现粒度的失效已有实现。完整泛型模板分发、选择性内联策略、可替换多模块DLL、GPU参与编译、域构建及完整稳定自举继续各自研发；当前B词法与泛型前瞻迁移不等于完整自举。消费者采用仍需独立记录，缓存命中不作为完整冷编译或引擎启动达标依据。

固定数组与普通记录由原Ty统一给出名义身份、字段／元素、对齐和实际字节布局。零长度数组和零分量记录保留类型与对齐，既不增加虚构元素／标记字段，也不产生不存在的拥有／借用分量。普通B参数及位置按实际分量降低；没有机器参数就不生产引用，入口事实没有可取输入就不生产函数体执行。GPU数据页按实际载荷字节生产，零字节数据保留原逻辑条数、步长与绑定表而没有数据页；上传／读回只消费真实页，不增加空资源类别或运行时拥有状态。

## 普通 CPU 应用、函数与链接

compile_application 将无参数 u32／i32 main 编译为普通 x64 入口，退出码交给 ExitProcess。object::emit 在编译阶段生成启动、输出辅助函数、导入跳板及展开信息，object::coff交接已生成的对象语义及原始字段，B的bootstrap.bindings选择符号并绑定COFF重定位，bootstrap.metadata写出元数据，bootstrap.coff写出标准AMD64 COFF字节。`bc -c` 到对象为止，独立 blink 排列已编译节、解析符号／导入／重定位并产生 Windows x64 PE32+。

普通 CPU 函数拥有独立 FunctionBody 和原生符号，自递归／互递归通过真实调用帧衔接。native_function::Module 由 Builder、CheckedFunction 和模块编译入口按值交接；application::Context 只持有编译期 Frame 寄存器及资源映像描述，不持有函数模块。真实运行期 Frame、设备、存储及完成不进入编译上下文。

普通值参数／返回采用原 Ty 布局、GPR／XMM、栈槽及隐藏结果缓冲。普通 B 位置借用传真实地址：记录／数组保留声明布局，合法重排向量按逻辑分量交接原地址。同一类型／const 具体函数不按调用者物理映射或 CPU／GPU 驻留复制原生实现。外部 C 连续指针需求通过 requires contiguous 沿既有合同表达，不创建连续副本或末尾写回。

需要动态存储或 CPU／GPU 域时，编译阶段通过正式 Rust SDK 产物生成必要静态本机库，随 COFF 的 `.blrt` 保存；`.blmeta` 保存接口、合同和资源绑定。根包装的Cargo清单声明原SDK中实际需要的blanguage／blcompute路径依赖，关闭默认compiler功能；installed来源保持原选择。一次Cargo依赖图共同生产运行库与包装，复用原target/dll，不另起SDK --lib构建或用顶层同名rlib手工交接。暂存源码和私有Cargo package归本编译单元，归档后只清除该单元，共享运行库依赖缓存继续保留。

最终链接只消费这些静态代码和标准重定位，必要时调用 MSVC 链接器生成应用配套执行 DLL 或算法 DLL。运行产物不嵌入待编译 B 源码／值 IR，不依赖原暂存目录。println 和 extern C 是可观察效果，不因返回值未使用而消除；标准输出借用进程句柄，外部库持有到最后代码消费者结束。具体 ABI 见 [NativeInterop.md](NativeInterop.md)。

## 独立模块、归档与公开合同

`bc -c`的普通模块、应用与`--program`算法库在同一次构建中按实际模块提供者固定代码来源：入口使用本次源，非根模块若由`--import`对象／归档或图中的提供者交付，只消费该产物的公开接口、实际实例与合同，不读取同名磁盘.h／.b；其余模块沿本次源码闭包捕获真实.h及可选.b，包含实现内部的导入和纯接口模块。捕获与装入共同使用已有提供者集合及Imports.modules，不再按任意提供者存在而关闭全部导入实现，也不在产物、合同或实例失败后改走源码。构建图在原输入所有者中一次固定这两类来源，同一文件和接口继续共享原解析输入；实际已消费源码实现及提供者合同沿原身份失效。应用沿原调用闭包生成源码函数代码，独立模块仍只交付自己拥有的具体代码和公开合同，其他源码模块的真实外部调用须由最终链接提供者解决，私有实现不成为额外原生导入；链接不读B源码或重新生成代码，Frame仍在完整函数图中闭合。算法库沿原Program、CPU／SPIR-V发射和C ABI工厂生成代码，所选模块的实际常量／类型依赖进入同一构建身份；不再把Library的dependencies丢弃，不生成所选提供者的同名源实现。CPU算法范围调用已编译普通CPU函数仍归C-027.35.4，入口映像及完整模块DLL组合仍按各自能力，不能把接口消费写成全部调用位置已支持。

开放泛型／const 通过 --instance 交付明确具体实例。`blink --archive` 生成标准 COFF 静态库，应用链接从唯一实际入口沿原机器符号需求选择显式模块与按既有库顺序抽取的成员，并继续其依赖；显式对象优先作为明确提供者，显式符号重复及实际抽取成员与明确提供者的冲突仍拒绝。应用入口及实际函数符号选择代码节，局部／跨模块调用、导入跳板与打印辅助只沿真实重定位继续；函数字面量随原代码节保持，pdata／xdata按标准COFF关联COMDAT随实际函数保留。未使用函数不带入自身缺失依赖或DLL导入；模块资源archive只在其真实包装被调用时保留，只导出被调用包装及原资源工厂，未消费包装不再成为链接根。需要的资源仍沿原模块工厂、类型／程序本地索引与完整映像交接，不重排资源或复制Frame。PE容量仍消费所选对象声明的原上界；按实际函数帧和调用引用形成的静态报告不自动修改容量。COFF辅助符号及节关联属于实际编译产物边界，对象元数据、模块资源及执行映像的现行兼容身份统一见[语言规范“已编译模块的资源ABI”](BLanguage.md#已编译模块的资源abi)；真实不匹配在各自原编码入口拒绝；标准关联语义见[Microsoft COFF格式](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#comdat-sections-object-only)。入口、种类及符号唯一性归原链接命名所有者，物理组合只处理已选节、重定位与原合同；文件输入与SDK单对象链接复用同一入口，单对象算法DLL保持原根。公开合同保持的私有实现可单独重编并重链原调用对象；公开事实、布局、参与或效果改变时重新编译真实受影响消费者。Borrow公开编码保留已知无view的Inactive来源键，并只将该无所有者占位的成立条件写为true；它不授予资源、位置或初始化权限，未知来源仍另行拒绝。Data、Parameter、Position、Unresolved及External的真实条件继续按原规则编码。合同导出与COFF读取复用原合同编码／解码交接规范身份：末尾空借用槽与缺失分量按原读取语义相同，不将内部容器长度写成接口差异；中间位置、非空来源及其条件和真实类型／布局／访问／函数事实保持。链接继续精确比较该身份，不解析B源码或重新生成代码；已接受格式中的原调用对象与提供者无需为这种空槽差异改写。

静态栈信息由原机器发射者交付实际局部／保存／出参区和真实CALL引用，普通函数地址不成为调用。它随同一COFF的函数节与重定位保存；链接选择同时删除未消费帧，组合只沿同一节位置和原符号重定位交接，不建立另一符号解析器。可选bc对象报告与独立blink报告消费这一结果；分析不生成代码或调用构建工具，不进入运行期。图的叶项只闭合一次，以同一路径的嵌套帧求峰值；调用环、间接目标、外部代码及运行库范围保持明确未知，不能将有限输入的递归断言为无限，也不能以已知前缀代替完整上界。

CPU入口的局部帧数值统一由原NativeCode.stack_bytes交接实际分配、保存寄存器与出参空间，不含本入口返回地址；普通函数的对象Frame及PE输入消费同一字段，不另存一份local_bytes。范围及自定义集合的五次64位保存计入40字节，普通函数仅在实际使用scratch寄存器时计入其8字节保存；手写集合入口各按真实指令统计。应用、独立模块与算法DLL的CPU执行映像将每个Element主入口的同一字段交给对象报告，行名为CPU、程序身份与stage序号；这些入口没有静态COFF位置，不伪造地址。同一NativeCode保留发射器在实际invoke处记录的调用：Some位置对应该代码的真实调用重定位，None对应真实间接CALL；只取得函数地址的重定位不增加调用。无调用入口以局部帧加8字节返回地址闭合本入口Upper；具名外部／运行库／模块目标本体与间接目标仍未知，已知前缀同时计入实际CALL的返回地址，不把未知本体当零。本帧已超过所给预算时仍如实标注。模块资源未被选中时相应行一并裁掉，GPU专属映像不产生CPU行。四种单入口延续ReductionTail、ScanAdd、CompactScatter、SegmentedFinish也从同一映像交接局部帧，行名分别注明reduction tail、scan add、compact scatter、segmented finish；它们由运行库在主范围完成后独立调用，不与主入口的局部帧相加。ContinuationCode::Scan的双入口也分别按scan prefix／scan apply交付同一映像中的局部帧；自定义扫描和自定义分段归约共用这两个字段，宿主先调用prefix再独立执行apply，不把两帧相加为线程上界。Sort映像的全部initialize入口及histogram／scatter／gather也各自交付原局部帧，行名分别注明sort initialize与从零开始的映像次序、sort histogram、sort scatter、sort gather；初始化个数来自实际展开键列表，不固定为源键数，不按运行时基数轮次重复记录。运行库独立调用这些入口，不把帧相加。这些入口的实际调用／无调用事实已交接；运行库本体、间接目标与实际线程的完整调用栈仍归原所有者，未知不作零栈。

预算由真实调用者声明调用指令前的剩余空间，调用者已经准备的入参／home空间不再归被调用者。报告区分本帧必需空间超过、闭合上界满足、仅保守上界超过和未知；没有预算就不猜实际剩余容量。PE reserve只显示原容量政策，不自动成为该线程预算。调用者、实际线程及外部代码的栈仍归原执行所有者，报告不新增保护、运行时状态或任意深度限制；编译器／B执行耗尽定位继续为各自独立工具能力。接口与命令见[语言规范](BLanguage.md#cpu调用链的静态栈报告)。

资源位置合同对同一输入和同一存储／布局要求的使用条件取析取，公开编码不保存使用点数量。独立条件沿原Clause规范形排序、合取去重及吸收，并用原否定关系作共识闭合，消除短路分割；原真／假条件、类型、位宽、范围及浮点谓词保持，不求解一般算术等价。模块导出与既有COFF读取共用原Contract编解码，把已接受格式中的同义布尔条件交接为同一身份；链接继续只精确比较，不重读B源码或运行事实推导。普通bool返回Proof的完整演化、任意算术等价及模块版本迁移不由本项承诺。

整域独立模块导出支持的 CPU／GPU 入口。纯整域组合在本地阶段与真实模块调用之间分段优化；同一物理存储中的逻辑参数按真实字段区域借用；非重叠字段允许read／write／inout／atomic组合，重叠区域必须全部read或全部atomic。Frame 按物理存储唯一交接，逻辑参数在真实指针／描述符处投影，不复制载荷或隐式传输。一般资源阶段、符号模板分发、设备普通值调用和版本迁移继续开放。

### 模块资源C ABI与已编译映像

根运行库唯一创建、解释和释放 Frame。非根包装只通过不透明指针调用共同分配／执行入口，不解引用私有 Frame，也不跨单元传 Rust Vec／Box。模块工厂交付 C 布局的静态映像字节，包含编译后类型、布局、代码和重定位；消费者不释放工厂静态字节，create 不生成 B 代码。blink_create直接接收调用者的C错误接收函数及显式上下文；模块解码失败在同次调用借用UTF8错误字节，随后交回空指针，原局部类型／映像资源正常释放，后续工厂不执行。错误文本在接收函数返回前有效，保留副本归调用者，不增加错误表、字符串释放链或Frame替身。原B应用入口交付根应用错误接收者的原生符号，创建失败只输出错误、返回退出码1并跳过正文／destroy，成功仍沿原正文与最后释放；宿主选择自己的处理与进程寿命。已有Frame的allocate／resize／run／upload／download／address均返回u32状态1成功／0错误；allocate／resize的句柄与address的指针只在成功时写入调用者输出位置。错误文本沿同次C接收函数及context借出，仅保持到接收函数返回；共同入口不保留错误状态、不销毁Frame或结束宿主。生成B应用自己的适配仅在成功后消费输出，错误由根应用报告、显式销毁同一Frame并退出1；非根仍只借用不透明指针并使用根政策。实际部分效果和最后消费者沿原Frame／执行器交接，完整普通B可失败返回及业务result适配仍见Issues C-020.5.2.4。

当前对象／资源编码和 Value 标签集中定义于[规范“已编译模块的资源ABI”](BLanguage.md#已编译模块的资源abi)。Value 为十六字节、对齐八，标签在偏移零，最大八字节载荷在偏移八；实际活动载荷宽度由标量类型确定，填充不是值。uniform 按逻辑分量交接，不按物理 u32 字数传参。

资源兼容身份只对应实际 C 签名、标量及映像编码和含义，不散列整份 SDK／工具链，也不绑定私有 Frame 布局。真实不匹配沿原对象／资源边界拒绝；软件版本、缓存身份、ABI 和稳定状态分别定义。模块接口交付不代表完整版本演化、迁移或热更新已实现。

same_length是dataset的真实输入长度合同，由函数声明交给原Proof与调用点，整域根及模块交给原Program／ProgramLayout。编译器据该关系允许同一index处理分离的同长输出，并把真正完成的字段初始化交给其原消费者；长度相等不合并存储身份、布局或借用权限。普通函数独立检查时只使用自身合同，CPU应用提取parallel时只交付捕获中已经成立的关系。

ProgramInterface明确携带length_requirements，ExecutionPlan、已编译模块接口和资源映像消费同一关系。requires index的实际Data索引域比较直接消费Program.same_length，允许已成立等长绑定的同一index；DataLength仍只表示长度，等长不合并存储、布局或权限。原运行库arguments已拥有各实际数据集的类型和数量字；CPU、Vulkan及Frame映射共用该入口，在执行开始前一次核对实际长度，不向DomainBindings加长度状态或分别复制检查。每次实际N可变，同一代码实例保持；原Frame、资源传输、CPU／GPU完成和最后消费者释放继续拥有原职责。对象及映像字段改变时更新其真实编码版本，公开Rust接口变更按版本文档中的不兼容变更计数公式交付，软件编号与稳定发布分别记录。

## 原生C函数签名值与代码地址

cfn是必要原生互操作的签名值，不是普通B动态多态模型。系统函数表和回调可以要求运行时函数地址；普通B的复用仍采用具名函数、静态引用、泛型及特化。存入变量、记录或数组只改变这个原生值的存放位置，不自动产生代码所有权，也不证明目标实现和存活期；接口声明者及真实代码所有者分别承担这些事实。

cfn<R,P...>复用原Ty的嵌套参数类型表达返回及普通值／read／write／inout签名，实际载荷仍是一份8字节U64。签名包装只在类型元数据中存在，不增加Scalar、Ty公共字段、第二类型树、运行时签名表或代码所有者。普通B参数、记录／数组、模块和C ABI消费同一完整签名及物理地址，nullable零值与实际调用分别处理；不把函数地址当数值类型或对象动态派发。

unsafe_function与function_address只在CPU显式解释原地址及签名，不调用或装载代码。unsafe_function在原类型转换点结束address的数据借用；cfn继续只持有实际代码身份，function_address重新交接明确的External地址来源。真实目标签名、DLL装载与最后消费者期间存活仍归外部系统和调用者。函数地址的签名保存原TypeName中已绑定的完整名义引用，不复制参数／返回记录的物理Ty布局。World先完成当前对象真实布局，再沿同一签名引用图验证普通C值、位置访问和类型实参；一次验证内已消费的签名引用不重复展开，直接按值记录递归仍按原规则拒绝。实际调用才沿原World解析完整参数／返回布局，因此记录可通过函数地址签名自引用或互引用，不伪造空记录、不新建类型权威。CPU实际间接调用沿原调用ABI执行：目标表达式先于实参求值并进入原调用栈的独立目标槽，参数寄存器准备后从该槽取得本次地址；原Call操作数遍历保持目标寄存器活跃和重写。函数值的requires nonzero与ensures initialized以argument0起的位置名进入同一签名；TypeName及CFunctionType的contracts向量持有这份元数据。具名、外部和函数值调用通过原合同的借用视图消费同一输入义务与输出条件：原Nonzero选择／prove使用已求值实参快照，入口沿原resolve／assume取得事实，原guards／declared继续交接实际初始化；规范身份绑定实际模块常量并规范化条款顺序／重复，不另建函数定义或初始化状态。原字段类型选择由同一纯类型函数提供，cfn构造沿已有Construct进入唯一原值构造器；不把函数地址按空记录打包。具体声明的输出条件使用纯condition_type检查，实际执行与声明共同消费operators中的原字面量／数值／维度／身份／一元规则及matrix的原形状选择；执行端按同一选择保留原转换、Proof与降低，声明端不伪造Value、寄存器、Definition或IR。命名外部声明在原check_declaration复用实际参数／返回类型，调用处不重复检查；普通函数沿原requirements检查一次完整合同，函数值沿原签名闭包检查。dataset快照沿原Ty::owned_dataset与真实count表达存储，初始化位置选择其实际元素；资源所有权和完成仍归原所有者。声明闭合时已沿原运算类型规则检查完整表达式；字面量在绑定签名时消费同一转换和常量求值，保留实际类型、精度及位模式。常量字段按原可见性投影，递归名义记录仅解析实际条件路径，不为比较数字展开整个回调布局。浮点比较由原Fact条件图持有实际操作、标量类型、原值来源／常量位模式及真／假结果；复制、布尔返回、原实参替换与模块合同消费同一身份。浮点数值相等不合并位来源，NaN的关系否定不改写成有序补集；不创建浮点范围表、运行时初始化标志或第二所有者。原capture保留已知浮点常量的唯一存储位，仅用于同一谓词的实参身份，原component_ranges仍不推导浮点次序。普通模块合同编码这个真实事实标签，当前对象格式在原入口拒绝不匹配合同；模块资源的types／images不消费该普通Proof事实；这一普通Proof关系不改变资源ABI或C调用签名。头文件与实现先沿原加载入口核对结构，其中的函数值类型在具体声明或实际泛型实例闭合后由同一World绑定完整签名和数值身份再比较；不同实例独立检查，不将局部相等当作开放模板普遍等价。普通值／位置、输出初始化及循环写范围消费同一签名，非零前提沿原Proof／requires nonzero交接，不增加运行时签名登记、空值守卫、借用表或全局事实失效。Result及一般变体的宽载荷非零交接复用下述条件图，实际间接调用前提保持。B的明确C ABI定义通过c_function交付无需Frame的直接原生符号；C入口的真实调用闭包若需要Frame，由原B263拒绝。可保留回调的代码／状态寿命及资源型C回调继续为独立待实现范围。静态owned释放和集合bind不混入运行期函数值。

明确的B C ABI定义沿原Function保存c_abi；from仍只表示DLL导入。原参数生产与调用消费按实际ABI选择：C位置是一份连续指针，普通B向量位置仍可交接分量地址。具体C声明在装入时检查；B泛型定义先检查模板结构，具体类型／const经原generics::instantiate替换后，在同一实例生产处检查实际C布局与输入／输出合同，正文继续原实现、初始化与访问检查。from导入仍是固定C符号，c_function对显式C声明直接取得该已绑定符号；其签名及输入／输出合同由同一callback入口检查，实际DLL和代码寿命仍归原所有者。c_function消费既有Name／FunctionRef，沿原specialize选择具体实例并从其实参／结果／合同绑定原cfn签名，以FunctionAddress的原CallTarget区分定义符号与外部DLL符号；普通IR结果与寄存器重写保持地址值，原NativeSymbol::Function／External及COFF导入重定位交付代码地址，不生成Rust／B转发器。纯签名绑定由原callback模块提供，写入预分析的Scope与实际地址降低消费同一实例／CFunctionType；Scope只取得类型，原effects继续追踪实际write／inout位置，不伪造Value／寄存器／IR或增加另一份写状态。编译期const的nonzero约束在原实例替换时消费，不成为动态C ABI前提。

原native_function的可达关系包含实际调用和被取址的代码，不把保存地址当作执行。隐式Frame需求来自函数体对原Frame输入的实际消费及结果，并沿实际普通调用传播；本地源码具名调用暂存的内部首参不是独立需求，已编译导入直接采用Contract.frame所声明的闭合ABI，不把第一个真实参数误当Frame。完成本地需求闭包后，无需Frame的原生C入口删除暂存内部参数，只保留真实C参数和返回；需要Frame的C入口由原B263拒绝，不生成转发器。源语言不公开Frame身份类型或取得当前Frame的内建入口；普通B辅助函数继续沿原内部ABI使用同一Frame，根资源C ABI及其不透明Frame指针保持。Contract.frame仍只标记内部ABI需求，参数类型、资源映像及根运行库签名没有因此新增字段。Frame仍由根运行库创建、解释、持有和最终释放；真实外部回调的代码／状态保留与资源型回调继续见Issues，静态代码可取址不等于稳定动态卸载或可复制的Frame权限。

## 数据布局、资源所有权与借用

Ty 唯一持有声明大小、对齐、字段偏移及逻辑分量。元素阶段的dataset字段借用只在原DatasetView记录字段路径，类型与字节位置从原Buffer的Ty取得，长度身份、实际记录步幅、权限及最后消费者保持；借用描述不复制整份类型树或载荷，也不另建运行期资源。同阶段跨invocation读写在原位置降低时收集实际字段区域，动态数组／向量沿原Ty与候选位置保留嵌套选择、记录字段及分量映射，阶段末直接消费同一份区域集合，不扫描IR重新猜测。数据位置与write参数的初始化义务分别保持，不能把参数作用域标记当作物理地址；选择式只合入实际可执行分支，区域归原Builder并在本阶段判定结束释放。真实重叠与append共享限制沿原规则处理，不增加IR／ABI、复制、锁或运行时区域表。普通read位置参数沿同一位置／权限表示支持CPU函数及CPU／GPU元素／cooperative阶段；声明、独立检查和调用都保持只读、初始化及实际借用，命名位置不复制为另一个输入对象。普通CPU原生及独立模块按函数原参与范围交接dataset：Invocation只读参数使用真实64位存储地址、u32长度、u64物理记录步幅和u32字段偏移；Host及write／inout／atomic参数保留原Frame句柄布局。DataPayload.root的Scalar直接区分真实地址与句柄，DataReference只保存原Ty中的字段路径，同一具体类型／const实例只有一个实际ABI，不按调用点或父记录布局复制实现。布局条件沿原资源Inputs／Call／Requirements与位置合同共同推导，递归及模块合同保持。普通只读载荷通过实际地址与步长访问；可写参数继续由原Frame定位实际存储；独占借用按原资源和实际字段区域判定，write及条件输出只更新实际投影字段的初始化位置，父记录其他字段的初始化与编译期内容事实保持。已有连续view要求真实元素连续；整域Frame支持CPU／GPU read／write／inout／atomic字段投影；普通CPU应用atomic dataset原生参数复用同一真实布局与原子权限；GPU字段投影沿同一实际根布局与原提交完成交接，不为适配布局复制列或新增资源所有者。u8／i8、u16／i16、u32／i32、u64／i64、f32／f64、bool、handle、向量／矩阵、固定数组、记录及 enum／result 各按实际布局交接。标量逻辑分量与物理存储字分别计算；窄字段只读写真实字节，宽值不截断高位。填充不作为普通逻辑字段，原始记录复制保留其存储语义。固定数值向量下标选择逻辑分量，Place／Position保留实际分量映射、初始化与权限；动态位置沿原索引IR访问真实局部、dataset或普通参数地址，重排借用不生成连续副本或写回镜像。

### 整域Frame的字段投影与物理布局

GPU数据集绑定以同一个16字节头交接：原页数组的64位设备地址、u32物理记录步幅、u32逻辑字段偏移。原根在既有页表分配的开头持有其零偏移头，页数组紧随其后；非零字段偏移只由本次提交参数持有另一个同格式头，指向原页数组，不复制页地址或字段载荷。SPIR-V按物理步幅计算整记录分页，再叠加字段及真实分量偏移；归约、扫描、排序和临时摘要同样消费实际绑定布局，不再转传未被消费的固定stride。不可变view仍以原连续元素类型访问页数组，设备指针指到绑定头之后。集合首遍与根写回交接原逻辑描述符，实际中间层只替换自己的临时引用，不从根分配重建零偏移引用。输入根只交接一次，字段类型、初始化、read／write／inout／atomic与真实区域关系保持，DomainBindings在原require／completed处消费实际slot与offset，参数和资源由原Execution持有至真实GPU完成。Frame同步GPU调用保持等待本次完成并返回同一根，结果不隐式下载。GPU绑定头遵守现行执行映像语义；Frame共同C签名与对象合同分别按其实际编码版本交接，不相容产物须重新编译。

CPU应用实际持有、或经普通原生函数read／write／inout／atomic参数交接的dataset字段，可按原权限借给CPU／GPU整域read／write／inout／atomic入口；独立模块交接同一引用。原根Frame持有物理Ty、存储与有效域，每个实际根只交接一次；同一具体入口按逻辑Ty工作，不按父记录类型复制实现。根dataset<R>保持原类型，逻辑参数引用其中的Cell字段；read／inout只要求该字段已有初始化，write只按被调入口实际保证的逻辑输出映射回原字段。完整域与单元素输出分别保留原作用范围，未保证写入的字段和兄弟字段不因此获得初始化。同根不同字段可以作为read／write／inout／atomic参数共同绑定，原Argument按真实来源及字段判断借用，普通调用只检查一次，自动parallel使用同一检查。Frame在原绑定列表中核对所有前置同根参数的offset及逻辑Ty区域，真实普通可写重叠仍拒绝；同根只交接一份存储，不新增区域表或复制作业载荷。CPU整域atomic字段沿原指针／stride执行32／64位真实原子指令，要求该字段已经初始化；同根原子别名保持，不能与同一区域普通读写混用。普通CPU应用atomic dataset原生参数与必要atomic T转借使用真实CPU地址，GPU字段投影也按同一物理根与已编译逻辑参数工作，完整typed资源CPU／GPU调用保持。

整域原生参数及共同C执行入口只交接根句柄和字段字节偏移；DatasetBinding为八字节，两个u32分别位于偏移零和四。长度与物理stride由原Frame存储取得，逻辑Ty、形状和访问来自已编译合同，不再转传没有消费者的长度／stride或为物理参数构造证明载荷。普通CPU函数的dataset借用按真实载荷访问需要交接地址或Frame句柄、长度、stride和offset，具体布局由其原参与范围与访问模式确定，与整域资源引用各归自己的实际消费者。

CPU范围入口的同一绑定表使用BufferAddress：十六字节、对齐八，原地址在偏移零，实际stride在偏移八。字段借用的起点为原地址加字段offset，步长保持父记录的物理布局；标量、SIMD、间接读取、where、tile、归约、扫描、分段、压缩、排序及append消费这一布局。连续四字节布局仍整体载入／写回同一SSE2批次，跨步布局逐lane寻址，批次计算计划保持。范围摘要与排序工作区替换原输入时同时提供其实际地址和stride；纹理槽只消费同表中的描述地址。投影本身不复制列，集合算法按其正式语义生产结果，工作区及子资源仍归原所有者。

### view来源与最后消费者

不可变 view 的机器布局为十六字节、对齐八。CPU的`view<T>(source,start,end)`从已有dataset或view借用半开元素区间，原Proof上界／偏移与路径关系共同证明start<=end<=length，允许空区间；已证明不回绕的Offset由原facts入口发布已有Below顺序，不同正偏移的共同大小关系沿原分支／模块合同交接；create_application_view直接复用原offset_application_address按类型步幅执行64位偏移，长度为end-start。源码实参按原顺序求值一次，区间实参求值期间原借用保持；不复制载荷、不增加运行时范围判断、表示、所有者或ABI类别。编译期 Proof 记录原存储完整来源及成立条件；普通值、记录、数组、变体、函数返回和 write／inout 输出沿同一合同交接。数值事实失效不清空引用来源，循环和递归在公共合同形成前闭合局部关系，局部存储地址不得逃逸。

不可变view的for游标保留原引用及活动借用，行内容沿原OwnedBinding／Place／Position交接。view三分量语义来源、行、步长和字段偏移标识同一位置；固定字段、静态数组分量和嵌套view元数据的重复读取共享该行未知值身份，条件、bool、continue及普通函数消费同一事实。身份在游标建立时存在，实际CPU／GPU装载继续读取原地址；不同来源、行、字段和游标周期分别处理。一般动态分量重复选择另按实际能力缺口推进。

只读tile的for游标直接复用原OwnedBinding内容关系，不另存专用元素绑定；位置由真实tile编号、行寄存器及字段字节偏移标识。输入捕获／普通发布后的不可变tile内容与原全局元素分别持有值关系，后续写全局源不改变已有捕获。字段／静态数组分量重复读取、bool、continue、seek和cooperative消费同一行事实，真实TileLoad及块内参与／发布生命周期不变。atomic tile仍只允许显式原子访问，不把独立原子读取当作稳定内容。

固定array／向量的动态选择由原内容Proof、位置与Clause路径共同交接。候选以一次实际元素选择为单位，所有逻辑分量共同交接，不按字段独立重复选择；嵌套位置沿实际下标组合，同一已捕获下标只绑定同一候选。每个候选消费读取前已经成立的路径、源内容事实、该选择条件及本候选新装载寄存器与源分量的绑定，直接形成新值身份、共同别名、布尔条件与view来源，再沿原Proof合流共同事实。本次全部候选的完整关系只构造一次并交回原路径，供后续条件和读取消费，不反复成为每个候选的查询输入；先前读取关系继续参与必要求解。同一记录的布尔字段与索引字段保留共同选择条件，不把分量混成不同候选。普通值或原位置以同一已绑定下标再次选择时，由这条真实关系消费前次条件。原Place尚未读出的候选字段在原OwnedBinding中取得编译期未知身份，不把一次加载结果赋给全部候选，不读取或初始化额外载荷。原赋值、作用域、循环与借用继续拥有内容失效及资源生命周期；Proof布局、对象格式与资源ABI不变。确定整数二元运算的结果关系沿同一Clause保存其实际类型、运算及输入快照；本次事实查询按相等输入推导相等结果，嵌套关系收敛后交给原选择消费者。常量按类型及位模式标识，调用／原子装载／可变内容仍消费各自实际快照，不以源码文本替代值身份。该编译期关系不是运行时缓存、身份登记或另一份资源状态；函数／模块边界仍只交接实际可翻译的公开输入关系，不携带私有寄存器身份。对象合同据其真实编码版本交接，资源C ABI保持原义。

CPU 自包含拥有聚合可同时持有自身 dataset 的 view 和外部 view。移动元数据不迁移物理存储，实际拥有树和选择条件决定来源，不能按候选集合相同猜测两个选择相同。构造期间已产生的 view、返回输出及静态释放函数保持来源到最后真实使用；活动消费者存在时拒绝写入、移动、传输或释放来源。

## 原生并行与CPU／GPU后端

索引值使用既有实际寄存器身份；index()与有界游标ordinal的重复求值从当前路径取得同一值的范围、相等和非零事实，不要求额外局部快照。条件、循环与游标各自的真实值及作用域保持，不把其他迭代、被改写值或另一资源的关系沿用。parallel 每个实例只取得当前元素的普通写权限。阶段可以共享读取 inout 数据，但同阶段普通跨元素读与写冲突报错；范围证明、unsafe_read、read 转借都不授予额外写权限。write 字段在实际生产后可读，完整输出再交接整域 read／inout；有效前缀、稀疏选择和未初始化容量保持实际范围。

归约、扫描、分段集合、稳定 compact、稳定数值键排序和 append 进入同一并行 IR／依赖及原生完成所有者。排序键来自 Scalar 和真实字段字节位置，支持当前窄／宽整数、f32／f64及现有数值向量；编译器不另存键类型权威。prefix 和 Count 的关系随原存储及写入生命周期交接，不靠下载计数重新制造权限。完整类型／算子范围见规范。

tile_input、tile_publish、块内集合、tile_atomic和根块屏障共同表达逻辑块。CPU按块、阶段和lane处理，只保存真实跨阶段私有流并保持原32位物理字流；GPU在一个内核内处理一致屏障，按真实Scalar／Ty将窄值与64位原始位分别放入u32／u64 Workgroup单元，字段／动态聚合沿同一生命周期布局与声明字节步长寻址。每个值只有一份实际共享单元，逻辑高／低字不是两个拥有者；数据布局和最后实际访问期决定同类型平面的复用，不为每个发布点另建系统任务／提交。块内集合的原32位工作区与数据平面分别表达，Shader发射者交出各入口静态Workgroup声明的总字节，ExecutionStage保留各入口峰值，运行库和CLI消费同一字段，不另维护预测预算。DeviceRequirements按实际原子目标分别交接buffer与shared64特性，真实Device所有者独立查询／启用，普通64位存储不扩大原子能力；平台已声明特性却实际降宽的当前缺陷归C-020.2.5.3.1，框架不按厂商选择替换指令／设备或复制存储。subgroup使用真实活动参与者及设备能力，不替代全域phase或唯一写权限。动态同步、任意非原子共享写与协作SIMD仍待实现。

CPU 原生范围通过 Windows 线程池按连续范围领取工作；x64 后端拥有指令选择、活跃性、干涉图、寄存器／栈槽和调用保存。标量与四元素 SSE2 计划共享分析，批次内统一的结构化控制流可保留 SIMD，逐元素分歧及更宽硬件计划仍未实现。编译期已知字面值、直接操作数、真实地址比例与复制关系由原后端消费，不新增运行时缓存或切换。

GPU 后端直接生成 SPIR-V。整数宽度、窄存储、subgroup、原子、光线查询和浮点控制按实际使用产生设备要求，原 Device 负责查询／启用和拒绝。浮点位复制与实际浮点运算分开，f64 GPU 超越函数未实现的部分明确报错；不隐式降精度、换设备或在 CPU 执行。原生代码、自研后端、指令变少不代替精确数值或实测效率。

## 原生存储、传输、完成与释放

Frame／Dataset／Device 及原代码所有者分别持有实际资源。CPU 句柄返回、提交接受、GPU 完成、下载可用与交换链呈现是不同事实。Execution 只持有本次真实直接生产依赖，生产者保持自己的依赖；最后真实消费者完成后才归还命令、暂存、数据、AS、Fence 和代码，不能以 CPU tick 或观察者退出代替完成。

CPU 存储连续，GPU 逻辑 dataset 沿当前页表及完整记录布局分页；单个 VkBuffer 受实际 maxBufferSize 约束，不能把这一物理边界扩大为整个逻辑域上限。AS 连续输入／scratch／本体按真实原生尺寸处理，不缩小几何或更换 primitive 编号。物理块、绑定区间、buffer 及内存分配各按原消费者释放，不增加计数镜像或后台回收。

缓冲上传／清零和 AS 构建可以返回带真实完成点的资源，同队列消费者沿原依赖推进；只读纹理上传显式提交异步设备复制，完整图像读回为显式同步。GPU 存储可直接参与 BLAS／TLAS 构建及新版本 refit，更新持有旧 source 到实际完成，旧查询继续使用旧快照。纹理及 AS 的真实格式、布局、unsafe 前提和输入所有权由原生接口表达，见 [DeviceInstances.md](DeviceInstances.md)。

原只读纹理所有者同时提供Rust SDK二维与三维体资源：`Texture2D`／`TextureMip`和`Texture3D`／`TextureMip3D`各自以同一Arc保存不可变mip、原通道位模式及实际维度；体数据x连续、再y、再z，不建立图集或CPU解码镜像。二维资产写BLTEX v2，三维体资产写带dimension=3的BLTEX v3，各层拥有真实宽高深；文件与具体格式分开，定义见语言规范。`Device::upload_texture`与`upload_texture3d`复用同一原图像创建／传输主体，返回默认`vulkan::Texture<2>`与`Texture<3>`；同一Storage／Image／uploaded继续持有原生image、view、sampler及上传完成点。维度由Rust类型交接，当前二维采样绑定不接收三维句柄。创建处分别消费实际格式的过滤／传输位与同一format、imageType、tiling、usage、flags的图像能力，不能用全局二维尺寸或格式位近似三维可用范围；平台错误沿原Result返回。

`download_texture`／`download_texture3d`沿同一原显式读回主体取得完整mip，三维复制使用真实extent.depth、逐轴缩小和原层间staging对齐，恢复原采样布局；没有原CPU像素缓存。上传交接后CPU资产可以结束，staging和图像仍由原Execution及最后真实消费者保持；克隆只延长同一所有者。三维体资产和GPU上传／读回已提供，B的`texture3d`、CPU三线性与SPIR-V三维采样仍沿[C-003.2.3／.4](Issues.md#c-003-2)继续，BLEngine Filmic LUT须由引擎实际采用，不能由体数据传输结果代替。CPU二维采样描述与原模块资源ABI不因Rust体资产接口而改变。

Submission／GpuCompletion 观察同一真实提交，结果可在观察者退出后继续消费。交换链 try_present 的 Pending 只是未取得可用图像／信号量的原生可用性；Ready 表示已排队，不表示上屏或源拷贝已完成。原存储的最后使用点随拷贝更新，详见 [DeviceSubmission.md](DeviceSubmission.md)。驱动预算是当前进程的动态估计，见 [DeviceMemory.md](DeviceMemory.md)，不是逻辑资源总量或硬上限。

物理 GPU 选择、逻辑 Device 和队列所有权分别定义。同一物理 GPU 上的两个逻辑 Device 不共享资源句柄；不同设备间目前通过显式 CPU 下载／上传交接。直接设备间传输、多队列、多 GPU 自动调度和域内运行仍待实现。

Issues 按具体子功能区分语言表达、编译正确性、冷编译成本、缓存／增量、原生执行及消费者迁移。完整模块／资源阶段、B自有位置取址、需执行上下文的回调与保留寿命、系统与文本基础库、动态拥有／递归容器、其他目标普通调用、异步应用、跨平台、域内编译／运行、自举和稳定热更新均按实际缺口推进；已闭合子范围不会因父项未完成继续占用正在修复状态。

热更新仍按模块版本、执行版本、状态迁移及资源交接共同设计。已有静态模块重链和新版本 AS 快照不等于代码热更新。新版本接收新工作，旧代码、数据和资源保持到最后 CPU／GPU／远端消费者结束；内联实现更新需要重生成受影响执行版本。具体迁移、失败及兼容语义须有实现后才能宣称交付。

当前文档只描述现行设计和实现。源码实现、正式构建、原生执行、消费者采用、数值／效果、性能、P4 和 Git 分别在现有双台账记录；原生验证不自动证明完整渲染、窗口 FPS 或冷编译目标达标。不新增常驻测试、断言、审核或证明流程。
