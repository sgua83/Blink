# Blink 语言架构

Blink（简称 B）提供独立的原生并行计算语言与执行基础，不依赖 BLEngine。接口 `.h`、实现 `.b`；当前由 Rust 实现编译器、原生代码生成、平台与物理资源生命周期。当前实现目标为 Windows x64 CPU 与 Vulkan GPU，不引入第三方编译器、Shader 编译器或并行运行时。

B 也寓意 Base。Blink 希望像 C 语言为上一个计算时代所做的那样，成为 AI 超算时代的基础语言。架构围绕并行计算、数据关系与协作展开，使算法意图能够由编译器与执行框架兑现为原生异构计算；具体能力与规模由当前实现和真实消费者推进。

## 长期系统设计目标与语言边界

本节记录已确定的长期目标与设计原则。B 是面向 AI 超算时代的完整通用与系统编程语言，以顶级原生效率、原生分布式编译、编译器可控的原生并行与调度、稳定热更新为核心，同时服务人、AI 代码生成工具和上层编译器。B 不采用面向对象；这一点是确定的语言边界，不再作为候选或待论证方向。本节记录研发目标，不声明相关语法、后端、跨机执行、热更新或目标性能已经实现。

BLEngine 当前保留 Rust＋B 混合架构，是当前实现事实。B 当前由 Rust 实现编译器和执行框架，不构成语言的永久能力边界；B 长期应能独立构建应用、系统软件、编译器、运行库与执行基础，具备自举能力。长期系统目标不变；当前阶段优先补齐 BLEngine 替换自身 Rust 实现所需的完整语言能力，具体范围与次序见下节。语言能力交付、引擎实际迁移和编译器自举分别按真实结果记录。

### 当前阶段目标：完整语言支撑 BLEngine 纯 B 迁移

本节明确既有完整语言目标在当前阶段的优先实施范围，**不改变长期系统目标**。本阶段的语言研发优先服务于 BLEngine 自身 Rust 实现能够被 B 实际替换，覆盖普通 CPU 组织、数据与资源管理、系统接口及 CPU／GPU 计算。现有 Rust＋B 分工是实现状态，不是把平台、资源生命周期或普通系统编程永久留给 Rust 的语言边界。

需求从 BLEngine 最新已提交源码的真实职责向上推导：实际值宽度与布局、地址与别名、回调与原生 ABI、动态数据结构和字符串、文件／系统接口、错误与资源交接、完整函数／模块／库、实际执行与部署。逐项区分已经可用、仅部分可用、确实未实现和仍待复现的范围，并回到 Issues 的 C-020／C-021／C-022／C-024 及具体关联项记录。Rust 中出现某种写法本身不证明 B 缺能力；应先确认现有 B 机制能否保持同一职责、语义和生命周期。

优先顺序由真实迁移阻塞与依赖确定。先补语言基础、标准库、原生平台边界及会阻断迁移的正确性，再用原生 B 消费者和对应引擎模块实际采用；已能表达程序的局部后端微优化随后继续。完整能力、原生效率、机器控制力、原生并行与稳定热更新的既定要求保持，不通过削减引擎功能、精度或效果换取迁移完成。

语言、编译器和通用执行基础由 BLanguage 拥有；场景、资产、几何、渲染、窗口／输入等引擎职责仍由 BLEngine 拥有。实现语言迁移不改变唯一资源所有者和最后 CPU／GPU 消费者的完成责任，也不以把引擎 Rust 实现转入语言框架、外部包装或宿主逐元素回调的方式伪装成纯 B。操作系统及 Vulkan 等真实平台接口仍按原职责消费。

每项沿现有构建和实际产品命令记录：语言能力已实现，B 已实际编译并原生运行，引擎的对应职责已用 B 接管，旧 Rust 消费和重复实现已退出，功能／效果与性能结果，以及 P4／Git 交付。目标、文档和 B 源码比例都不代替这些事实；未闭合能力继续保留未完成状态。本阶段不新增常驻测试、断言、审核或证明流程。编译器自举等长期目标按原路线推进，不把本阶段迁移目标误写为全部长期能力已经交付。

### 确定的CPU运行目标：仅64位

用户2026-10-28明确：BLanguage只考虑64位CPU运行，不支持32位CPU。CPU代码生成、原生执行框架和系统ABI只按64位目标建设，不设计或维护32位CPU后端、运行库或兼容路径。当前已有Windows x64；其他64位架构／操作系统仍需各自的实际实现，不能据此宣称已经支持。

这一范围不改变数值类型的位宽：u32、i32、f32和实际需要的8／16／32位数据仍可在64位CPU上使用；平台结构布局、文件格式与GPU数值语义按各自真实合同定义。待实现的原生地址、指针宽整数及系统ABI按64位CPU目标设计，usize／isize不需要32位CPU变体；不能把地址宽度等同于所有数据、dataset索引或GPU运算宽度，也不据本节宣称u64／指针等缺口已经实现。

### 确定的大小写敏感边界

B 的关键字与标识符区分大小写，与 C 一致。`value`、`Value` 和 `VALUE` 是三个不同名称，关键字使用语言规范的精确拼写。此项是语言规格及名称身份的确定边界，词法、名称解析、模块接口和生成的互操作接口共同遵守；内部编码与目标语言名称转换必须保留合法名称的区别。

除非用户明确要求变更语言规格，重构、优化、缺陷修复或跨平台适配不得改为忽略大小写，不增加大小写归一化别名或兼容路径。本项沿用现有语义，只明确事实源与修改权限，不新增运行时判断、测试或审核流程。具体规则见 [语言规范的词法与名称身份](BLanguage.md#词法与名称身份)。

### 长期设计原则

1. **完整通用。** 支持应用、系统软件、编译工具、数据库、网络服务及计算基础设施所需的值类型、顺序控制、动态数据结构、模块、泛型、错误处理、内存与资源管理、系统接口、独立编译、链接和部署。CPU 通用能力不能被 GPU 可表达子集永久限制；各执行目标按明确语义提供自身能力。
2. **顶级效率与机器控制力。** 同时追求高质量机器代码，以及顶级工程师对指令、布局、寻址、存储层级、向量化、同步和通信的理解与控制。保留从源码、IR、生成代码到实际执行的可追查关系，发展必要的硬件内建、底层接口和目标专门化。原生代码、自研后端、源码减少或内核减少本身不证明高效率；关键性能不能完全依赖编译器自动猜测。
3. **确定的非面向对象边界。** 不设计类、类的数据／实现／接口继承、虚函数、对象行为覆盖、类层级 RTTI 或基于对象类型的运行时动态派发体系；不换名称重新引入等价对象模型。数据、函数、模块和执行域是基本组织单位，数据的身份、布局和所有权显式定义，不附带可由派生类型替换的行为。该取舍优先减少隐含布局依赖、调用关系和运行期间复杂度，为可控并行、调度与稳定热更新保留明确边界。
4. **完整封装与大规模复用。** 通用软件的封装、共有数据与行为复用、局部修改和扩展需求仍须完整解决。通过数据组合、函数组合、编译期泛型与特化、明确的模块接口和访问控制建设这些能力；函数显式表达所操作的数据及访问关系。不能以取消面向对象为理由，要求大量重复定义或逐项手写转发，也不能把方案名称当作已解决复用需求的事实。
5. **原生单机与计算域内多机并行。** 覆盖 CPU 多核、SIMD、GPU、单机多设备及同一计算域内的多台计算机。一次执行使用域内选定资源；跨域级联由上层应用组织，不把整个超算系统的全局计算与治理纳入执行框架。数据域、访问权限、协作、分片、通信、依赖与完成关系进入语言和编译表示；编译器生成计算及必要通信，原生执行框架负责真实连接、传输、设备提交、完成观察和失败报告。单机与跨机执行遵循一致的所有权、访问、可见性、顺序及完成规则；真实目标能力、通信与失败须明确表达，远端数据不被假定为本地同一物理存储。
6. **编译器可控并行与调度。** 尽量在编译期确定类型、具体实现、访问范围、副作用、生命周期、执行目标和依赖条件，采用编译期多态及目标专门化；接口能够独立检查。运行时根据实际输入、设备与节点选择合法的执行映射和调度，不要求提前固定全部输入、节点数或执行次序。插件通过明确的函数／模块接口及版本绑定扩展，不引入逐对象虚派发；动态装载和调度的范围、必要成本与失败保持可解释。
7. **稳定热更新。** 模块版本、执行版本、状态迁移和资源交接从设计之初共同考虑。更新发生在明确边界，每次执行绑定确定的代码及接口契约，派生任务、异步回调和 CPU／GPU／远端消费者遵守本次版本关系。新版本接收新工作，旧版本完成已有工作；同一可变状态在真实所有者处交接，迁移期间写权限和提交点明确，不形成两份可独立改写的权威状态。资源和旧代码保持到最后一个真实消费者完成。系统持续服务与受影响任务／分区的必要协调分别定义，不承诺任意代码或状态都可瞬时替换。
8. **访问、效果与所有权一致。** 普通函数、模块接口、并行阶段和异步消费采用能组合的访问与效果契约。明确权威数据来源、共享借用、独占修改、必要副本及版本交接；两个不同的数据入口不自动证明其引用范围互不重叠。CPU 返回、GPU 阶段结束、通信完成和远端计算完成分别观察，不能用无关计数或作用域结束代替。
9. **布局与数值语义明确。** 区分逻辑数据、物理布局、执行映射和资源所有权。数据重排、传输、精度变化、转换、运算重排、融合和近似计算具有明确许可与成本；逐步覆盖实际需要的整数宽度、低精度、单／双精度、混合精度及量化。跨后端结果、误差、可重复性与性能分别说明，归约顺序和数值约定明确，不承诺任意并行浮点计算逐位一致。
10. **开放组合、互操作与可移植性。** 通过可组合机制支持新类型与算法，发展编译期约束、库与模块接口、ABI、资源交接、独立产物和上层语言调用。当前操作系统、CPU 架构、设备／队列数量、索引宽度和证明器推导能力，不能未经论证成为永久语言边界。安全前提必须成立；仅缺少某项优化依据时，不把未做该项优化等同于算法不可表达。
11. **同时服务人、AI 和上层编译器。** 语义一致、隐式行为少；错误能定位到具体关系和来源；接口能独立理解和检查；编译结果、资源使用和执行行为容易解释；常见修改能够在局部完成。简洁体现为规则统一、机制可组合和重复表达少，保持工程师深入理解与优化机器执行的能力。
12. **依据真实消费者和实现事实发展。** 保持语言与消费者职责独立，自研前端、IR、优化、后端与执行基础，依托必要平台和标准接口。真实需求推动能力扩展，保留真实失败，区分能力缺口与已证实缺陷；源码实现、编译成功、原生执行、产品使用与性能达标分别记录，不以目标文档代替交付。
13. **计算域内原生编译与独立运行。** 将本机并行、增量和域内分布式编译作为工具链正式能力，按真实模块依赖、泛型、目标代码与产物复用组织构建。编译域和运行域可以不同，产物按目标平台、ABI 与指令要求部署，不依赖原编译域在线。Blink 只负责各次构建或执行所选计算域内的工作，跨域级联由上层应用组织，不以千万节点统一编译或计算为目标。配套独立运维底座面向大规模机器管理，提供远程控制、必要特权和自身更新；管理规模与一次并行计算范围分别兑现，具体能力按实现与原生证据记录。

### 数据、执行与模块演化的共同边界

非面向对象是确定方向；函数与模块契约、数据表示、原生执行和热更新之间的具体规则仍须完成设计与实现。以下约束不构成现有能力声明，也不重新开放类继承或对象派发的取舍。

| 场景 | 设计边界 |
|---|---|
| 同一数据类型和函数用于顺序、并行或不同设备 | 由访问、生命周期、数据表示及目标能力确定适用条件 |
| 多个调用通过不同入口引用共享状态 | 必须检查真实访问范围和依赖，不能仅凭不同参数名或数据身份推定独立 |
| 插件在运行期间加入或更新 | 通过明确模块接口、目标能力、访问契约和版本绑定接入；执行期间的既定关系保持 |
| 原生地址、字段地址或外部 ABI 跨更新边界保留 | 明确其有效期、布局保证与交接方式，不能同时任意重排或迁移存储 |
| 数据跨 CPU、GPU 或机器使用 | 明确代码目标、数据表示、分片、传输、资源归属及完成，不传递本地调用地址冒充远端能力 |
| 运行期间的动态能力 | 将变化集中到声明的绑定、调度和更新边界，必要成本能够观察与控制 |

共同规则必须具体处理以下交汇点：

- **函数、泛型与模块契约。** 接口表达必要的读取、写入、副作用、生命周期、顺序和目标条件，具体实现由编译器检查。静态特化不自动证明数据无别名；取消虚函数也不消除共享状态。接口访问范围或目标保证改变时，相关依赖者重新检查、编译或绑定，不能沿用已失效的并行结论。
- **数据表示与引用。** 数据身份、原生地址、字段地址、外部 ABI、数据域布局及视图的保证分别定义。允许编译器在语义许可下选择布局；模块内部的直接寻址与跨更新边界的引用各有明确保证，不为所有数据访问强制增加运行期的间接访问，不增加可独立改写的权威状态镜像。
- **执行版本与真实完成。** 一次执行及其派生消费者持有所需的代码、数据与资源，不能因入口返回或模块入口切换就卸载旧代码。已内联或静态特化的实现更新，需要重新生成并切换包含该实现的执行版本，不能仅替换一个函数地址就宣称更新完成。
- **状态迁移与失败。** 定义可更新的代码与状态范围、兼容条件、迁移逻辑、可变状态的独占交接点，以及失败后的真实状态和处理责任。状态含义的业务转换由其实际定义者提供，编译器不能凭字段名称推断。稳定接口和状态迁移目标不等于冻结全部内部布局。
- **跨机协作与版本推进。** 装载可按节点逐步推进，任务使用其绑定的代码、通信接口和状态版本。需要共同切换的分片在真实依赖边界协调，节点及通信失败显式进入执行语义；不以全局当前版本、节点数量或宿主作用域冒充实际完成。

运行期复杂度应通过提前确定关系、限制动态变化范围和清晰所有权减少。不得用隐藏锁、复制、隐式等待、额外权威状态或假完成掩盖尚未解决的关系。设计与真实消费者研发共同推进，不据此新增常驻测试、资产、断言、审核关卡或独立证明流程。

### 长期框架

| 部分 | 主要职责 | 必须共同定义的边界 |
|---|---|---|
| 数据 | 类型、状态、结构、布局、身份、所有权、借用及生命周期 | 逻辑数据、物理地址与资源所有权的关系 |
| 函数 | 操作、顺序控制、数据与函数组合、编译期泛型及特化 | 输入、输出、访问、副作用、目标与错误契约 |
| 模块 | 封装、公开接口、独立／增量／分布式编译、链接、装载、版本与状态迁移 | 接口兼容、执行版本绑定、更新交接及卸载 |
| 执行域 | 并行工作、协作、依赖、分区、异步、多设备及多机 | 合法调度、通信、可见性、失败和真实完成 |

编译器与原生执行基础共同落实上述四部分：前端、IR、优化与后端检查契约并生成可追查的机器代码，执行框架拥有真实存储、传输、提交及完成后的释放。优先明确通用基础、访问契约、数据表示、资源生命周期和版本交接，再按真实需求完善单机、异步、多设备、多机及热更新实现；互操作、工具和文档与实现一起成长。普通管理程序可以使用顺序函数、模块及动态数据结构，不要求改写为批量计算。

### 统一函数、结果与执行位置的设计决定（2026-10-27）

**状态：方向已确认；统一源函数、单机 target 与纯接口模块已有实现，CPU 应用普通原生调用已有实现，独立模块契约、其他目标调用及异步应用仍待完成。** 本节针对完整语言设计，仅确定非多机部分，不以书籍示例为边界。C-022.6 的计算域、构建部署与执行组织另行设计；编号枚举及后续普通值 result 增量已实现，详见本章对应实现节；统一源函数、CPU／GPU 同步 target 和纯接口模块已落入现有前端／执行器；异步应用语法尚未完成。

1. **统一函数机制。** 语言表面取消 `program` 这一独立函数类别，应用入口、普通函数和计算函数采用一致的定义、调用与组合规则，能够在合法环境中组织顺序控制与显式并行。CPU 通用能力不受 GPU 子集永久限制；统一函数不等于所有函数均可在任意目标或参与范围执行。编译器内部的 `Program`／`Stage`／`ExecutionPlan` 按实际职责保留，不因表面语法变化重命名或删除必要的阶段与执行计划。
2. **并行表达与调用条件。** `parallel` 继续显式表达并行域，普通调用不会自动变成并行或异步。不增加手写 `requires launch`，也不将 `program` 换成另一种许可；编译器从函数体及被调接口推导必要执行条件，随模块编译接口导出，支持不读取实现体的独立调用检查。公开接口仍明确稳定的访问、目标与生命周期承诺，现有具有真实数据、索引、访问或协作意义的 `requires`／`ensures` 保留。元素实例、工作组协作与整个数据域的发起和同步分别定义，组同步不能被任意分支或普通调用隐式取得；不新增运行期许可对象或重复校验链。
3. **统一执行位置。** 保留 `target` 作为执行位置的统一抽象，它不等同于网络地址。函数声明支持的目标与本次调用实际选择的位置分别表达，单机 CPU／GPU 复用共同规则，同时保留具体能力差异。声明目标能力不等于已经选择设备、迁移数据或启动计算；多机 target 的绑定及部署方式不在本节定稿。
4. **显式结果与枚举。** 保留 `Ok(value)`／`Err(error)` 的结果表达方向，成功与错误可用枚举定义名称及接口编号；成功可以包含已更新、无需更新等不同正常结果，也可以直接返回业务数据。区分普通业务数值与状态编号，不强制纯计算或无失败契约的函数增加结果包装。业务成功／错误编号、外部 ABI 编码与操作系统退出码分别映射，不把成功枚举的非零编号机械视为进程失败。入口可以采用 `Ok(0)` 这样的明确表达；普通值 result<T,E>、match 与显式 try 的当前实现见后节；dataset／拥有记录载荷的当前交接见后节；结果入口适配、其他资源载荷及完整失败交接仍待完成。
5. **同步、异步与真实完成。** 同步调用成功后，其契约承诺的结果在声明位置可用；异步调用产生明确的任务／结果，由依赖与等待决定后续访问。GPU 计算完成与数据传回 CPU 分别处理，不增加隐式下载或无关的全设备等待。错误传播与作用域退出不能提前释放仍被真实消费者使用的数据、代码或资源；业务返回、执行失败与最后使用点共同定义，CPU 返回不能替代 GPU 完成。
6. **原生调用、模块和互操作。** 普通原生调用、适用目标的递归、选择性内联与独立模块编译沿 C-021 推进，不以全量静态展开替代完整函数能力。延续 `blc -c` 与独立 `bllink` 的分工，链接不重读源码或重新生成 B 代码。C/C++ 与 Rust 都是一等消费者，双向调用的 ABI、错误映射、借用和生命周期按真实边界定义，不因语言统一或书籍简化损害任何一方。

当前已取消源 program 类别，普通定义持有从实际体／调用闭包推导的参与要求；CPU 主流程可直接 parallel，target 复用原真实参数和 Scope／Exit／Frame。GPU 同步位置调用等待本次原生提交完成，数据仍留 GPU，不隐式下载。cooperative 继续显式表达块协作，内部 Program／Stage／ExecutionPlan 按原职责保留。推导目前依赖本次装入的定义，CPU 应用普通原生调用／递归已有实现；独立模块契约导出、其他目标普通调用、选择性内联、GPU 普通值返回和异步应用语法仍待完成，不能把本项当作 C-021／C-022 整体交付。源码、原生运行、消费者采用、P4 与 Git 结果分别见 Issues。

### 计算域内的原生编译与运行（设计边界）

**范围已确认；具体语法、协议与实现待完成。** Blink 提供计算域内的原生并行编译与运行。编译域和运行域可以不同；Blink 是更大系统中可独立组合的计算分块，上层应用负责分块之间的级联、数据交换、业务顺序、汇总和故障策略。本节取代此前面向千万级计算域及超大规模统一构建的目标，不以该规模的一体化计算或全局业务调度为语言任务，也不因此硬编码域节点上限。配套底座仍须支持大规模机器远程管理；上层级联须有正式 API／CLI，不能要求用户重写节点控制、传输与更新基础。

- **域、target 与实际资源。** 计算域提供已加入、获准使用并可实际通信的节点与资源；target 引用本次执行位置或域内选定资源。一次原生执行不合并独立域；域内分组沿同一域选择，不为每个子任务新建域。数据域仍表示算法的逻辑数据范围，不能与计算域混为一谈。
- **编译域与运行域独立。** 构建机器与代码生成目标分别确定，原生产物记录实际操作系统、ABI、指令及 GPU 要求，不写死编译节点或运行节点数量。已有产物适用于目标运行域即可重新绑定资源；运行不要求源码、编译器或原编译域在线。跨架构代码须由真实已实现后端生成，不借域绑定宣称已有平台能力。
- **依赖、增量与职责。** 本次源码、接口、泛型／内联依赖、编译器、目标与选项确定后，按真实依赖拆分域内合法编译工作，按完整输入身份复用产物。支持未提交源码，不要求各节点取得完整可编辑仓库。blc 拥有语义、优化及原生代码生成；独立 bllink 只消费已编译代码、符号、布局与重定位。分布式编译不要求链接也远程执行，不把链接重新变成 B IR 编译。
- **一次安装、域加入与原生部署。** 首次安装经 OS 合法管理入口建立维护身份与稳定启动根，随后由底座完成软件安装、配置、诊断和获准特权操作；不要求逐次登录、提权或重新 bootstrap。计算加入与维护授权分开。构建与运行复用同一必要计算基础，域执行者消费已编译入口，main 按入口语义执行一次，用户不必为每个算法编写客户端／服务器或逐机复制启动。
- **四类独立程序。** Admin、Supervisor、Domain、Node 分为独立可执行程序和进程。现有 BLAdmin.exe／BLSupervisor.exe 负责特权与普通用户运维；本方案 blink-domain.exe 负责域成员、本次参与资源、构建／执行图实例、逻辑分片和跨节点调度，blink-node.exe 负责计算机器的注册、实际资源接收、本机编译／计算工作与状态。新计算程序尚未实现；Node 不等同于 Matrix 的 BLNode，也不要求 BLUnit。blcompute 是实际执行进程使用的运行库，不是第五个常驻运维程序；不得将 Domain／Node 以插件或同框架名义装进 Supervisor。
- **程序、进程、运行库与产物分别列明。** 程序文件启动后才形成进程；Admin／Supervisor／Domain／Node 是四类常驻程序，blc／bllink、应用或原生参与工作按需形成进程。blcompute 是链接进 exe／DLL 并在实际宿主进程内执行的运行库，不单独启动；现有同名 Cargo 包另产出 blrun 工具，不能因此把库说成进程。SDK／绑定及目标文件、ProgramImage／ExecutionPlan、数据对象也不自动形成进程。完整类型、启动者、执行位置、寿命和当前状态见 [组件清单](ComputeDomain.md#57-程序进程库和产物的完整清单)，独立本机应用不以 Node 或 blrun 为必经入口。
- **计算与运维通信分开。** 正常链路为客户端／SDK／blctl → Domain → Node → 原生 CPU／GPU 工作；数据按真实依赖在节点执行者之间传输，不强制经过 Domain，也不经过 Supervisor／Admin。维护调用方 → Supervisor → 本机 Admin 只处理机器动作。Supervisor 持有受管 Domain／Node 的原生进程生命周期，不读取其分片图／任务数据库或判断计算结果；计算程序不因域授权取得维护凭据。编译域与运行域复用同一 Domain／Node 程序的不同实例与参与资源，本机独立应用仍不要求这些守护进程。
- **完整独立维护底座。** 以现有 BLSupervisor／BLAdmin 的独立职责和公开接口为复用起点，提取必要依赖并独立分发，不建立同机第二套维护权威，也不以 Matrix 业务系统为前置。Supervisor 以普通用户身份提供远程执行、终端／输出、文件及受管原生进程生命周期；已授权的特权命令、系统配置和受保护安装经本机认证通道交给 Admin。Admin 不直接外网监听，计算身份不自动获得维护权。维护独立于域中心、计算配置、GPU 和业务进程存活。
- **底座自身更新与持续维护。** 独立签名发布、可信读取、受保护安装及 OS 原生稳定启动／激活共同形成闭包；Supervisor、Admin 工作版本及稳定入口自身的更换都须有仍存活的实际所有者，不能由被替换进程成为唯一恢复者。精确目标、候选、安装、实际采用与失败分开，受影响工作按预先授权的排空／终止策略交接，原资源保持到最后消费者退出。底座恢复不等于计算重做；候选失败不提交为采用成功，不能靠无限重装掩盖错误。
- **域内数据与执行。** 编译器表达分片、访问、通信和依赖，执行框架在实际参与节点上推进原生本地计划。数据可以直接分布式分配、初始化或从已有分片读取，不要求入口机器先容纳全部输入；结果可留域内。逻辑索引、唯一写入、边界交换、归约、重新分片和显式传回按真实所有权定义，远端数据、裸指针及 CPU／GPU 完成不能混同。
- **完成、错误与版本。** 每次执行持有确定的代码／接口版本、参与资源及数据关系，旧代码与资源保持到最后实际消费者结束。明确未接收、失败、完成与无法确认的结果；超时或取消请求不等于远端停止，部分结果不等于整体成功。不静默重算或改在本机运行，不以跨域全局恢复掩盖域内实际状态。
- **正式二次开发接口。** 提供 B、C ABI／C++、Rust 同等 SDK 及对应 CLI，覆盖域与节点、编译／链接、产物、执行／取消／事件、输出引用、跨域显式传输及独立维护。上层选择级联顺序、持久化和业务故障策略，框架提供可调用的数据与生命周期机制；不要求手写连接或私有 JSON。接口直接消费原所有者事实，接收、执行、结果可用和关闭分别成立；断线后查询原请求，不自动重放。
- **管理规模与开放组合。** 底座可按明确机器、域／租户或分区管理大规模节点，采用精确读取、有界游标和事件，保留逐节点实际采用／失败，不把全网状态装入单域或要求全量轮询。跨域全局业务调度、事务、barrier、容灾与流程仍由上层组织；原生并行一次使用所选域内资源。普通本机编译与应用保持独立，不以域服务在线为前置。

完整框架方案、候选源码／命令、域内数据过程、远程维护／自身更新闭包及跨域 API／CLI 示例见 [计算域内的原生并行编译与运行](ComputeDomain.md)。以全生命周期与对外合同完整设计，不以开发先后或小规模示例代替框架设计。具体标准库、启动参数、节点入口 ABI、产物封装与协议仍待完成，不把示意的参数或语法写成现有功能。C-021.9 与 C-022.6／C-022.7／C-022.8 记录研发范围，联合 C-020、C-021.4／C-021.5、C-023 及 C-024 按真实消费者推进；本次只更新文档，不宣称跨机能力已经交付。

### 入口编译产物复用与执行装入（C-021.5.1a，首个实现）

构建拥有源码装入、语义检查、优化、原生代码生成和已完成产物的替换；执行只消费既有ExecutionPlan与最终CPU机器码／SPIR-V。原Frame、Device及代码和资源的最后消费者继续拥有运行生命周期，不为复用建立第二套运行时或伪造IR。

正式SDK由调用方明确提供生成目录。入口请求区分源码位置、模块根及大小写敏感的具体入口；实际World装入的全部.h／.b字节、编译器实现生产身份及后端编码决定本次输入身份。新增或删除可选.b及导入改变均沿原装入器体现；不以时间戳、P4编号、文件大小或资源ABI版本替代实现身份。构建期身份只取编译器实际实现与构建配置，不把引擎、运行库私有布局或全部SDK散列混入资源C ABI。

同一入口的生成位置保留一个已完成版本，输入未变即读取最终映像；输入改变才重新编译，以完整文件替换发布。当前所有实际装入模块都参与入口身份，尚未完成按公开接口、独立对象及泛型／内联依赖细分的模块精确增量。产物缺失是正常构建工作，存在但无法读取或解码则报告原错误，不增加隐式重编路径。可信编译产物的装入保持既有原生代码／前缀合同边界。

正式SDK为`build::compile_entry(path,root,entry,target,output)`；`target`必须选择Cpu或Gpu，原源码`on compute`能力不替调用方猜后端。BLBI1构建文件包住原BLRI6映像和完整输入身份摘要，资源C ABI及其编码保持。返回`artifact`和本次`reused`；可信部署产物可经`unsafe build::load`独立装入，不要求源码或原编译目录在线。

BLEngine现有源准备调用改为消费这些最终映像，并调用原CPU／GPU装入入口；共同设备能力仍由同一ProgramInterface提供。该子范围不等于真正首次冷编译加速、本机编译并行、多B模块DLL、域编译或域运算，分别沿C-027、C-021.5.2、C-021.4.1、C-021.9.1及C-022.6.1推进。

本轮入口复用已完成Release构建及原生CPU／GPU整数消费、源码闭包变化、旧代码持有与条件模板装入身份验证。PA3的RTX5070Ti对原f32保留能力要求不满足：直接编译和缓存恢复的image／SPIR-V相同且报同一错误，见C-004.1；不以本轮整数结果宣称完整引擎GPU渲染已跑通。真实首个冷编译性能与完整4K启动仍沿C-027记录。

### 本机编译工作的共享输入与独立执行（C-021.5.2，正在实现）

原装入器唯一生产模块源码、声明及调用参与推导。完成装入与推导后，这些定义冻结为共享只读输入；每个真实编译工作拥有自己的const递归求值、Builder、证明与发射临时上下文。const求值栈不属于共享模块定义，不用全局锁或克隆整份定义解决并发。

独立声明检查、闭合实例、被选择入口及已闭合的原生函数／阶段可并行。真实共享模块契约、资源编号、递归闭包及阶段融合按原依赖完成，不能为并行拆开有顺序的证明或资源交接。未被导出的有限声明继续执行相同语义检查和单映像边界，但不优化随后被丢弃的IR；正式产物所保留IR才进入优化，检查规则不因此删除。

一次阶段的本机工作队列只拥有本阶段真实输入，worker数量取可用CPU与独立工作数，不固定为32。任务按原稳定顺序汇合；并发发现错误后不启动无须执行的后续工作，已启动的工作在其原身份下结束，最早源顺序的真实诊断仍是结果。线程创建／资源错误直接报告，所有已启动消费者结束才释放输入，不重放工作或引入后台编译服务。

语义、优化与代码生成使用本次依赖允许的独立工作，不在每个worker内部再扩增整机线程数。普通模块的共享资源／合同收敛完成后，其独立函数发射才并行；CPU机器码及SPIR-V保持原布局、顺序、ABI、访问与设备要求。执行框架、Frame／Device、缓存身份、独立bllink和计算域职责不改变。阶段实现与原生结果分别记录；单个强依赖入口的冷成本、完整多模块增量和域编译继续按C-027／C-021.5.1／C-021.9开放。

### 尚待确定的具体设计

- 大规模共有数据与行为如何通过组合、泛型、特化和模块接口复用，避免重复定义与大量手写转发。
- 函数访问与效果如何随接口、泛型及模块绑定传递，哪些条件允许安全并行、目标专门化和运行期调度。
- 普通数据与并行数据域如何表达布局、身份、地址、借用和视图，在哪些边界显式转换或传输。
- 模块装载、版本兼容、执行版本持有、状态迁移及旧代码卸载的具体语义与接口。
- 数据初始化、移动、资源释放、异步完成及跨机失败如何共同定义生命周期；不同数值和归约模式提供哪些结果保证。

上述待设计项限定在非面向对象方向内；类、继承、虚函数和对象动态派发不列入后续候选。

后续章节描述当前实现与职责；当前实现限制和原生记录不外推为上述长期能力已完成。

## 当前64位数值实现与资源编码（2026-10-28）

u64／i64是8字节、8对齐的普通整数，32位数值与bool布局保持；CPU仍只面向64位，当前后端是Windows x64。数值位模式与实际Scalar宽度贯通常量、IR、范围／非零事实、原生调用、外部C ABI、对象／归档和CPU／GPU存储。一个宽值是一个逻辑分量、两个物理u32字，Ty仍是记录布局的唯一来源，宽值不自动成为地址或资源身份。

归约／扫描／分段、类型化tile、自定义值函数集合按类型物理大小分配摘要，按声明偏移拆分／重组实际分量；自定义函数参数继续按逻辑分量绑定，原记录填充保持。GPU subgroup的宽整数由实际指令形成扩展类型要求，在原Device创建和程序绑定边界查询／启用shaderSubgroupExtendedTypes；不另建设备、回退或宿主计算链。浮点精度要求保持独立。

当前对象数值合同为BLCO19、模块资源ABI为BLRI5。共同C入口的Value采用16字节／对齐8的标签与union载荷，u32标签位于偏移0，最大8字节载荷位于偏移8，原六个标量标签由resource.rs定义。BLRI5同时包含宽subgroup实际设备要求，真正混用资源ABI仍由既有ResourceBinding拒绝，旧对象须重编。后文BLCO4至10及BLRI1／2为对应早期交付，当前编码以本节和实现为准；机器view布局、普通资源来源合同与Frame唯一所有权保持原职责。

Rust Dataset持有原Ty和实际存储，set_scalar沿原字段路径、活动判别字、记录下标与标量类型写入真实字节；和统一参数共用Value位模式交接，不生成第二份布局或引擎参数表。字段写入沿原words_mut的view失效边界。引擎继续拥有字段含义和输运算法，语言只拥有通用表示和执行；实际采用、源码提交及发布见Issues，不把本层修复当作纯B引擎完成。原生指针／回调、窄类型／字符、字符串／动态容器、64位原子、其他CPU后端及完整版本迁移仍另行实现。

## 编译器与原生并行语义

并行不是普通循环外加线程池装饰。`parallel (element in dataset)` 表达一个元素域，每个实例取得自己元素的写权限；只读数据可共享，未证明安全的任意散写不允许。编译器据此知道访问域、读写集合、阶段依赖和可融合范围。

`.h` 保存模块接口、数据结构和访问能力；实际存在的 `.b` 保存实现与私有声明。纯类型／常量／外部接口模块不需要空实现，普通声明仍须有真实匹配函数体；不伪造空实现或忽略实际 I/O 错误。导入闭包的接口与实现一起检查，包括暂未从入口调用的函数。错误在源文件、行列和诊断编号上报告。检查后的 Program 不能被调用者任意改写阶段；编译器分别构造无前置条件的 ExecutableProgram 与带 requires 的 TemplateProgram。普通执行入口只接收前者，条件执行入口还须取得实际数据持有的域关系；两类入口共用原生后端。

记录、枚举和类型集合的源码名称按其唯一声明来源及直接导入解析：`.h` 声明对直接导入者公开，`.b` 声明只在所属模块可见；限定名也遵守该范围。不可见声明不参加同名候选，所属模块仍优先解析自己的声明。类型解析与原函数名称规则保持同一模块关系，不另建公开类型表、权限状态或运行时名称查找。

泛型实参在调用点取得实际名义类型后，类型交接保持已经绑定的完整定义键。`Ty::syntax` 交付该编译期身份，后续实例化直接取原定义，不将它重新当作被调模块写出的源码名称；源文件解析不能生成这种绑定身份。由公开接口获得的值、调用方私有类型和嵌套记录／数组／结果可以继续传给通用库，不要求库反向导入其消费者。源码中的显式类型实参仍先在调用者作用域解析。真实 Ty、布局、IR 指令和原生 ABI 保持；字段访问控制、公开接口依赖完整性及完整模块体系继续开发。

阶段融合成立的条件是同一元素域、相同前缀及稀疏选择、没有显式 phase，且不存在跨元素的读写冲突。融合后可以删掉中间全局存取和冗余表达式。归约具有集合语义，不能作为独立元素操作随意融合。CPU/GPU 消费同一份布局与阶段描述，不各自维护另一份 ABI。

program阶段层for以当前编译期u32范围展开有限轮次，循环计数器直接进入原常量根；不建立宿主逐元素循环或新的运行时。每轮继续使用同一数据、访问效果、phase及接口关系，常量展开之外的设备动态阶段循环仍待实现。递归检查按表达式、位置、语句和内建值操作分工，调度栈帧不再携带所有未执行分支的临时量；同样的类型和访问诊断保持。

详细语法、支持范围和限制见 [Blink](BLanguage.md)。CPU 计算 program 生成自研 x64 范围函数，普通应用使用下述值入口；GPU 为自研 SPIR-V 计算程序；没有借用 HLSL/GLSL 编译器。SPIR-V 的标准数学扩展仍由驱动执行，不代表引入第三方语言实现。

GPU 的 subgroup 值协作位于同一逐元素 IR 内：归约、前缀和／计数、投票、选举、首个活动 lane 广播及指定 lane／XOR／上下相对 shuffle 都由源程序表达，可进入 GPU 值函数和模块组合。交换值和 lane／mask／delta 作为同一 Subgroup 指令的真实操作数进入既有别名重写、活跃性、DCE 及原生编译；由 SPIR-V 直接编码值交换，不生成共享存储、宿主逐组调用或另一条执行路径。编译结果按实际使用请求 shuffle／shuffle-relative，设备按真实 compute subgroup 支持能力接收。该作用域遵循真实活动参与者，宽度由管线实际执行决定；源 lane 由算法选取且须参与同次调用，不把物理 lane 当作全局数据索引。它不改变唯一写权限，不自动建立设备内存可见性，也不替代全域 phase。含协作的源阶段保留边界；普通 map 继续按已有依赖证明融合。块内原子共享值与根块屏障已实现，非原子任意共享写和动态屏障仍未实现。

`tile_input` 为 CPU／GPU 定义共同的逻辑分块输入快照，宽度由源码指定。编译器根据实际字段读取合并物理输入，整条记录视图及字段视图不重复存储同一源 word，未消费的捕获不生产存储。CPU 范围先复制本块必要值再更新独占元素，GPU 由 workgroup 统一装入共享存储并同步后进入主体；快照只读，不开放任意共享地址写入。尾块只公开有效长度，有界游标与 lane 具有 tile 索引域，不能升级为全局唯一写权限。快照在每个阶段重新生产；含 tile 的源阶段保留边界。

`tile_publish` 在同一逻辑块内发布逐元素计算出的不可变中间版本，只有根块发布点能够切换块内阶段。每个元素只生产自身 lane，编译器拥有同步和物理布局；版本及字段按实际消费者存活，旧版本仍被读取时不能覆盖。共享 word 的复用要求最后读取阶段严格早于新生产阶段，不靠额外屏障扩大复用。输入与发布共用同一描述和存储，不新增全局中间 dataset。

私有状态由 IR 后向活跃性派生。CPU 范围按块逐阶段执行 lane，只保存跨阶段需要的私有槽；GPU 在单内核中让所有 invocation 经过统一屏障，以 SSA phi 保持有效 lane 的寄存器值，局部变量仍各 invocation 私有。两端消费同一份类型、阶段与寿命分析，不为每个发布点创建系统任务或设备提交。无用载荷删除，可观察的 subgroup 同步作用域保留。

`tile_reduce_sum`／`tile_scan_exclusive_sum` 为普通数值提供共同的块内集合语义，返回值不升级为写入能力。集合步骤与发布步骤共用阶段切分、读集合和物理 tile 寿命；CPU 每块线性计算一次，GPU 复用全域扫描的 SPIR-V 树核心完成归约／传播。工作区按逻辑宽度补到二次幂，各分量和后续集合顺序复用；CPU 只保存实际交付给 lane 的私有结果流，不分配 GPU 共享树。

局部变量不能构成“有消费者”的假事实。优化器与阶段切分共用后向寄存器／局部槽活跃性和循环固定点分析，删除未读取的局部写入及其输入、集合载荷和工作区；必要的循环控制与可见写入保留。无用数据消除与可观察的 subgroup 同步作用域分别处理，不叠加运行时检查。

Map 的指令全部消除后，阶段本身也从生产端删除；集合运算即使逐元素指令为空，仍保留其单位元／计数等真实产出。源程序为空或静态范围不展开时，同样可以没有执行阶段。CPU 不生成范围函数，GPU 不生成计算管线、布局、描述符或时间戳查询池；零阶段的程序跨度为零、阶段耗时列表为空，不表示上传／依赖等待或提交延迟为零。GPU 仍由既有原生提交及 Fence 交接前序依赖、保持资源到实际完成，不能用立即完成的宿主标记替代。参数 ABI、requires／ensures 和唯一数据所有权保持。

`cooperative`／`cooperate` 把块内阶段效果写进模块接口与调用点。tile<T> 参数只读借用调用方的类型、字段来源和同一逻辑块，atomic tile<T> 借用显式原子模式，宽度按调用方专门化；函数只能继承范围，不能在实现中暗含另一个固定宽度。前端区分符号借用与具体来源，program 封闭 IR 时完成实际来源／宽度绑定，不向后端传递未绑定参数或虚构物理存储。

借用字段／swizzle 只保留原 tile 的 word 映射；函数根块、循环和游标自有作用域，普通值调用与协作调用共用同一个内联实现。生成代码仍是现有范围／内核的指令及阶段，资源生命周期由既有执行所有者管理。跨模块函数统一消费 .h 导出与直接 import，限定名不绕开接口；函数库可以独立类型检查，原生代码仍从实际 program 专门化。

内联后的局部值转发也属于同一 IR 优化：已知值直接连接使用点，再由既有活跃性删除多余的局部存取。分支只合并相同值，循环先使可能改写的槽失效；真实可变状态和跨阶段寿命保留。CPU／GPU 共用这一结果，不各写一套函数复制消除，也不为优化新增执行状态。完整 SSA 局部提升、复杂控制流与协作 SIMD 仍需继续实现。

选择分支的安全提前求值包含 f32 取负和 abs：两者只翻转／清除符号位，CPU 标量按实际分配位置使用位 XOR／AND，四元素使用 packed XOR／AND；SPIR-V 同样在原 to_word／from_word 边界使用 u32 XOR 0x80000000／AND 0x7fffffff，保留其余31位，包括特殊NaN载荷与次正规数。普通指令能力分类按实际操作处理，单独取负／abs不要求浮点算术保真能力；真实数学、浮点比较、数值转换、tile／subgroup和集合仍由原对应分类确定能力。优化器在原局部值合流处生成 Select，现有直线机器计划即可消费，不增加运行时分支或存储状态。普通浮点算术、数值转换、动态除法和外部索引读取仍保留原分支及其证明作用域；不提前执行未选路径中的异常运算或潜在无效访问。

f32／u32 原始位解释由前端检查对应标量或 2／3／4 分量向量；常量保留原位，运行期复用 UnaryOp::Bitcast。CPU 标量沿原位置复制，包括 GPR／XMM 间 MOVD；SSE2 沿原四元素载入／存储复制，SPIR-V 使用 OpBitcast。IR 的 f32 Constant 在 GPU 也先由原 u32 OpConstant 持有完整原始字，再通过原 from_word／OpBitcast 交付同一 f32 SSA；已知特殊 NaN 位模式不经过浮点常量交付路径，之后的浮点算术继续遵守其本身语义。活跃性、寄存器分配及资源所有者继续消费原 IR，不增加执行器或存储状态。数值 cast 的原行为保持；位解释结果不继承源类型的数值／资源域证明，也不要求浮点算术控制能力。

## 普通 CPU 应用与平台链接

`compile_application` 使用同一模块闭包、普通函数检查、值 IR、优化和 x64 寄存器分配，将公开的无参数 `u32／i32 main() on cpu` 编译为一次普通函数执行；返回值成为进程退出码。共享检查器的空资源上下文用于编译期类型分析；纯值应用没有 dataset 或计算设备，拥有动态资源的应用按下节接入原存储与执行框架。

`application` 检查普通 CPU 应用入口并生成 main 的原生代码；`object::emit` 在编译阶段生成启动、标准输出辅助函数、导入跳板和 x64 展开信息。`object::coff` 写出 AMD64 COFF 机器码、符号和标准重定位。`blc -c` 到目标文件为止，不生成最终 PE。

独立 `bllink` 只消费目标文件：`linker::pe` 排列已编译节、解析导入和地址重定位，输出 Windows x64 PE32+。启动调用 main，再把原始 32 位返回值交给 ExitProcess；数学入口按实际消费导入 UCRT。链接器不读取 B 源码，不进行前端检查、IR 优化或机器码／SPIR-V 生成，也不调用 Cargo 或 rustc。

需要动态数据或 CPU／GPU program 时，编译阶段使用现有 Rust 工具链，把执行框架、ABI 和已生成程序映像编译成静态本机目标库，随 COFF 的 `.blrt` 节保存。`.blmeta` 保存 BLCO 版本 4 的应用／算法／模块类型、入口、归档.h接口、函数合同、资源绑定和本机库依赖；标准 COFF 重定位表是代码位置的唯一重定位来源。链接阶段只把已编译静态目标库交给 MSVC 本机链接器，生成应用配套执行 DLL 或公开算法 DLL；不把 Rust 编译隐藏在链接中。`.blmeta/.blrt` 不作为应用可装载节放入 PE，产物不嵌入实现源码、待编译值 IR 或运行器；模块归档的.h只提供公开接口。

编译暂存产物归所属编译单元所有。沿用当前编译单元身份为 Cargo package 和静态库命名，公开 ABI 前缀不再作为共享 target 中的私有产物键；编译器只读取本单元的库。Archive 接收完整静态库字节、本机依赖和导出信息后，原编译所有者通过 Cargo 清理本单元 package 的产物，并删除生成源码目录；共享 blanguage／blcompute 依赖缓存继续供后续编译复用。真实编译失败也结束该单元的暂存生命周期，原错误和清理错误如实交付，不吞掉任何一方。目标文件已拥有后续链接所需内容，链接不依赖这些临时目录或私有库，不增加全局锁、第二份产物登记表或新的链接步骤。

保留一次装入定义闭包的应用／算法编译，同时提供下节的独立原生模块编译和多对象链接。两种编译入口明确选择，导入产物缺失时不转去读取实现。`blc check`、阶段代码导出 `blc build` 与计算模块执行器 `blrun` 保持各自职责。

`println` 是显式 CPU 标准输出效果，进入同一 IR 的使用、活跃性和死代码分析；即使返回值未被使用，写出仍需执行。含该效果的 map 保留原阶段边界，避免融合改变可观察的跨阶段输出次序；并行参与者之间不承诺输出顺序。独立应用链接原生数值格式化与 Windows 输出调用，嵌入式 CPU 执行由既有代码重定位连接宿主标准输出，两者都用 bool 返回完整写入的结果。f32 的原始位值进入同一 Print IR／原生 intrinsic，两条实际执行入口均用系统 UCRT、C 数值区域和 %.9g 格式；区域对象由单次格式化拥有并释放，不改变宿主区域设置，不建立全局缓存或独立输出状态。标准输出句柄由进程提供，单次打印借用而不关闭。

Windows x64 的普通 CPU 应用、u32／i32／f32／bool 输出、C ABI DLL 调用，以及应用创建动态 dataset、显式传输和 CPU／GPU program 组织已接入，实际执行资源继续由既有 blcompute 所有者持有。通用文本／文件库、资源构造的其余能力、其他平台／CPU 架构及源码调试继续研发。

`extern "C"` 声明属于模块接口与可信的原生 ABI 边界，不制造 B 实现包装。前端检查具体普通值类型和 read／write／inout 位置，外部调用 IR 同时记录真实输入、返回、私有存储与数据读写；未消费返回值也保留效果，map 不跨外部效果融合。外部写入在原证明所有者处使相关事实失效；借用不产生拷贝后写回的第二份权威状态。POD 局部和固定数组使用同一物理偏移／步长，寻址字段保留完整原对象的存储范围。

x64 后端拥有 Windows C ABI 的参数位置、GPR／XMM 与栈参数、必要按值副本和隐藏返回缓冲，调用帧来自实际最大需求；寄存器活跃性保留跨调用值。独立应用由 PE 链接器输出真实 DLL 导入，内存中的 CPU 原生代码由 blcompute 解析并持有 LoadLibraryW 模块，最后一个代码消费者释放后 FreeLibrary；真实装载／符号错误直接返回。DLL 函数须遵守声明的布局、读写权限和调用期借用，不能保留指针或跨边界抛异常。GPU 不生成宿主调用；裸指针值、回调、变参、静态对象和其他平台不在当前支持范围。正式示例见 sample/extern，完整边界见 NativeInterop.md。

## CPU 应用普通函数的原生调用（2026-10-27）

普通 CPU 应用调用现在由同一前端生成独立 `FunctionBody`，调用 IR 明确区分本模块定义和真实外部符号。实际 CPU 主流程中的普通值／void 函数，以及从该位置使用的 compute 值函数生成 Windows x64 函数入口和返回；自递归与互递归通过已声明的同一符号衔接，不继续展开递归体。源语言不增加函数类别或调用许可，CPU／GPU parallel 的元素函数和 cooperative 仍由原并行编译职责专门化、内联；选择性内联和其他目标的普通调用继续研发。

普通CPU调用在原调用入口直接交给原生函数所有者，设备／协作／常量编译的内联体只处理其真实参数和状态；不再保留已经没有合法CPU消费者的第二套内联拥有参数、资源输出及view清理。CPU应用的Data／OwnedValue是私有编译元数据，随原绑定和资源树间接持有，不成为每层设备普通值表达式的按值栈载荷。其Box编码沿原透明codec交接字段，BLCO13、BLRI2和实际B资源／机器调用保持；这是编译表示和调用职责的收口，不为合法B程序规定展开层数，也不表示一般编译性能或生成程序的栈分析已完成。

普通函数分析的声明、参数准备、函数体与出口打包各自持有本阶段临时值；下一层函数体不保留未执行语句分支的宽载荷。Builder、CheckedFunction和外层函数体状态按原所有者间接交接，Returned的普通Value与已有资源载荷同样间接持有；普通表达式仍使用原Value，只在右侧求值期间间接保留已求值左值的编译元数据。实参表达式沿源码顺序求值，再分析真实callee并降低调用；初始化、requires、返回数值／资源／view关系仍由原合同消费。Context只保存实际Frame寄存器，固定指针类型由原使用处构造，不保留无人消费的Value事实。这些属于编译器活跃存储安排，不改变B机器参数、Frame资源所有权或透明模块编码，采用当前BLCO18／BLRI4；不规定合法源码调用深度，也不构成一般编译耗尽或生成程序运行栈政策的完成。

值参数和结果复用原布局、GPR／XMM、调用槽与隐藏结果缓冲；入口参数是同时存在的真实定义，进入原寄存器干涉图。每个函数的局部槽、跨调用值、栈探测和 Windows 展开记录由原 x64 所有者生成。普通B的write／inout借用传实际地址：标量／记录／固定数组按声明布局，向量按逻辑分量传原地址，跨对象和递归共用同一函数符号，不按调用方物理映射再生成函数。外部C接口继续要求真实连续布局、顺序和对齐，按后节的requires contiguous表达这个边界，不能据此限制普通B位置。调用点仍证明原 requires、独占关系与初始化，消费函数实际输出的范围事实，并按原写入所有者撤回旧内容事实。

dataset 交接的是原 Frame 的句柄和长度，拥有记录／result 沿原资源叶交接；调用不复制数据，也不建立第二个资源所有者。函数调用链只传必要的同一 Frame，入口负责一次创建及最终销毁；优化后无资源消费者的函数和调用移除 Frame 参数。实际可达函数共同决定需要的类型／程序映像，原生对象在编译阶段完成本次函数符号重定位及各函数展开信息。拥有参数沿下节的静态资源位置合同交接，不按驻留状态复制原生实现，不把 GPU 载荷默认为 CPU；真实 GPU 最后消费者和显式 upload／download 保持原职责。

普通应用可按完整定义闭包编译，也可采用下节的实际独立模块对象。完整效果／资源阶段合同、借用返回及一般资源引用ABI、版本演化、选择性内联、其他动态相关的资源阶段、其他目标原生调用和热更新仍开放。源码实现、Release、真实运行、消费者构建与提交分别见 Issues，不将原生代码生成当作性能达标。

## 普通函数的静态资源位置合同（2026-10-27）

CPU控制执行和CPU／GPU存储是不同事实。普通函数可以只传递资源句柄、读取length或交接拥有值，也可在CPU控制流中发起GPU域。只有真实载荷读取／写入、所选计算目标、显式upload／download提出位置条件；借用不获得存储迁移权，原Frame、Dataset及真实完成仍是实际资源所有者。

每个具体类型／const函数只生成一份原生实现。输入资源以参数序号及记录／result的逻辑字段路径表示；结果两种载荷即使共用物理union槽，也保留各自逻辑身份。实际用途推导的CPU／GPU条件沿既有原生Contract导出，调用者把条件作用于实际资源。递归输入条件沿原调用图传播，参数置换同样受约束；无需运行时位置表、动态分派、载荷复制或隐式传输。

返回资源保持固定位置、输入位置关系及真实分支可能来源，在调用点代入实参。已有result载荷元数据继续区分不存在分支与位置未知的活动资源；合流不能为未知位置授予访问。循环往返显式传输可沿同一输入条件保持位置；自递归和互递归的输出位置按下节形成闭合关系，真实未知仍为未知。一般动态相关的资源阶段、借用返回、异步及版本演化仍开放。

接口结果模型的规范编号只属于编译元数据，按既有类型布局投影，不能送进实际IR寄存器表或生成转换指令。已修复原result拥有载荷返回在规范化时访问不存在寄存器的崩溃；函数事实仍由原Proof所有者交接。位置条件与返回关系随当前BLCO版本4编码；私有实现改变且合同相同时原调用对象可重链，位置合同改变则旧调用对象不能绑定。实际Release、无库源码CPU／GPU消费者及限制见Issues，不据此宣称完整资源或热更新能力。

## 递归函数的资源输出关系（2026-10-27）

普通原生自递归／互递归现在共同推导输入位置要求和返回资源来源。正在编译的函数已有真实符号；遇到其尚未闭合的返回时，保留该调用、实际资源参数及结果逻辑路径，沿原Returned／记录／result模型交接。实际调用闭包形成后，原residency分析从真实返回的CPU／GPU存储和输入来源求得输出关系，再传播原输入要求。该分析不展开运行期递归次数，不按深度设截断或猜测位置。

访问、同步目标、显式upload／download和循环回边使用同一来源关系。已有确定的错误立即报告；尚含递归输出的实际使用保留源码位置，关系闭合后完成原位置检查。纯控制函数可以转交CPU或GPU存储，返回位置可以保持某个输入、参数交换后的多个实际来源或函数实际分配／迁移的位置；混合来源不能取得不成立的访问权。循环仍保持原拥有关系和回边位置，借用不取得迁移权。

求解中尚无可返回来源与真实未知是不同事实。仅转交一个不存在的资源结果，不会制造活动载荷；总是Err的递归结果可以保持其实际不存在的Ok资源分支。真实未知的旧模块合同仍为未知，不会被当作CPU，不从没有来源推定设备或许可。普通值的范围、bool条件、初始化与所有权继续由原所有者持有，本轮不扩展这些证明规则。

公开模块合同只保存闭合的CPU／GPU／输入位置来源，编译期调用引用和使用关系随编译结束释放；不交付运行时位置表、重做服务或第二资源所有者。BLCO仍为4，资源C ABI仍为BLRI1，机器参数、Frame、原生调用和CPU／GPU后端保持。无库源码的对象／静态库、开放类型具体实例、记录／result、私有实现重链及前轮旧前端读取新合同已有PA3原生结果；实际输入、输出与限制见Issues。一般资源阶段、借用返回、符号模板、版本演化、其他目标普通调用、异步及热更新继续开放。

## 独立原生模块与多对象链接（2026-10-27）

`blc -c --module` 检查本模块实际.h／.b，生成没有应用入口的原生COFF模块；公开的具体CPU适用函数成为真实全局定义，私有可达函数留在所属对象。`--import` 读取已编译模块内归档的.h及函数合同，沿同一World、Ty、Proof和调用分析使用接口，不读取该模块的实现或重新生成其机器码。纯接口声明仍由实际.h提供；普通函数没有对应产物／实例就直接报告缺失。有限泛型生成允许的具体实例，开放泛型用重复的`--instance function<args>`显式导出本次实例；模块对象不保存开放实现模板供调用方重编。

函数合同直接编码原参数／结果布局、访问、requires、参数相对的结果及写后事实、实际目标和是否消费Frame。参数／结果身份在原Proof所有者处规范为相对输入／输出的位置；不保留编译器内部寄存器号作为跨单元身份。调用者使用已归档事实生成本对象，链接时实际定义须与其消费的合同一致。缺失定义、重复定义及不匹配合同分别报错；模块名、函数名与资源本机符号保留大小写身份。该合同是当前原生接口，不是完整的语言效果／版本规范。

`bllink`接受一个真实应用入口对象和多个独立模块，合并已编译节、函数符号、重定位与展开信息，最大栈需求覆盖所有函数；不读取B实现、不做IR优化／CPU或SPIR-V生成，也不调用Cargo／rustc。库内私有实现改写而公开合同保持时，可仅重编库并重新链接原应用对象；本轮已按此方式实际运行。当前BLCO版本4明确拒绝旧元数据，旧对象须在正式编译阶段重新生成。标准COFF模块静态库及其按需成员抽取现已实现，见下节。

各资源模块在编译阶段生成自己的类型／程序映像工厂和局部操作符号，符号前缀按完整模块名的UTF-8字节编码。工厂返回C布局的静态字节描述，应用根运行库解码已经编译的类型、执行布局及CPU机器码／SPIR-V，并把解码结果移入唯一Frame。链接器仍只绑定只读类型／程序基址、工厂地址及标准COFF重定位；GPU设备创建前可以看到本应用全部实际程序要求。模块包装只用标准库，通过不透明帧指针调用共同入口；数据句柄、显式传输、执行、真实完成与释放仍由原Frame／Dataset／设备所有者负责。

初始化最终链接表的入口只属于应用产物；共同allocate／run／destroy／release／upload／download／address的C入口由根blcompute实际所有者提供。非根包装不再编入blanguage／blcompute，不解释Frame布局，也不向根交付由其他Rust单元分配的Vec／Box；根应用和原算法DLL仍编译其真实SDK依赖。已删除整份SDK源码、Cargo输入、工具链和代码生成参数的资源ABI哈希链；兼容由下节实际C接口及映像版本决定。Release优化与B算法编译阶段保持，未据此宣称性能达标。

当前实际范围是CPU主流程的普通原生函数、已编译具体实例、普通位置借用、拥有dataset及记录／result合同，以及模块内部同步CPU／GPU程序。普通位置借用按下节的稳定形参组织，不依赖调用方重排生成实现；拥有参数的一般资源阶段合同、符号泛型体／模板分发、完整公共常量及依赖版本演化、设备普通跨模块调用、选择性内联与热更新仍开放。不得把当前有限实例和资源ABI1写成完整C-021.4、任意版本演化或稳定热更新。Release、实际消费者及提交结果见Issues。

## 模块资源C ABI与已编译映像（2026-10-27）

当前Windows x64独立资源模块采用资源ABI4，身份为8字节`BLRI\x04\0\0\0`，由`blanguage::resource::ABI`定义。该身份同时约束实际C入口、标量表示、映像字段／标签编码和含义；这些合同改变必须改变ABI身份。编译器帮助文字、无关源码、Rust工具链或Frame私有布局改变，不是资源不兼容的理由。链接沿既有ResourceBinding拒绝真正不匹配的资源模块，原Rust私有工厂对象须重编；没有旧格式转换路径。外层BLCO对象为版本11，数值／函数合同和本机目标要求继续独立生效。

工厂`<模块前缀>_resources()`按C ABI返回`{const uint8_t *data; size_t bytes;}`；字节由所属已链接映像静态持有，调用者借用、不释放。根`blink_create()`借用全部工厂字节并解码，创建唯一Frame，返回不透明指针。非根单元的类型分配与程序包装仍使用静态模块基址，调用共同`blink_allocate(frame, type, count)`和`blink_run(frame, program, handles, values)`；只有根运行库可以解释其Frame。共同执行入口从实际ProgramLayout取得句柄和标量数量，调用者按已绑定接口交付有效且对齐的数组，空数组亦须满足指针要求，借用保持到本次同步真实完成。句柄只属于该Frame，调用与销毁遵守独占所有权。

标量数组沿uniform顺序及类型逻辑分量排列。每项为C布局的u32标签与最大64位union载荷，大小16、对齐8，载荷位于偏移8；标签0／1／2／3／4／5分别为f32／u32／i32／bool／u64／i64。窄类型使用低32位，宽整数保留完整64位，bool交付0或1；填充及非活动union字节不构成值。`blcompute::Value`显式采用这一C表示，生成包装在栈上形成数组，普通bool参数按原语义规范到0／1；共同入口直接借用，不每次创建另一份Vec。这里的标量合同不改变B记录、结果、向量或普通函数的原数据ABI。

资源字节在编译阶段由`resource.rs`产生，依次保存类型序列与CPU／GPU映像序列。映像保存实际ExecutionPlan、已编译机器码／重定位或SPIR-V及辅助阶段，不保存值IR供运行时编译。编码复用模块codec：整数为小端，序列／字符串长度及usize编码为u64，枚举使用明确u32标签，bool与Option存在位为0／1单字节，字符串为UTF-8，字段按正式编码声明的顺序。类型、布局、阶段、重定位和代码标签以resource.rs及其复用的既有编码声明为具体合同。解码只是恢复根所有者的已编译数据，unsafe原生API要求真实编译产物及其访问／布局／前缀合同，不能把可执行字节输入当成任意不可信数据的验证器。

静态工厂描述不产生跨模块分配／释放；解码后的类型、映像、实际存储、代码装载和外部DLL由根Frame及派生真实消费者持有。Frame与其代码所在映像保持到最后实际CPU／GPU消费者完成；显式传输、最后消费者释放及同步GPU结果仍驻留设备的语义保持。原B应用错误仍输出真实原因并非零退出，不扩大成一般宿主可恢复错误协议。公开算法DLL的create／run／destroy、C/C++头文件和Rust包装继续使用原接口。

实际Release验证已使用两份私有Frame布局不同的SDK双向组合CPU／GPU模块，并由C++直接消费静态描述及不透明Frame；九类集合布局、记录值自定义scan／reduce和外部调用也有原生结果。它们只闭合此资源表示边界，完整模块版本演化、资源阶段与借用返回、任意状态迁移、异步／远端和稳定热更新仍待实现。当前Windows x64与这份映像编码不构成语言永久平台边界，具体范围及原始记录见Issues。

## 模块静态库与按需成员链接（2026-10-27）

`bllink --archive`将已经编译的独立B模块保存为标准COFF静态库，也可组合现有模块库。成员保留原COFF对象字节、归档.h、具体函数／资源合同、代码及编译阶段产生的静态执行框架。库目录保存符号与成员偏移，长成员名使用标准长名表；目录与物理成员共同属于这个产物，不引入另一份可改写的接口来源。文件格式依照[Microsoft COFF库规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#archive-library-file-format)。

编译器通过`--import library.lib`读取已有成员接口，沿原模块名称、可见性和具体实例规则检查；不装入库实现源码或生成库机器码。链接从显式对象的未解析模块符号出发，按库顺序选取定义所在成员，继续处理该成员的实际符号依赖；每个成员只交接一次，跨成员循环引用可以在原符号图中闭合。函数／模块大小写身份和同名文件中的不同成员分别保持，不按文件名合并身份。

未使用成员不参与原生绑定、执行框架静态库或资源基址交接，也不因其未使用依赖缺失而阻塞实际应用。显式对象保持其实际定义，真正缺失的符号及不一致的合同仍由原组合入口报告；不按“可匹配版本”切换另一个定义。选中成员的代码、模块工厂、类型／程序映像与展开信息仍由原链接及Frame所有者消费，CPU／GPU执行、显式传输和真实完成保持。

CLI与Rust原生API共用这份实现：`object::Input::read(...).objects()`导入对象／库，`object::archive(...)`归档已编译模块，`linker::link_inputs(...)`链接对象与库。归档及链接不调用B／Rust编译器，BLCO成员仍为当前版本4；标准库容器不自动提供任意外部C对象接口、完整资源版本演化、符号泛型模板、完整依赖版本或热更新。当前读取Microsoft COFF的双链接成员目录，其他归档布局的支持按实际目标另行实现，不据此约束语言的长期平台范围。

## 独立整域模块与实际发起入口（2026-10-27）

独立模块现在可以交付现有dataset借用与普通uniform接口的整域函数。模块编译拥有实际CPU机器码／GPU映像及原资源入口，按on cpu／on gpu／on compute形成相应位置的原生调用入口；应用只消费公开.h、已编译具体实例和模块合同。CPU应用及普通CPU包装函数调用这些入口，仍借用原Frame和原dataset句柄／长度，设备位置、显式upload／download、同步调用的真实完成及最后消费者释放保持。不从库私有源码重新生成程序，不复制载荷、隐式传输、注册另一套程序表或引入执行进程；链接只绑定已编译代码、合同和原资源基址。

模块元数据独立保存公开函数推导出的Invocation／Domain／Host参与要求；不能把所有已编译声明都当作Host，也不能从当前是否恰好导出了某个泛型实例反推声明身份。尚无具体实例的开放声明仍保持参与要求，使用未导出实例则按真实产物缺失报错。普通CPU包装函数对已编译整域入口的调用是实际CPU发起关系，归Host检查及原生调用；它不尝试展开.h中不存在的实现体。符号泛型模板分发仍未实现。

每个具体整域入口的原模块合同保存实际目标、缓冲区与uniform布局，以及完整域、同长度域和归约首元素的初始化效果。源程序和已编译程序共用这份效果表示；调用点沿原Position／确定初始化事实消费，不以write声明或返回时刻伪造完整输出。筛选输出不会初始化整份目标；完整输出改为筛选输出后，旧应用对象的原合同不能绑定新库，新编译的CPU write包装也必须面对尚未完成的输出。布局与初始化合同不变的私有实现可由原应用对象重新链接采用。原来直接遍历Program的重复初始化分支已删除，不引入运行时初始化表或另一份完成权威。

当前目标格式为BLCO版本4，旧版本目标需重新编译；链接只消费当前已编译产物。库与应用按模块资源C ABI和已编译映像版本交接，不绑定私有Frame表示。本轮真实验证包括移走库.h／.b的CPU／GPU调用、三层模块与拥有资源返回、有限／显式开放实例、带填充记录及混合浮点／布尔栈参数，以及零条、单条、65条和1000003条的完整结果。CPU浮点算术及GPU浮点值选择／传递已验证；PA3 GPU对需要DenormPreserve与SignedZeroInfNanPreserve的浮点算术仍真实拒绝，不能将参数传递当作该算术能力完成。

纯整域内部现也可组合独立模块的整域CPU／GPU入口。编译器沿同一域展开顺序收集本地阶段与已编译调用，本地阶段在两次真实模块调用之间按原IR优化；模块边界使用既有原生函数调用及原合同，链接只绑定代码与资源，不读取库实现或重新生成内核。prefix事实在原编译所有者中按函数作用域进入／退出；子调用改写实际Count时撤回相关作用域事实，其他父项关系继续保留。当前单个内核映像仍表示封闭阶段；需要外部对象的组合使用原生模块／B应用产物，不能把缺失库体写进单一内核。

应用与域内调用遵循相同访问语义：同一存储的重复参数可全部为read或全部为atomic，普通可写混合别名仍拒绝。Frame只移动每份物理存储一次，逻辑参数在CPU原指针和GPU已有描述符准备时投影；前缀关系与GPU阶段读写依赖按实际物理存储交接。GPU提交继续持有唯一存储及最后使用点，实际完成后交回原Frame，不冻结／重建载荷或隐式传输。此次实现改动编译器与blcompute绑定层，原生后端及GPU算法保持原实现；原始验证使用Release，不据此作一般性能达标结论。

## 普通B位置借用与C连续布局合同（2026-10-27）

普通CPU位置的借用ABI由其声明类型决定。标量、记录、矩阵和固定数组保留声明物理布局并传同一实际地址；源语言向量可以合法选择重排／离散分量，因此按逻辑分量交付原存储地址。前端沿现有CallParameter／CallArgument生成这些指针参数，已有Windows x64调用槽、栈参数、输入活跃性及展开信息直接消费；不新增IR指令、原生后端分路、运行时布局描述表、数据复制／写回或调度。普通B函数符号不再携带调用方的`#r`物理映射；一份已编译具体函数可以接收不同合法位置，递归和跨对象转交也保持同一符号。开放泛型仍需导出实际具体实例，资源位置按前节的静态合同交接，也不再生成`#s`实现；一般资源阶段系统仍未完成。

Place持有借用的逻辑分量／实际地址，初始化和别名继续按原Position及访问所有者处理。向量地址只是同一存储的借用，不是多个载荷所有者；记录和数组不按分量扩张为整份地址表。动态下标及实际参数仍按源顺序求值一次，随后各分量地址从已确定的位置形成。类型、合法重叠、write完整输出及最后消费者规则保留；不能以取消物理映射专门化而允许重复独占分量或重叠可写实参。

C函数的原指针ABI需要被借用区域符合参数类型的连续偏移、顺序与对齐。B包装函数若接收可能离散的向量位置，并把它作为完整C指针借用，接口使用原requires体系声明`requires contiguous(value)`或某个字段／swizzle。调用点从实际Place静态满足该条件；函数体只使用当前声明中已经承诺的布局，递归／多层调用传递同一前提。布局不因载荷改写而失效，也不假定其他参数或未覆盖的分量具有该性质。普通B借用本身不需要此标注，直接且已知满足布局的C位置也不增加标注。

此项是已有跨模块／C ABI的必要内存表示合同，不是附加安全许可或通用校验流程。仍沿原contracts::resolve／prove和接口序列化工作；不新增事实登记表、推导遍历、运行时检查或隐式等待。库对象导出该requires，旧调用对象绑定不同布局要求的库会在原合同匹配处失败；不读私有B实现、不重新生成库代码或制造连续副本。C的read仍要求此前已初始化，write必须在正常返回时完整写出；原外部读取入口已补上原生参数位置，防止只写参数在初始化前被只读C调用观察。

本轮PA3真实验证覆盖uint／int／float的2、3、4分量、矩阵、带填充记录、数组、动态下标与顺序副作用、开放具体实例、多对象复用、递归及实际C++／Rust接口。重排位置与拥有记录／隐藏结果／栈参数组合后，沿同一Frame完成CPU→GPU→CPU并核对0、1、65、1000003条全部结果。任意借用返回、一般拥有资源引用／阶段、符号泛型模板、完整依赖版本和其他执行目标的普通调用仍开放；本轮未测通用效率，不把不复制载荷当作性能已达标。

## 编译映像与执行所有权

native::compile_program 与 spirv::compile_program 在编译侧一次生成主入口、集合尾部／传播、排序和间接启动的全部代码。ProgramImage 将最终机器码／SPIR-V、真实重定位与 ExecutionPlan 一起交给执行器；CLI 阶段导出、算法 DLL 和原生 SDK 消费同一结果，不各自维护辅助代码的编译选择。

ExecutionPlan 只拥有接口、前缀关系、访问集合、集合布局、工作组／共享存储与实际设备需求。自定义集合保留输出类型及源／目标字段，投影、单位元和合并器正文随编译结束释放。ProgramInterface 让数据打包和资源绑定消费必要的只读布局，原生代码消费者不再为了引用 ir::Program 的类型而持有指令。编译器内部的完整 IR 继续负责检查、优化和代码生成。

CPU 执行器只装载编译好的范围／集合函数、解析真实符号并管理可执行内存，GPU 执行器只按编译结果建立实际管线和原资源。原 CpuProgram::new／Device::compile 也先进入同一编译映像路径；数据、Vulkan 提交、域关系、Fence 和最后消费者之后的释放仍由原 blcompute 所有者负责。算法目标文件在编译时保存最终代码，create 不再从值 IR 编译；Rust 链接只封装平台执行与 C ABI。生成映像的 unsafe 恢复入口承接同版本编译输出这一原生 ABI 信任边界，不接收动态宿主数据或补加运行时证明。

## B 应用的数据所有权与显式执行

CPU main 使用 dataset<T>(length) 创建全零的普通值存储，编译器复用原类型、索引、局部位置、控制流及 x64 值入口，生成真实 CPU 访存；read dataset 共享借用，普通 CPU 函数的 inout dataset 独占借用整份已初始化 CPU 存储。资源不能被复制成第二个独占所有者或按普通值返回；普通 CPU 函数可用 dataset<T[,N]> 返回自己拥有的资源。返回转移该所有权，借用不能作为拥有资源逃逸，原作用域只清理其余本地资源。return、块结束、break、continue 与 seek 的清理由现有退出边携带，原生运行库只释放对应实际资源。

普通函数的只读／独占资源参数借用原分配身份与实际存储，函数内可转借和执行 CPU program；仅声明者拥有释放和物理转移权，返回时只清理函数本地拥有的资源。独立接口检查使用参数的符号身份和原形状，实际内联使用调用方的同一资源，不分配参数镜像。函数实参在原调用入口统一判定整份资源、元素、字段及只读／原子位置的重叠；C ABI 只消费已确定的借用并投影地址，删除重复别名判定。该边界没有新运行时状态、锁、引用协议或额外调度。

upload／download 由 B 明确转移 CPU／GPU 存储，target(cpu, ...)／target(gpu, ...) 只执行位置匹配的真实资源。位置事实沿原环境、分支合流与循环继续边检查，不建立统一地址空间或隐式迁移。B 的 GPU 同步调用沿本次真实提交的 wait 完成后返回，数据仍留 GPU；低层 SDK 异步接口继续交付带真实完成对象的原资源，CPU 下载负责实际传输。有效域属于同一 DomainBindings 所有者：调用只投影实际绑定，未参加本次执行的资源与其关系保留；写计数和释放按原身份撤回关系，不读回数值重建能力。

每个应用调用帧拥有自己的资源绑定与已声明程序，沿原 Dataset／GPU Dataset 执行，空槽在作用域结束后复用。编译器剔除优化后没有调用者的类型／程序映像；CPU 原生范围与 GPU 管线在实际首次执行时装载，设备在首次上传或 GPU 执行时创建，保留原单设备、声明程序能力及物理生命周期。程序映像被装载后归原代码／管线所有者持有，不保留值 IR 或另一份可写存储。

blc 将 main 与实际资源依赖编译进目标文件，bllink 单独生成 PE32+；需要资源时，链接器使用目标文件中已有的静态本机代码生成同目录的执行库。该库嵌入最终机器码／SPIR-V 和执行布局，不编译 B 算法，也不调用运行器。运行库 ABI 只服务同次构建的应用，公开 C/C++ 算法 DLL 协议保持独立。入口使用的运行帧先作为 ValueCode 参数参加既有寄存器映射，再连接原生创建／析构，不能在优化后使用旧编号。

当前实现范围为 Windows x64 应用的普通值 dataset、显式 CPU／GPU program 调用与原生位置借用；动态部分移动的拥有数组／动态容器与view图、其他资源种类返回、一般动态子域／数组初始化推导、其他执行域的整份独占资源借用、应用内拥有view图及GPU view构造、纹理／AS 创建、通用标准库和其他平台继续按所属能力推进。正式示例为 sample/applications/datasets.b。

### 拥有 dataset 的函数返回

函数返回在原返回上下文中区分普通值与拥有的 dataset；资源结果保留实际元素类型、长度、静态形状和 CPU／GPU 存储位置。每条资源返回边先检查声明及唯一所有权，再撤回原局部的释放责任。提前返回和循环返回沿原 Scope／Exit 交付句柄与长度，不增加资源副本、运行期所有权标记或新的调用 ABI；嵌套调用继续使用同一应用 Frame。未接收的资源结果在该表达式结束后沿原 release 退出。

多返回位置合并长度事实和存储位置，返回值仍指向被实际分支选中的唯一存储。固定形状由真实长度事实满足；CPU 函数可以返回已显式上传的资源，后续 GPU program 及下载消费原最后使用点和 DomainBindings。位置不一致的继续关系沿原应用位置规则处理，不能隐式传输。CPU 应用普通函数现沿本章原生调用交接，独立模块 ABI、通用资源值或稳定热更新仍未完成。


### dataset 移动与拥有形参

局部资源初始化和 CPU dataset 按值形参沿原 ApplicationData 交接句柄与元数据；按值是唯一所有权交接，普通值参数仍是值快照。原 owned 位在同一编译期绑定中改为拥有／借用／已移动三种状态，不增加并列权威表、运行时 flag、资源注册表、数据副本、IR 或调用 ABI。借用不能升级成拥有，实际元素位置或前序实参仍在消费该资源时不能把原存储交给后续嵌套调用。

普通分支、短路和选择只合流真实继续边。部分路径消费后，在仍拥有的对应边结束该不可继续使用的资源；循环按每个入口绑定记录原所有权与位置，在真实 break／条件失败边分别完成必要释放。原 LoopContext 保存这些编译期出口，资源释放直接进入原 If／Loop／Scope，不新增运行时 drop 标志。循环继续边保持入口所有权，循环局部资源仍在 continue／seek 前结束；移动前已结束的旧名称不再参与实际访问或释放。

接收拥有形参的 CPU 函数可继续移动、转交、上传与返回，实际调用仍使用同一应用 Frame。接口独立检查用原符号资源，封闭调用绑定真实同一资源；CPU 拥有形参的入口要求 CPU 存储。GPU 返回与局部移动保留原最后使用点和 DomainBindings。动态部分移动的拥有数组／动态容器与view图、其他资源种类与通用跨异步借用继续开放，不把本轮静态函数展开作为完整内存模型或独立调用交付。

### dataset 可变绑定与资源身份

普通 CPU 应用的 dataset 整份赋值交接右侧唯一资源；类型和声明的固定形状留在绑定上，实际句柄、长度、位置与有效域来自资源。编译器只为确有整份重赋值的绑定使用原有两个局部槽保存句柄和长度，普通不可重绑定快照保持原值路径。无初值声明没有物理资源或原生初始化，直到真实赋值后才可读取和释放。右侧先求值，目标仍拥有旧资源时才沿原 release 结束旧资源；自移交和移动后重新初始化不产生重复释放。

绑定槽与存储身份分开：ApplicationData 的句柄沿原 Value／Proof 保存来源，每次装载快照携带实际资源来源，元素位置同时保留真实机器操作数和该来源。数组投影、C ABI 地址、借用重叠、长度和索引域消费同一身份，不新建身份注册表。资源被替换时撤回旧来源；循环中可能写入的绑定在原副作用入口撤回旧事实，实际元素／游标借用仍保持其资源来源。现有整数／bool 的精确事实在普通局部读取时直接供原 Value 消费，不增加数值推导状态或另一套范围算法。

CPU dataset 游标的内容身份归原 OwnedBinding／Proof。ApplicationElement 读取与已有局部位置使用同一个 read_owned_proof，不再在每次实际装载后丢失位置内容来源；实际 ViewLoad 保持，未引入运行时值缓存。原 assign_owned_proof 按同一位置的写后值更新，并按真实位置重叠撤回可能被别名写入影响的分量。普通 CPU 函数的可写 dataset 参数和 application_execute 的可写数据交接撤回相应载荷事实，不撤回资源句柄与长度身份；read 借用和独立普通值保持。原 effects 写入收集区分绑定／位置写入与 dataset 内容写入，将未来迭代变量按其真实资源来源和字段／数组投影映射到现有所有者，供原循环入口失效使用；不求值下标、不再次生成表达式代码、不新增权威状态或后端检查。包含资源的普通记录直接读取原载荷元数据，表达式恢复也按实际资源来源识别受影响位置。这是编译器现有所有权及条件事实的修正，IR、ABI、执行框架及运行时检查路径不新增机制。

原生位置参数的入口内容与地址分属现有语义和物理调用层：ParameterContent按参数／逻辑分量命名编译期入口内容，Proof直接翻译参数、结果、写后事实和bool命题，不再为静态事实拆出普通Value副本。调用点在原所有者中为未读内容取得身份；使用原虚拟寄存器身份池且不发出装载，value_code按既有使用集在原生分配前清除无机器消费者的编号。真实写入按原分量失效与正常返回合流撤回旧身份，write不持有入口内容；机器参数、原地址、Frame及后端保持。已编译模块沿原Contract编码传递这些关系，不新增运行时状态、注册、复制或额外检查。递归环、动态位置、完整字段requires／ensures和一般资源合同仍按实际缺口开放。

bool入口真值沿原Fact::Boolean、Condition与Proof表达，不在机器ABI增加状态。函数合同保留必要的参数真／假关系，at_call替换为调用者已有条件；实际分支与返回把已知真值写回原Proof，矛盾真值表示没有可行结果路径。数值、位置和bool副本仍按原值身份及写入生命周期处理，不把旧谓词转嫁给新内容。函数及实参的可观察效果保持，不为静态推断新增运行期缓存、守卫、装载或解释器。当前共享条件图及逻辑分量已交接析取路径和结构化bool载荷；一般关系求解、动态数组选择和循环回边不变式仍开放，不升格为语言限制。

现有控制流持有正常路径的共享条件图。分支分别继承入口条件，仅合流真实继续边；ReturnContext在实际返回点把路径条件交给bool逻辑分量与write／inout输出，LoopState沿自然结束、break与continue交接路径。这样if(index<count)后返回true／false或常量bool字段，仍能在调用点代入实际资源长度；OR不在代入前压成共同端点。当前值Proof与执行路径各自负责值快照和实际执行条件，改写后的内容不会继承旧观察。复用原Clause及模块合同编码／COFF4，不增加运行时状态、检查、机器参数或后端路径；一般关系求解、循环回边不变式和分开读取的动态位置关系继续开放。

固定数组动态读取的语义由原位置与Proof共同持有：Position::Indexed保留实际槽位的候选逻辑位置，bounds按选择条件投影原所有者的分量事实，临时array值直接交接原Value的Proof。同次聚合读取用已产生的真实结果寄存器关联各字段来源，不生成第二次装载或另一份位置权威。只读材料化数组同样保留其实际局部槽位，并在原StoreLocal完成后标记初始化，不授予写权限。原Clause必要事实反复交回同一共享图直至稳定，让后续槽位约束排除先前不可能分支；每轮只消费共享节点，不展开析取路径的笛卡尔积，不添加持久求解状态。写后失效、IR、Frame、ABI及后端保持；跨次相关数组读取及完整回边／关系求解仍开放；新的普通返回字段间关系按下段交接。

普通正常返回沿原Returned／Proof共同命名数值分量、bool条件及write／inout写后内容。每个真实正常出口先将函数体内新身份代入共同输出分量，再合流路径；函数入口前已有SSA身份和输入快照不被改名，重复来源保留同值关系。canonical在既有输入编号后命名结果和写后内容，普通调用再代入实际返回寄存器与当前位置内容身份；无机器消费者的静态编号由原value_code清除，不生成额外装载。条件图重命名沿共享DAG处理，不变节点保留原Arc，避免复制未受影响的路径。IR、机器ABI、Frame、资源驻留／释放及原COFF4／BLRI1编码保持，没有第二份运行时关系状态；旧生产模块未导出的关系须由生产模块重新编译提供，不能在导入处猜测。跨次相关数组读取、一般回边不变式及完整关系求解仍开放。

never 函数结果是无正常返回的静态合同，沿原 TypeName、Flow 空后继和 ReturnContext 的真实退出边处理；物理调用不带普通返回载荷，原生／内联／C声明及归档模块接口消费同一合同。没有返回边的函数体保留无返回，不再制造普通返回或把空退出表当成必需值错误；never 调用结束当前路径，写后事实、输出初始化及正常参数归还只由真实继续边交付。编译器不按外部名称推断终止，不添加运行时终止检查、异常系统或完成状态，进程内执行框架仍由实际资源和消费者拥有。当前实现覆盖函数结果，通用 never 数据／泛型组合和完整错误语义继续待实现。

普通位置的复合赋值沿既有 Assign／Place／binary／write_place 交付：lexer先匹配连续的最长运算符，parser只形成同一种赋值语句，前端从原赋值token去掉末尾等号取得完整二元运算。左侧位置只求值一次，右侧真实继续后读取当前内容并写回，类型、权限、初始化、事实失效与提前退出由原所有者负责；不引入新的赋值IR、原子语义、运行时状态或解析失败后的源码改写。

整数 min／max／clamp 的类型与事实归前端原数值所有者：与普通二元运算共用字面量定型／宽度关系，沿既有有符号或无符号比较和 Select IR 交付精确整数结果。原 IntegerRanges 传递极值区间及确定来源；min 保留不增大的真实索引关系，max 交接双方共有的索引域，不把长度等同于合法下标。clamp 继续展开为 max 后 min，实参求值与提前退出由原调用求值负责。整数常量复用原常量机制，f32 保持原 Math IR 与后端；没有新增执行状态、后端运算类别或运行时校验。

CPU 游标位置的条件精化沿原 Place.index_range 交付，不建立第二份位置表。bounds 的既有条件／等价来源收缩位置上下界，flow 的原实际路径合流取并集，空路径不扩大其他路径；嵌套数组位置递归处理同一原位置。原 effects 投影按相同位置区间排除不重叠常量索引，并用本次实际写集撤回索引变量的入口常量假设。Argument::overlaps 对位置对直接消费原精确位置／分量重叠，不再先被整资源句柄同名截断；完整资源、拥有值及内部位置仍使用真实资源拥有关系。源码类型、ABI、原生代码生成及运行时不增加区间状态、检查或快照。

循环首次进入时若尚无外层资源，而正文会对它赋值，编译器保留这次真实首轮及其继续边；每个继续点沿所捕获环境生成普通后续循环，再经原 break 退出首轮。条件、迭代起止值、实际游标、continue／seek、局部清理和返回仍在各自执行位置。此实现会为不同首轮继续边生成相应后续代码，不承诺代码体积不变；没有原生拥有 flag、哨兵句柄、新 IR 或调用 ABI。零轮、break 与条件失败仍按真实出口合流，不能把可能没有初始化的路径写成已拥有。

真实资源释放仍属于同一 Frame、Dataset 和设备完成所有者，GPU 最后消费者未完成时不会提前释放物理存储。本项只交付普通值 dataset 的可变绑定与确定初始化范围；动态部分移动的拥有数组／动态容器与view图、其他资源种类、一般动态子域／数组初始化推导、一般异步借用、普通原生调用与完整语言内存模型继续开放。

### CPU write dataset 的初始化责任

整份 write 借用与原标量 write 共用输出形参作用域及 initialized／Position。ApplicationData 只携带该输出作用域，位置键区分全域字段与实际资源作用域内的具体元素／字段；没有另一份可变初始化权威。新 write 借用不继承调用前的旧内容，read／inout 仍要求实际初始化，返回在原函数出口检查完整输出。

编译器从既有长度来源、具体下标、每条继续边和真实循环出口交接覆盖事实；首轮资源初始化的继续代码沿同一 ForLoop 携带已完成前缀。零长度输出在其实际路径上按空域完成，分支、短路、选择及循环合流消费同一初始化集合。既无 write 输出又无待初始化内联数组的普通循环不保存本项额外继续快照。ordinal 消费已捕获游标的真实范围，绑定位置不升级为存储身份。

CPU program 的输出初始化从既有 Program／Stage 的实际 Map、扫描、排序、归约和计数写入及绑定长度导出；不新增运行时元数据、全容量证明记录或独立程序效果注册表。prefix／where／分段结果不自动成为完整容量初始化。数组动态位置只写入实际选中位置；既有输出借用的初始化归属沿基位置追查，不能继承被 write 合同撤回的旧字段，也不能把动态一次写入记成整个基对象已写完。

这些检查落实真实函数输出和资源访问契约；物理存储、Frame、原生程序执行、完成点与释放仍由原所有者负责。本项不改变 IR、ABI、后端或 blcompute，不增加初始化 flag、清零、payload 副本或运行时检查。一般循环归纳、依赖运行期端点的任意覆盖、动态前缀／尾部组合及其他资源初始化仍未完成，继续归 C-020.3／C-005。

### 动态内联数组的实际位置

动态选中位置由原逻辑分量及已捕获的下标身份描述，嵌套投影继续选取同一位置；initialized 仍是唯一可变初始化集合。构造写地址不读取基对象，写入只初始化实际选中的分量；移除旧的整数组初始化前置条件和忽略动态写入的分支。选中位置只在所有候选分量已初始化时继承整体可读性，改写下标不继承旧选中位置。

## 计算执行与内存

CPU 后端把范围函数提交给 Windows 线程池，按连续范围领取工作，不为每个元素创建任务或 Future。tile 阶段的范围按逻辑块对齐，局部按字段存储由原生范围函数持有并重复使用，不复制整个场景。已有标量及四元素 SSE2 生成与自研物理寄存器分配；直线 map、批次内统一的普通分支／循环与其作用域退出可保留四元素正文，逐元素分歧和 tile SIMD 尚未完成。

公共 IR 的局部值转发沿原结构化控制流交付已存在的 SSA 定义：正常继续、break、continue 与函数 Scope 的 Exit 分别合流，只有实际到达同一接收点且仍指向同一 SSA 值的槽才能转发。Scope 接收自己的正常／提前返回出口，保留未改写或共同交付的值；已退出分支不污染后续普通继续点。真正不同的分支值和循环携带写入仍使用原局部槽，循环先撤回可能写入槽的入口事实；不把某次迭代定义当作循环后的值。动态私有索引写与外部调用按原实际写范围失效，存储读取仍沿原控制／同步边界撤回，不推测未选路径的读取或副作用。无继续出口之后的指令不再交付事实；DCE 同时消费 Scope 外仍需要的域内 SSA 定义，避免把已转发的真实生产者删除。该处理不增加 Phi、运行时副本或另一份存储状态，也不声称完整 SSA 局部提升。

CPU 在原 texture 降低后的同一私有 Stage 中，将无副作用的 SSA 生产者交给首次真实消费，再由原活跃性、干涉图、Frame 与 SSE2 计划消费该次序。常量／索引、普通算术、除余、转换、选择及内联数学按原 SSA 依赖交付，每个运算的输入和依赖保持，不重关联或重复计算；多结果指令的多个输出仍只有同一指令所有者。依赖用显式工作栈处理，已消费的节点不再建立工作栈；没有额外运行时计算、寄存器分配器、缓存、调度服务或另一个持久 IR。

只读 dataset／view 装载在所有原写入与可写读取前完成，不以不同绑定名推断无别名。局部读取的窗口由真实逻辑槽及原索引跨度决定：写入重叠存储之前先交付此前快照，不相关局部写入不改变该存储。其 SSA 操作数已经持有值，纯计算可以越过普通存储写入到达实际消费，实际存储顺序保持；新次序交给原图重新计算寿命与位置。调用、控制／作用域退出、原子、tile／subgroup、未知指令及块结束关闭原区域，子块各自处理，不把读取或计算移入／移出分支和迭代。普通范围复用原入口，普通值入口在原图前接入；自定义集合的初始化、范围循环、尾段分别交付并按实际区间记录切点，不跨执行段。公共 IR、GPU 指令、数据布局与 ABI 保持；局部收益和退化均需实测，循环携带状态、完整 SSA 局部提升与整体效率继续开放。

寄存器分配由 x64 后端拥有，复用 IR 的循环固定点活跃性；SSA 值和可变局部槽共用干涉关系及溢出槽寿命。普通范围、普通值入口及自定义集合的非 tile 标量正文将实际未占用的 R10／R11 纳入原整数候选，在非易失 GPR 之前交付；tile 输入复制与阶段集合仍拥有 R10／R11，沿原候选分配。C ABI 的动态局部引用在设置参数寄存器前复用 RCX，所有原调用槽准备完成后才设置实参；返回后 RCX 保留完整聚合位，RAX 逐 word 交付及规范化，不破坏尚未读取的分量。跨调用值继续排除易失位置，值入口栈探测在正文产生值前使用易失临时。跨数学／C ABI 调用的值不占用易失位置，实际使用的非易失寄存器在范围入口／退出保存恢复，未调用外部函数的内核不生产调用区。tile 阶段从实际分配位置交接既有私有流，不维护第二份常驻栈镜像。此处不改变语言数据布局、执行 ABI、算术依赖或 GPU 代码。

固定 SSA 字面值属于编译期事实，不拥有可变物理存储。原 Allocation 遍历全部结构化定义，只有所有定义都是相同位模式的 Constant 时交付固定位置；其他定义、不同字面值及局部槽继续按原干涉图分配。整数／bool 的真实消费者选择 ALU／比较的 imm8／imm32、移位低五位、直接内存写入或所需寄存器物化，按 x64 编码保持完整 32 位模式；C ABI 原调用槽直接消费分配值，按值复制、参数／结果布局和 bool 规范化保持。

f32 固定值的浮点读取使用同一 NativeCode 内的只读字节：原 Emitter 按实际读取的位模式持有引用，代码收口在返回指令及原局部 helper 后附加四字节对齐的数据并修正 RIP 相对位移，同一代码内每种实际位模式只保留一份。没有数据读取的代码不附加数据或对齐。普通范围、普通值入口、自定义集合及其他原生入口统一交付完整机器码；普通值主函数结束／展开记录仍指向原指令范围，外部重定位保持原偏移。完整字节随原 RX 代码一起链接、复制、装载并在最后代码消费者结束后释放，常量没有独立运行时存储或生命周期。固定 f32 不占 XMM／溢出槽或跨调用保存，真实动态值仍按原 ABI 保存；位复制与直接写入保持有符号零、NaN 和次正规位模式，算术顺序及浮点运算语义保持。packet 仍使用原物理分配，tile 私有交接沿同一已知值及实际存储处理；公共 IR 与执行 ABI 保持。内存操作数与寄存器物化的实际成本仍需实测，比较反例及完整效率目标继续开放。

数值转换也由原位置发射：标量 f32 到整数直接读取 XMM／四字节源并写入实际 GPR，整数到 f32 直接写入实际 XMM；u32 的零扩展值按原 64 位有符号转换取得完整正数范围，栈源仍只读四字节后零扩展。规范 bool 的 0／1 可使用有符号整数转换。CVTSI2SS 前清零目标 XMM，切断其保留高96位对旧浮点结果的依赖，不改变有效低32位数值。四元素 i32／bool 到 f32、f32 到 i32 直接读取原分配位置，其余 unsigned 拆分及 bool 规范化在分配结果位置完成；原 u32 高低16位转换和 f32 到 u32 的 2^31 拆分顺序保持。跨调用、溢出、作用域、公共 IR／ABI、GPU 和资源所有者继续使用原规则，不增加运行期数值检查，也不扩大浮点到整数的有效输入域。

标量 f32 的取负／abs 直接消费原 Allocation 的真实结果位置。结果在 XMM 时，原四字节字池通过 MOVSS 向保留的 XMM0 交付符号掩码，再由 XORPS／ANDPS 在结果寄存器修改低32位；操作不执行浮点算术，不改变其余31位。掩码只读取一个字，不把128位内存操作数套在四字节字池上。固定来源直接交付变换后的字；真正共址的溢出位置以四字节整数位操作原位修改，其余溢出交付使用原字临时。高位不属于标量值，存储和ABI继续只交付原规定的字。掩码与其他实际字节共同由原 NativeCode／finish 持有、定位、链接、装载及最终释放，没有单独的资源、缓存或运行期状态。公共IR、算术顺序、活跃性／分配图、packet与GPU代码保持，代码字节增长与具体性能结果分别记录。

局部加载／存储与保持位模式的 Cast 在同一干涉图中交付复制关系：复制定义处不把当时相同的源／目标互相设为干涉，其他定义、重写、调用存活与 tile 私有值同时交接仍建立原关系。着色优先使用已分配且属于当前候选集合、没有真实干涉的复制源／目标寄存器；跨调用保留类别、可寻址私有存储和原溢出槽分配不变。SSA 身份与标量类型继续分别保留，u32／i32 的同位模式仍由各自消费者解释。标量和四元素发射共用位复制分类：同类型、32 位整数互转及规范 bool 转整数进入原 Copy，相同位置不发射搬运；数值到 bool、浮点与整数之间的转换保持原指令。不增加运行期别名、缓存或另一套局部状态。

一元、二元及内联 abs／min／max／sqrt 的结果在同一着色过程中优先采用输入的位置：普通算术采用首输入，比较采用既有 SSE2 降低实际使用的左侧输入，Select 优先采用假值。它们的结果可能改变值，因此这类偏好不撤销任何真实干涉，源仍存活时继续保持独立位置。候选寄存器类别、跨调用约束和溢出槽寿命沿用原分配；只有前述纯复制关系可以省略复制定义处的同值干涉。

x64 指令选择直接消费这些位置，不再要求每个算术值先复制到固定临时寄存器再复制回来。整数取负／按位非直接作用于结果寄存器；源与结果确实共用栈槽时可原位修改，其他溢出情形沿用临时寄存器。IR bool 已规范为 0／1，逻辑非直接 XOR 1；标量 sqrt 由 SQRTSS 直接读取分配位置，标量浮点取负继续使用原符号位路径。四元素取负／按位非／逻辑非／abs 与统一移位直接写入结果 XMM；整数取负先保存减数，移位先取得并按原规则掩码计数，防止覆盖与结果重叠的输入。两地址写入保留未读右值及浮点操作数顺序；位复制、存储、比较、值选择和寄存器保存共用必要的寄存器／内存编码。硬件规定的除法、移位、调用与栈到栈复制继续使用临时寄存器。位置分配与指令编码分别由后端分析和生成，不改变 IR、数据与执行 ABI、执行器资源所有权、调度状态或设备要求。

标量比较保留原条件码与浮点无序规则，在 AL 中形成条件位后直接零扩展到结果 GPR；溢出结果沿原临时寄存器写回，不先在 EAX 扩展再额外搬运。标量 Select 直接测试原 bool 位置；整数／bool 结果在已分配 GPR 执行 CMOV，浮点／溢出结果沿原 GPR 临时位置交付。目标已有真值时改用 CMOVZ，避免先写入假值覆盖真值；浮点选择仍按原始位交付。SSE2 比较按既有条件选择输入，不先复制并交换整组寄存器；右值可直接来自实际寄存器／栈位置，结果与未读右值重叠时保留临时计算，无符号顺序仍先保存右值再作原符号偏置。四元素 Select 在结果 XMM 建立选择掩码，覆盖前先保存假值和必要的重叠真值，以整数按位运算交付原字节；bool 仍为 0／1，浮点 NaN／零符号、比较次序、非易失保存及范围／尾部规则保持。

x64 的编译期步长缩放由原 Emitter 统一生成：地址索引先按既有 u32 读取零扩展，再在 64 位寄存器中计算字节偏移；二的幂步长用 SHL，单位步长不发射乘法，其他步长沿原 IMUL。需要具体指针的 R15 基址与 RAX 索引消费者，对硬件可直接表达的 1／2／4／8 比例使用单次 LEA；其他比例仍形成同一实际地址。普通／稀疏标量与 SSE2、只读 dataset／view、固定数组、tile、外部位置、原子、append 及集合的起始地址共用这一降低，不重排字段或复制布局。数组字偏移、完整记录复制、严格范围与尾部、原子接纳顺序和既有 ABI 保持；这只是编译期指令选择，不增加运行时范围分支、调度、状态或硬件能力要求，也不把局部代码缩短作为通用性能已达标。

单次实际读写由同一 Memory 操作数携带基址、可选索引／硬件比例和位移，Operand 只区分寄存器与这份内存事实；REX／SIB／位移由原 instruction 编码，不先把每次读写的最终地址放进 R15。已知步长按硬件比例因子分解，剩余乘法／移位在原 64 位索引临时位置完成，比例直接进入实际读写指令；无需改写索引值时直接消费原已分配 GPR，包含高位寄存器的 REX.X 编码，避免先搬入 RAX。标量 dataset／view、私有与全局数组的最后一级、四元素连续 32 位访存、稀疏单 lane 和只读间接读取共用该路径。普通稠密 AoS 四 lane 仍复用一次物化地址；C ABI、原子和其他实际指针消费者保留原地址生产者，不引入地址缓存。溢出值搬运及 bool 规范化从原保留临时 GPR 中选取未参与该内存地址的寄存器，避免消费值时破坏仍要使用的索引。所有选择发生在编译期；源位置、布局、别名、访问范围、Frame／ABI 与资源所有权保持。

四元素计划沿原结构化 If／Loop／Scope 递归生成；统一条件只取同一批次的一个真实 lane 决定共享跳转，正文仍在原 XMM／溢出位置处理四个独立值。SSA 定义的一致性来自其实际程序点，局部赋值强更新该点的当前事实；条件分支按真实继续边合流，后续逐元素赋值不追溯污染先前读取。循环入口只与真正回入本循环的普通／continue 边求固定点，break 交给本循环出口，作用域退出交给所属 Scope 合流；退出边的逐元素值不能用于回边推断，也不能在退出后的控制判断中丢失。试探迭代不交付定义事实，固定点稳定后才记录；原索引和可写数据读取仍是逐元素来源。只有全部控制条件在批次内一致的结构化区域进入该计划，嵌套循环和作用域复用原跳转栈及循环活跃性，未选分支不执行，算术次序及终止行为保持。该编译期事实不形成运行时一致性检测、分歧掩码、另一份 IR 或资源状态；逐元素分歧、tile／协作及其他不能表达的实际指令保留原后端路径。

四元素机器计划只改变已检查 IR 的执行粒度；写入始终使用当前独占元素，读取来自当前元素及只读数据集／view。整组和标量尾部共用一次范围入口、Frame 与非易失寄存器保存，临时区域按最大需求复用；前端数据类型、AoS 资产／传输布局、域关系及 Windows 范围调度均保持。纯寻址索引直接由范围游标提供，没有值消费者的索引向量从生产端删除；其余索引产生四个真实元素值。CPU 批次不是源语言 tile，也不改变 GPU 的参与集合和后端。

普通连续域中，stride=4 的四个真实 32 位记录使用一次非对齐 128 位读取／写入，替代逐项 MOVD 与拼装／拆分；读取仍交给同一 bool 规范化及分配位置，写入只覆盖该四元素范围。MOVUPS 不要求数据基址按 16 字节对齐。范围入口先确认完整四元素，余下记录沿原标量尾部；统一广播仍只读取一个真实值，where 选中索引、非连续 AoS 与间接读取继续按实际位置访问。该选择发生在原 CPU 机器计划内，不增加运行时分派、资源分配、别名规则或布局转换。

逐元素变化的 u32／i32 移位量也保留在同一四元素计划中。SSE2 没有逐 lane 可变整数移位指令，后端按各 lane 的真实值与移位量使用已有 x64 SHL／SHR／SAR，再合回原批次供后续 SIMD 运算；统一移位量仍使用原 packed 移位。全部源 lane 读取完才写回分配位置，允许真实寄存器复用与溢出槽；硬件按原 32 位移位语义使用低五位，不新增运行时校验、缓存或分配，其所在控制流是否可批量表达由同一统一性分析决定，tile 仍按原语义执行。

只读数据集间接索引及 view 读取现接入同一机器计划，写入仍只针对当前独占元素。CPU 逐 lane 组合实际 64 位地址并读取分量，再交给原有四元素 SSE2 运算；嵌套来源可各不相同；数据集与统一 view 的基址在同一次读取操作开始时只构造一次，直接保留在原 R15，后续 lane 提取、64 位索引缩放和读取都消费该基址且不改写它，不再逐 lane 重装或经 RDX 中转。真正逐 lane 变化的 view 仍分别构造各自实际基址，读取完四个源值后才写回目标；没有跨读取操作的地址缓存或另存一份基址状态。数据格式、共享子所有者、资源传输和实际完成点不变，没有另一套几何预处理或运行期访问检查。寄存器与栈输入均在所有 lane 读取完成后才写回目标分配位置。可表达的直线及统一控制流函数可以批量执行，逐元素分歧和 tile 等原有语义保持。

GPU 数据为独立设备内存。上传、读回和零初始化都是明确操作；多个时间步可以在一次提交中执行，中间数据留在 GPU。执行结束返回数据所有权，调用者决定何时读回。CPU 内存和 GPU 显存不假装是同一物理存储。

同步读回由本次调用持有最终主机 Vec 与一个物理页大小的 staging，逐页完成实际设备复制后，把映射内容直接追加到最终存储；整次调用结束释放 staging，不创建逐页主机副本或跨调用缓存。原分配器依据 buffer 的实际兼容内存类型、必需属性及用途选择单一类型：供宿主读取的 host-visible TRANSFER_DST 在既有 coherent 类型中按 HOST_CACHED 属性选择，上传与设备分配沿原顺序。原队列依赖、transfer→host 屏障与 Fence 完成继续负责可见性和真实资源寿命，view 图的主机地址仍由下载后的实际所有者重建。缓存属性依据 [Vulkan 内存属性规范](https://docs.vulkan.org/refpages/latest/refpages/source/VkMemoryPropertyFlagBits.html)；具体内存类型、吞吐与分配收益按实际驱动和消费者记录。

设备能力由真实消费者提出。`Device::new` 提供通用计算，`Device::for_program` 按程序声明启用加速结构／光线查询，两者均不启用窗口或交换链扩展。需要呈现的消费者使用 `Device::with_presentation`；交换链自己加载并持有呈现入口，计算设备不持有这组入口。无窗口几何渲染也使用普通计算设备，不先创建窗口。它们仍使用同一套 Vulkan 数据、编译与提交实现。Device::swapchain 接收实际宽高，Swapchain 持有真实 extent，按 dataset 的物理页逐段复制完整 BGRA8 输出；页尾和页首不足一行时仍按图像实际偏移交付，不复制页表，也不依赖某个引擎产品的固定分辨率。

Win32交换链创建与present读取实际窗口的DPI上下文，在该线程作用域执行WSI后归还原上下文，不改变进程全局DPI。窗口仍由调用者持有到Swapchain析构之后，独立GPU线程沿相同平台入口使用。Swapchain::present返回PresentStatus::Optimal／Suboptimal；两者均成功取得并提交图像，Suboptimal保留WSI原生状态，其余结果继续报告。依据为[微软线程DPI接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddpiawarenesscontext)和[Vulkan获取图像](https://docs.vulkan.org/refpages/latest/refpages/source/vkAcquireNextImageKHR.html)／[呈现规范](https://docs.vulkan.org/refpages/latest/refpages/source/vkQueuePresentKHR.html)；不以缩小输出或重试处理表面变化。动态extent／OutOfDate仍由后续实际窗口生命周期工作补齐。

try_present以零超时获取和原完成点观察返回Pending／Ready；Swapchain持有当前acquire信号量的真实消费执行，呈现等待信号量仍归实际图像。源显示存储的最后使用点交给原ExecutionResources::Transfer，后续写入／退出沿同队列依赖处理，不增加显示镜像或呈现调度服务。Ready是已排队，不是拷贝或扫描输出完成；原同步present仍显式等待同一执行。实际接口及WSI寿命见[原生提交](DeviceSubmission.md#交换链呈现与原显示存储2026-10-27)。

Device::same_device仅比较原逻辑设备／队列所有者的身份。Device克隆共享该所有者；同一物理GPU重新创建的Device仍不同。真实消费者在交接跨模块资源前可据此处理平台归属，不复制设备ID、按名称猜测或增加运行时审核链。引擎多输出的场景／图像职责仍属于BLEngine，通用执行框架不持有场景或视图状态。

每个阶段的读写集合用于生成 RAW、WAW、WAR 所需依赖。当前使用同一计算／呈现队列；全局内存屏障覆盖全部待完成生产者，再清理同步记录。执行上下文持有命令、描述符、临时存储、编译程序及原生完成点；每份唯一数据持有自己的最后使用上下文。资源只随最后一个真实消费者结束而释放，分支不再复制或重建存储所属表。

Blink 的不可变 `view<T>` 由 CPU／compute／GPU 共用，普通索引沿用同一引用范围与类型证明。CPU 冻结数据以 Arc 保持真实子资源，根记录通过 `with_views` 编码连续主机缓冲地址；GPU 仍绑定其物理页表与设备引用。两端字段与类型绑定共用实现，原生 x64／SPIR-V 直接消费 ViewLoad，资源函数按实际目标静态内联。源程序不提取地址，不开放写 view。`surface_normal` 的真实几何插值是可共用的 compute 函数，硬件查询仍限于 GPU program／值函数。普通函数的调用分析将 read acceleration 与其他真实资源一样交给既有借用处理；只接收加速结构和普通值的辅助函数不需要附带一个无消费者的 dataset 来获得资源身份。

原始可写 payload 不等于已绑定资源图。Dataset 取得 words_mut 时放弃已有主机视图子引用及字段绑定，执行前必须显式绑定真实来源；裸地址字节不能成为 CPU 所有权。该检查属于现有资源 ABI／生命周期边界，不增加元素索引运行检查、后台修复或从地址重建引用。

父数据的实际来源与逐记录字段槽构成闭合不可变资源图。显式 upload／download 递归复制图并从目标实际所有者生成平台地址，不要求消费者逐层重新绑定；GPU 编码直接使用既有逐页暂存映射。一次操作内按真实所有者身份保留共享，批量域传输在各根间共用局部映射，内容相同的独立来源不合并。读回的根直接持有真实主机子资源；GPU 生产的子资源仍按原提交与 Fence 生命周期保持。映射随调用结束释放，不建立全局资源注册表、迁移缓存或新的执行循环。CPU、GPU 物理存储与显式传输保持分别所有，不做隐式迁移、设备选择或统一地址空间；同设备缓冲区上传、清零与纹理上传已按真实完成点异步交接；普通数据与纹理读回均等待真实结果；纹理可经显式 CPU 快照交给另一逻辑设备，直接跨 VkDevice 设备传输、多物理 GPU 选择／验证与多队列尚未实现。

`DomainBindings` 将有效域关系附着于实际存储所有权，CPU／GPU 显式传输时一起移动。宿主取出存储就放弃原关系。多个结果可 join；CPU 结果、GPU Completed 及尚未等待的 Submission 均可 partition。CPU／GPU 绑定均可用 freeze 显式冻结选中存储，随后多个分支共享同一 Count 的只读绑定；数据没有对应真实 Count 绑定时不交付关系，同一冻结所有者的别名可继续承接原关系，不从数值或内容重建能力。同一可写数据和 Count 仍只移动一次。DomainStorage 由存储所有者直接交付只读身份和绑定，CPU 借用入口继续接受 Dataset，拥有型入口接受 CpuDataset，GPU 入口接受 GpuDataset；不另加存储类型封闭列表，不建立计数镜像、别名注册表或第二份存储状态。

CPU 的拥有型执行统一使用 CpuDataset 的 Owned／Read 两种真实所有权，裸 Dataset 和 ReadDataset 分别移动为独占与只读绑定；读取均消费同一原生 buffer ABI 和阶段执行主体。Frame 保留该绑定，原 C ABI 和借用型入口保持；宿主原始可写访问与 write／inout／atomic 仍只属于独占存储。CPU／GPU 的显式域传输在原闭合资源图映射中同时处理根与子资源，保持共享和只读访问；同一实际冻结来源在一次操作内只复制一次，相同内容的独立来源不合并。映射随传输结束释放，不建跨操作缓存或统一地址空间。

`submit_join` 消费多个同队列未等待提交，`submit_after` 使用同一实现；`Submission::into_bindings/partition` 可直接转移 pending 数据，普通 submit 也从实际绑定及其不可变 view 收集生产依赖。在设备建立执行与内存依赖，Count 留在 GPU。接口数据次序可以重排，执行依赖按该队列成功提交的实际次序归并，完成事实仍取自原生 Fence。追加绑定也可以携带已上传、已完成或 pending 结果的真实域关系。

分支共享执行上下文，各自拥有独立物理数据。丢弃或绑定失败的分支把尚在使用的存储交回最后使用点，不迫使存活的兄弟分支等待。继续提交前回收已完成依赖；显式完成观察和末项等待同样释放已完成命令、临时页、待释放存储与 Fence。延后消费的分支保留自己的数据，生产者命令资源可先释放。查询池则按 GPU 命令和实际时间戳读取者共同持有，完成观察后仍可正确读取计时。最后一个执行所有者退出时结束仍未完成的消费者；没有定时回收线程。GPU 共享只读 Count 沿同一冻结存储及实际最后使用点保持，不增加计数读回或 GPU 数据页；CPU 只读绑定沿原 Arc 持有实际存储和子资源，同步原生执行结束后归还绑定；自动背压、多队列和设备自主任务仍未实现，分支在单队列上不保证硬件同时执行。

`GpuTimings.elapsed_ms`／`GPU_program_ms` 使用一次提交中首个程序时间戳至最后一个程序时间戳的跨度，包含程序阶段之间的依赖间隔；`stage_ms` 单列各阶段时间戳区间。该计时不包含此前的资产读取、上传、加速结构构建、之后的读回或交换链呈现。完整呈现 FPS 和首帧时间使用墙钟，不能用 GPU 程序时间替代。首帧起点已移到原生 view 入口、设备和编辑核心初始化之前；此前计数从渲染器初始化之后开始，不能称为完整宿主启动耗时。

归约、扫描和 compact 的谓词扫描使用 64 个线程的 workgroup 共享存储。扫描组和递归处理并逆序传播前缀，全程驻留设备，阶段和临时资源由同一执行框架拥有。部分和在设备上递归归约，空输入的 sum 单位元为 0。CPU 范围部分和与 GPU 树形部分和采用不同分组，不承诺 f32 位级相同。

CPU compact 的稳定 scatter 只为入选记录推进输出游标，源游标始终按原记录步长推进；目标起点仍由原计数阶段生产的范围前缀提供。入选记录的完整 16 字节部分使用 MOVUPS，8／4 字节尾部使用精确 MOVSQ／MOVSD，不宽读下一记录；XMM0 是既有 Windows x64 范围 ABI 的易失寄存器，原 RBX／RSI／RDI／R12 保存保持。复制保留 bool、浮点载荷及填充的原始字节，不改变计数、前缀、容量关系或 CPU／GPU 资源所有者。

浮点连续／分段 min/max 扫描同样使用原 Scan、范围摘要、共享树与前缀传播，单位元为正／负无穷。合并沿既有严格比较与右值选择，不过滤 NaN；没有实际右元素的填充子树和空局部前缀不参与真实值合并。CPU／GPU 分组不同且含 NaN 的极值不具一般结合律，不承诺任意输入逐位相同；字段布局、有效域与实际完成所有者保持。

自定义归约与独占扫描的单位元、合并器及投影使用 Blink 普通值函数；`bind(静态函数,统一普通值…)` 可追加本次执行的坐标系、筛选规则等参数，四类集合及各自投影形式共用同一实现。统一参数直接进入既有值 IR，不复制进每条输入记录。这些值函数静态编进 x64 范围／摘要函数与有序 SPIR-V 共享树；源类型与结果类型可不同，投影不物化逐元素中间数据集。普通记录按字段类型构造，逻辑分量和 ABI 填充分开。CPU 跨迭代累积值由既有分配器持有；扫描的范围摘要前缀和结果传播也由原生函数执行。自定义分段扫描只在摘要中附加段头 word，右摘要开始新段时直接保留其尾值；CPU 传播到首个段头结束，GPU 最终传播只覆盖组内首个段头之前的结果。GPU 左右顺序固定而结合括号可变，扫描复用现有递归层级，递归摘要不重新投影；函数不得隐藏资源副作用。扫描输出沿用输入 Count 的有效域关系。类型／访问由编译器检查，结合律、双侧单位元和浮点稳定性由算法定义。仍复用现有调度及资源寿命。集合内核的无条件纯统一表达式在共用 IR 中前置并消除重复；CPU 每个范围一次，GPU 每次 invocation 一次。三个函数体分别继承入口，摘要／传播只生成真实需要的函数角色；不从未执行的角色借用局部结果。CPU 使用既有结构化活跃性保留跨迭代值，GPU 合并只刷新元素 SSA，入口值持续支配各个节点。用户分支、循环和动态除法证明作用域保持，不引入宿主预计算缓存或额外设备提交。

内置数值与自定义普通值／投影分段归约都将每段结果与实际段数共同生产为后续有效域。CPU／GPU 两次遍历源，只保存范围／工作组的 `(K 个尾值, 段头标记, 段数)` 摘要，再直接由真实段尾写唯一结果；不物化逐输入扫描值或段号数组。GPU 的递归只处理摘要，计数留在设备并沿既有 requires／ensures 与资源所有权交付消费者；内置数值的显式共享载荷为 768–1536 字节，自定义普通值按 K+2 分量派生共享容量，纯值合并与摘要前缀同样编进原生代码。它是封闭集合操作的写入权，不把数值段号开放为任意散写。具体类型、容量及浮点语义见语言规范。CPU 原生范围 ABI 的第二参数始终拥有程序统一值；分区前缀和排序私有元数据改由范围回调自己的指针表末项交付，消除两者对同一参数槽的重用。自定义后续阶段通过已有只读 Load 消费范围数据，用户合并器在所有遍历仍读取原统一参数。

逻辑数据集按完整记录分页，每个物理页最多 256 MiB。描述符绑定只读的 64 位设备地址页表，自研 SPIR-V 通过 buffer device address 访问数据页；计算和渲染使用同一实现。页边界不拆开记录，记录索引仍为 u32。一次缓冲区上传将各页复制录入同一提交，清零填充各页，读回仍逐页等待；归约临时数据也使用分页布局。提交同时持有页表与物理页。分配指标现在记录 VkMemoryAllocateInfo 的 allocationSize；请求缓冲区容量、Vulkan 分配量和驱动显存统计分别报告。

每个实际资产拥有自己的分页数据，引用通过 Blink 类型化不可变 view 连接。删除全局着色追加池及其扩容复制；每块上传暂存最大为一页，同一操作的全部暂存随该上传实际完成后释放；异步提交不再意味着整次操作只持有一页。当前目标设备要求 Vulkan 1.2、bufferDeviceAddress、shaderInt64，渲染程序另外要求 accelerationStructure／rayQuery，缺少能力明确报错。该实现依据 [Khronos Vulkan 功能定义](https://github.khronos.org/Vulkan-Site/spec/latest/chapters/features.html)。

分页移除了整个逻辑数据集必须放进单个 storage buffer 的限制；没有取消真实显存容量、单次分配限制或数据生命周期。资产资源已按实际引用生命周期回收；同设备纹理上传已按实际完成点交接；完整磁盘流送、多 GPU、其他纹理传输和设备生成新任务尚未完成，不能称为已具备超大世界能力。

共享修改由接口的 atomic dataset 能力表达，与普通元素独占读写分开。u32/i32 原子及静态内存序进入封闭 Atomic IR，CPU 自研 x64 与 GPU SPIR-V 均直接降低到实际地址；GPU 为 Device 作用域，未建立 CPU／GPU 跨设备共享原子内存。忽略返回值仍保留内存效果，不把原子值作为普通加载缓存或越过未选分支。原 cross_reads 统一成 cross_access，阶段融合同时考虑跨元素读与写；元数据仍只有原读／写／跨元素集合，没有另建调度或同步状态。同一资源的原子别名允许共享，混合普通可写别名仍拒绝。已有 CPU 范围和 GPU 间接参数捕获当前前缀有效数量；既有 written 规则在 Count 改写后撤销后续域关系；本次范围由原启动快照保持。

编译期索引能力沿实际值来源传递。u32 比较与既有范围／bool 命题共同精化，已证明无下溢的常量减法、除数已证明非零的常量／动态 u32 除余、右移及按位 AND 可保留原索引域；长度本身不可直接索引，可由安全正减法或除数已证明非零的取余关系取得索引能力。局部赋值与控制流仍由同一前端所有者更新知识，没有运行时索引句柄或额外检查；CPU／GPU 后端继续消费原有算术和加载 IR。资源边界与唯一写权限不因数值推导而放宽。动态除数是同一 IntegerDivide 的 SSA 操作数，优化、活跃性和 tile 私有状态共同消费；条件内非零事实不允许把动态除余提升到分支外。CPU 标量使用原生无符号 DIV，四元素批次逐 lane 除余后合并；GPU 使用 UDiv／UMod，常量倒数路径保持。

原寄存器 ranges 表、单独标量下界及 Value／Local 整值 domains 均并入现有 Proof 的逐分量事实，数值区间、资源域与实际值来源一起传递。字面量、固定形状、算术、条件、构造、字段投影及内联参数／返回值只交接这一份编译期事实。读取用既有资源域，或证明下标全部可达整数片段的上界均严格小于当前保证的最小长度；dataset、tile、view 共用同一入口。u32 取余的除数已证明非零时，结果严格小于除数，可取得除数实际长度对应的资源域。u32 保守端点使用宿主 i128 容纳完整乘积及负的减法结果；u32／i32 共用同一模 32 位投影，分别采用零／符号位偏置。Proof 每个整数分量保存按数值排序、不重叠且不相邻的闭区间集合；空集合承接矛盾路径。跨断点但不足完整周期的算术结果保留两侧片段，覆盖整个周期时使用完整整数域；每对输入片段计算后按并集规范化，不设置片段数量阈值。分支／选择合流取可能值的并集，投影、拼接、局部赋值和返回沿原 Proof 交付集合；条件上下界与非零事实在同一集合内收缩或剔除零值。仍使用单独最小／最大值的条件消费者取得集合的保守包围端点；索引入口直接消费全部片段，空集合按包含关系成立，不再把其包围端点0误当成真实可达下标。不将内部空洞虚构为资源权限。这是编译期表示，不增加 B 整数类型或运行时状态；赋值及控制流继续按实际值身份更新。向量分量可以属于不同 dataset／tile／view；局部字段赋值只替换实际改写分量的事实，选择按分量保留两侧共有域。打包的长度分量也参与当前保证的最小长度推导。固定 tile 宽度不会抹去尾块长度，引用的长度事实不会成为另一资源的权限。数据 ABI、IR、设备代码与资源生命周期不增加范围状态或自动修正路径。

固定数组 index 输入契约由原 Proof::mark_domain 交付形状事实：每个选中的 u32 分量既保留 Fixed(N) 索引域，又把已有非连续数值区间与 [0,N) 相交，保留更窄片段与矛盾空路径。条件传播的固定索引事实也消费同一入口，不在算术、循环、调用点或后端增加特例。后续既有区间运算可推导非扩张下标、无回绕加减、已知非零距离及较大固定形状的读取；向量逐分量处理，重写仍按原生命周期失效。动态 dataset／view／tile 的实际长度与身份不由固定形状推测，数值有界不授予独占写入。IR、ABI、设备代码与运行时不保存新的范围状态。

u32／i32 显式互转保留原 32 位模式，Proof 的数值顺序随零偏置／符号位偏置切换。每个输入片段共用原周期投影翻转有序符号位，跨符号边界时保留两侧，非连续集合沿原逐分量交接。原位模式的索引域随互转保留，数据集／view／tile／数组／应用索引仍先要求 u32；中间 i32 不直接获得索引入口，恢复 u32 后才可消费原资源域。数值来源身份不跨类型复制，原类型的有序上下界不会通过相等关系套到另一类型；位模式相同也不授予并行当前元素的写权限。后续算术、取负及局部重写按既有生产／失效规则处理域，整数取负从自身结果区间取得非零事实，不复用位转换。浮点数值转换、IR、数据 ABI、运行期与资源身份保持原职责。

u32／i32 的 AND／OR／XOR 对每对实际输入片段求可达结果的最小／最大端点，再沿原 Proof 合并结果集合。编译期从高位向低位枚举输入位，状态只表示各输入前缀与自身上下界的关系；同一状态具有相同的后缀选择，因此只保留输出前缀的极值。i32 沿用符号位偏置的有序端点，计算每个位时还原真实整数位，再将结果按原顺序编码。每对片段内仍使用保守包围区间，不逐个保存按位运算产生的内部空洞；结果集合供既有非零及索引检查消费，不记录运行期状态或跨值相关性，不改变资源身份和写权限。

移位范围先消费移位量的有效低五位。每个有序输入片段按模 32 映射为有效计数集合，完整周期覆盖 0 至 31，跨周期片段保留两侧；i32 的有序符号位偏置不改变这五位，交给数值算术叶函数时再使用目标类型的有序编码。左右移统一消费这些计数，原常量掩码特例与动态未知计数撤回分支随之删除，运行期仍使用原移位指令。u32 右移结果不大于原值，沿原非扩张关系保留资源索引域；源值已证非零且有效计数排除零时，才按严格小于关系把真实长度交付为索引域。原始计数非零不代替掩码后非零，空长度不建立此严格关系；i32 算术右移不套用 u32 位模式的非扩张关系。资源身份、原独占写权限、IR 与 ABI 保持。

u32 除法的索引关系同时区分非扩张与严格收缩：分子非零且除数的当前数值下界大于一时，商严格小于分子，由原 indices_below 的严格入口把真实长度域交为该资源索引域；其余已合法的无符号除法只保留非扩张关系。标量、向量与广播按实际分量判断，长度来源和非零事实仍来自原 Proof，动态 dataset、view、tile 与应用句柄共用原域枚举。零分子或仍可能为一的除数不建立严格关系，有符号除法不套用此 u32 关系；原除数非零检查、IR、ABI、资源身份与独占写规则保持。

同一实际分子／除数的商余复用归既有值转发所有：在当前直线块把单结果 IntegerDivide 合成双结果，不另加优化管线、运行时缓存或调度状态。死代码消除按消费者保留商、余数或两者，现有活跃性与位置分配共同消费多结果。CPU 从一次动态 DIV 取两个结果，常量路径复用精确商；GPU 分别发出两个标准运算。配对不跨控制／tile 协作边界，不扩张非零证明范围。

动态 u32／i32 标量和向量除数由同一前端的逐分量非零事实支持，和值来源、bool 命题及局部赋值失效共用所有者。构造拼接／广播、swizzle、32 位整数取负、位转换及 OR 按实际分量传递事实；直线局部子字段改写更新被替换分量的来源与事实，分支／循环沿现有整体变量失效规则重新证明当前值。前端向既有 IntegerDivide 交付各实际分量的寄存器，不新增向量运算 IR 或运行期元数据。CPU 的 u32 使用 DIV，i32 内部符号扩展后用 IDIV64 取得低 32 位商余；GPU 的 i32 用 u32 幅值除余及模 32 位符号恢复，覆盖 MIN32／−1。现有商余配对、批次统一性、控制流与 tile 私有状态共同消费同一个 IntegerDivide，不增加运行期检查、溢出分支或新语言整数类型。

## 有效工作域

`parallel (item in prefix(data, count.value))` 由前端的函数类型作用域证明数据与计数的有效关系；资源布局、阶段依赖、CPU 范围和 GPU 间接启动仍由既有编译／执行框架负责。GPU 在同一提交内读取计数、产生执行参数并消费有效前缀，CPU 不根据中间计数重建任务列表。多维启动使用 u64 线性索引形成有效性判断，再暴露 u32 源索引；没有把源语言全部整数改成 64 位。

`.h/.b` 的 `requires prefix(data, count.field)` 声明输入关系，`ensures` 声明并证明交付关系。每个模块只在自己的输入条件下检查；调用方提供所需关系，按被调用者声明的写权限使旧计数关系失效，并只接收接口交付的关系。私有 compact 实现不会隐式泄漏能力，read 计数保留关系，计数改写使关系失效。前端类型环境替代原先对全局展开阶段的反向查找，不增加运行期权威计数、审核或提交链。

跨模块调用仍可组成同一原生入口和 GPU 提交，阶段可按既有条件融合。模板可独立检查、导出，也可经拥有域关系的 CPU 绑定或前序 GPU 提交执行；动态宿主绑定只检查真实数据归属与已持有关系，不扫描内容猜测 Count。有效域 sum／scan／compact／分段归约沿用同一类型证明、阶段依赖和资源生命周期，扫描传递原有效长度，筛选及分段归约交付各自的新有效长度。重排绑定同时重排关系，声明可写计数就使旧关系失效；不通过独立裸 Count 假定数据域有效。通用设备动态任务仍未完成。


集合阶段的 GPU 执行参数与扫描中间量是不同消费者所需的数据，各占必要的内部绑定；不再把前缀 map 参数槽当成所有集合临时存储。一次参数生成形成 u32 域所需的各层计数与间接参数，扫描／归约各层只启动实际工作组，矩形补齐的整组统一退出，空结果仍能写出正确单位元与计数。层级命令和临时存储按容量预留，尚未实现 GPU 自主生成新的命令图。

`where(domain,flags.keep)` 以原数据集位置为元素身份，选择有效工作而不复制完整记录；domain 可以是普通数据集或已有关系的 prefix。read bool 字段或当前 inout 域自身的 bool 字段决定执行，谓词进入 IR 读集合和跨元素依赖，不能在优化后丢失这次资源读取。每个实例仍只写自己的原位置，其他只读数据通过同一 index 读取；数字 path／rank 不获得任意目标写权限，之前显式 compact 的排列也不会自动反解。

CPU 生成带条件的原生范围函数；可由现有 SSE2 计划表达的直线正文，每次收集四个选中原索引后批量计算，余下至多三个选中元素使用同一函数的标量正文。四个索引只占原 Frame 内 16 字节，不生产全域索引数组；读取、写入及源语言 index 都消费这些原位置，未选中元素不执行正文。GPU 复用既有扫描生产私有 u32 原索引，间接执行时映射回源位置。源域的层级参数与所选正文参数分开；临时数据沿原提交与完成所有者持有，没有另立公开 Count、宿主队列、逆映射或调度器。这个域让相同源位置的路径与像素可以独占汇合，通用执行层不绑定渲染。稀疏 tile 邻接／发布、复杂控制流 SIMD 和完整设备自主任务仍待开发。

同一串行提交中，同容量where阶段在前一消费者完成后复用扫描、原索引及间接参数工作存储；实际存储槽位由原Execution持有，阶段只引用其物理槽位。复用通过原prefix.prepare覆盖Compute／Indirect读写到下一写者的依赖，容量不同则使用各自需要的存储。它不在跨设备或并发提交间共享可写工作区，也不复用用户的数据集或改变源索引。

## 稳定排序与协作后端

排序是封闭的集合操作，前端负责 u32／i32／f32 标量／向量与多个字段的字典序键、读写权限、记录类型、容量和有效域关系，后端负责稳定序号与实际并行执行。键参数按优先级排列，向量按分量展开，同一排序的所有键来自同一 read 输入和有效域；`descending(field)` 为该键及其向量分量选择降序，未标注的键升序。IR 只持有源 word、数值种类与封闭 SortOrder，不增加另一套键数据。后端从最低优先级开始，每个分量装入时一次映射为无符号全序，降序取反该编码，f32 按编码区分正负零及 NaN，原字段不改写；下一分量按已有原始序号读取源记录并覆盖同一键槽。中间始终只重排 8 字节键／原始序号，相等完整键保持输入顺序，完整记录只在最终 gather 移动一次；临时数据属于当前执行／提交，编译 pipeline 属于编译程序。CPU 范围内核直接生成 x64，GPU 的 16 桶直方图扫描及各位分配管线在不同键之间复用，不增加第二个排序或扫描运行时。

CPU 最终 gather 按记录的真实步长复制原始字节：完整 16 字节部分使用非对齐 MOVUPS 块复制，余下 8／4 字节分别使用单个 MOVSQ／MOVSD；零个或一个完整块直接由静态步长选择，多个完整块由同一原生函数内循环消费，不新增运行时入口或分配。没有读取下一条记录来拼接当前尾部，也不对 bool、NaN 或布局填充做值转换。原始序号仍来自同一键表，源／目标指针、范围 ABI、私有临时表与执行所有权保持，排序键与稳定性不受复制粒度影响。

GPU 稳定性使用明确的 full subgroup 与合成逻辑输入序号，不依赖 LocalInvocationIndex 与 lane 的偶然映射。排序能力随程序请求启用，普通设备不拥有未声明的排序能力；计算、呈现和硬件求交仍使用同一 Vulkan 实现。排序内部的共享存储及屏障由后端拥有；语言现已开放 subgroup 值协作、类型化 tile 输入快照和不可变中间值发布，可变共享存储、用户手写屏障和通用原子仍未开放。

GPU compact scatter 与排序最终 gather 共用原始记录复制：每条入选记录复用源／目标起点，各自只查一次页表，再按 128 位原始 u32 向量块、64 位和 32 位精确尾部复制完整记录。物理指针的 Memory Operands 使用 Aligned 4，包含字节填充和非规范 bool／浮点编码；没有浮点运算或 bool 规范化。数据页仍以完整记录切分，块复制不跨出该记录，不重算每个 word 的页号、余数与页表读取。GPU 调度、键／序号暂存、稳定顺序、输出范围和完成所有者保持。

## 块内原子协作

`tile_atomic` 复用已有发布步骤初始化本块的共享值，`tile_barrier` 复用同一根块阶段切分。Atomic IR 只把地址目标区分为 Dataset／Tile；原子算子、旧值、内存序、索引与寄存器分析共用。GPU 按实际目标使用 Device／UniformMemory 或 Workgroup／WorkgroupMemory；CPU 的 dataset 保持真实跨线程原子，tile 由完整范围独占，在原生私有帧上直接计算，不增加锁或宿主同步服务。共享 word 的所有读写共同决定最后消费者，布局复用不能覆盖当前阶段仍在访问的值。

cooperative 的 atomic tile<T> 借用只转交访问模式和字段映射，不转移存储、不复制快照；只读与原子模式不可互换，同一实际来源可有多个显式原子别名。屏障只能在静态根块，尾 invocation 共同参与；值读取与下一次共享写之间的快照同步由算法表达，不隐藏在普通函数或执行调度里。没有新增全局中间 dataset、状态管理器或一次屏障一次提交。非原子任意共享写、动态协作和完整任务队列仍未完成。

## 有界工作输出

clear_prefix 在原 program 阶段建立空输出关系，append 在 parallel 中封闭容量检查、唯一预留和完整记录写入；输出与 Count 沿用实际 dataset 与已有 prefix 所有权。二者在同一阶段一对一配对，不能别名当前输入域，不能与普通共享读取或任意原子改写混用。阶段完成后才交付有效前缀，Count 预留值不成为同阶段载荷的发布标记。模块 requires／ensures 与跨提交 DomainBindings 直接承接，不新建队列管理服务、宿主计数镜像或执行循环。

CPU 以原生容量比较／CMPXCHG 接纳单条记录；GPU 以实际活动 subgroup 合并预留，广播范围并按 rank 分配唯一位置，减少全局 CAS 热点。Append 的 source effect 及字段输入进入同一 IR 和寄存器／生命周期分析；未被选中的分支不会执行，返回值不用时也不删除写效果。GPU 程序实际要求最大汇合与 ballot/basic 能力，设备创建及 shader execution mode 共同声明该必要平台边界，不靠驱动偶然汇合、不换用另一条算法。

接纳失败由 bool 明确表达，输出计数不越过容量，已写前缀及容量尾部分别保持其职责；输出顺序和成功调用者不承诺跨后端一致。完整记录先按普通值求值再接纳，通用可写批量 reservation、并发出队与设备自主任务仍未完成。

## 原子字段的模块化借用

函数接口的 atomic T 限定借用现有位置，普通值参数仍按值；实参先通过既有索引与原子访问权限检查，捕获调用方 Place 与逐字段 word 映射，索引只求值一次。独立库检查使用符号位置，实际 program 从调用点静态内联到既有 Dataset／Tile Atomic IR，不增加运行时引用对象或另一份设备地址 ABI。

字段可在普通函数及 cooperative 函数之间多层转交；显式原子别名允许，直接读写、局部复制或引用逃逸拒绝。数据、模块私有性、执行目标与生命周期仍由原所有者负责；跨函数的原子写入进入同一阶段依赖和 Count 失效规则。普通函数不隐藏协作屏障，无共享写副作用的集合回调继续只接收普通值参数。整份独占可写数据集借用、动态引用和通用资源泛型尚未完成。

## 数据集身份与函数资源接口

read／atomic dataset 参数借用现有缓冲身份，和 atomic T 位置借用、tile 字段映射共用原来的静态函数展开。独立库检查只使用声明的类型、形状和访问模式构造符号元数据；真正的 program 调用绑定实际缓冲编号、长度域和当前阶段权限。没有另一套数组存储、运行时引用 ABI、参数上传或宿主每元素调用。

函数内 read 与 atomic 各自保持权限，不能从正在独占修改的数据隐式借成共享只读，也不能把普通写升级成原子。多个只读或显式原子别名保留同一实际身份；读取、原子写、跨元素访问与 Count 失效都回到原阶段依赖。原子数组的遍历游标只表示位置，读写仍通过显式原子发生。program 继续拥有并行域、prefix 关系与调度，cooperative 继续拥有显式块内协作，函数不隐藏同步。

read 数据集可以包含既有不可变 view，返回子 view 仍由真实资源图持有。借用数组本身不能作为普通值存储或返回，函数只借用完整容量；固定形状和索引必须由自己的接口与算法证明。独占可写数组借用、第一类资源引用与动态任务仍待继续实现，不能用无权限的散写补齐。

数据集与 tile 的长度事实现由原借用持有，用实际数据集／逻辑块的稳定长度身份关联重复读取，不以某一次 SSA 装载代替资源身份。分支仍保存／恢复原环境，for 的既有比较与 parallel 的真实执行域提供循环体／元素内的非空事实。普通值、view 和局部赋值继续沿原值来源处理；数据字段与原子内容不因长度稳定就变成快照。这里仅调整前端元数据，不新增运行时长度对象、计数镜像、校验或设备 IR，阶段与资源完成点保持。

函数的 nonzero／nonempty／index requires 复用同一接口约束列表，与 program 的 prefix 要求共同参与 .h/.b 签名匹配。前端仅从已绑定的普通值、数据集／tile 元数据或不可变 view 参数字段解析要求，不在证明阶段执行表达式或读取数据；调用点先证明全部要求，再精化原参数 Proof。独立函数检查使用声明的前提，实际 program 仍从调用点静态内联为原有算术／访存 IR，没有运行时要求对象、断言、调用检查或新的执行状态。值条件暂不进入 program 原始宿主输入；资源权限、prefix 所有权和真实完成点仍由原边界负责。

## 独占位置与函数写效果

inout T 把 parallel 已有元素所有权或局部位置借给计算函数。前端以同一个 OwnedBinding 持有实际 Place 和逐分量事实，字段投影只映射原槽／原缓冲 word；独立库检查使用符号局部位置，封闭 program 时直接绑定调用方实际位置。实参捕获一次，同次独占借用按实际位置判定不重叠，多层转交不产生另一套所有者或引用 ABI。

函数体直接使用既有 Load／Store／LoadLocal／StoreLocal；返回时只交回编译期的当前内容事实，真实数据已经写在原位置。AST 写效果覆盖嵌套调用、实参、索引、条件、循环和选择式，局部存储分配与控制流撤回知识共用它；原阶段读写集合、Count 失效和资源完成点不变。独占位置的重复读取关联当前内容身份，原子与外部只读内容不被假定稳定。

inout 不提供整份可写数组、共享散写或隐藏协作。局部不可变 view 句柄交换不转移实际资源寿命，也不能修改子资源；存储与完成仍由原执行所有者负责。simulation.bodies 已用两个独占 float3 字段表达无返回值积分，能量通过 write f32 字段输出；当前下游原生代码与直接计算对照，不能据此声称完整语言、完整引擎或超越成熟引擎的性能已实现。

## 输出位置与无返回值计算

write T 与 inout T 共用实际独占位置、字段投影和别名规则。write 不消费旧内容；前端在既有 initialized 集合中撤回该位置的旧初始化事实，函数必须在结束前完整写入。实际局部槽与独占元素 word 使用同一种位置键，声明、直接写入、嵌套函数、分支及循环共用这一事实源；不向运行时增加初始化位、清零、检查分支或第二份输出对象。

调用内部明确区分普通值与无结果。void 函数、write 参数和无初值局部声明静态展开为原有 IR，不需要伪造返回值或新增调用 ABI。有返回值函数可以同时输出多个独占位置；cooperative void 调用仍在显式根块，并继承同一逻辑 tile。函数的实际写入继续进入原有阶段依赖和 Count 失效规则，原存储与真实完成所有者保持。普通函数的提前返回沿下述函数域实现；CPU 应用整份已初始化 inout 借用与当前 write dataset 完整初始化范围已实现；一般动态子域／数组初始化推导及其他执行域的整份独占借用仍待继续。

## 函数退出与控制流所有权

return 的所有者是当前函数；CPU 应用使用原生函数帧，元素函数仍以静态函数域表示，不结束 GPU invocation 或 program。前端以顺序块的顺序继续／return／break／continue／seek 边表达控制流；在每条返回边检查 write 完整初始化，在循环条件失败和 break 处保存原环境，后续合流只消费实际可到达路径。独占位置、资源长度与值仍使用既有 Proof／initialized 数据，不向运行时复制这些编译期事实。 continue 沿原 IR Continue 进入最内层局部循环回边；for 的普通结束与 continue 共用同一游标加一降低，while 重新求值条件，seek 保留显式赋位且不加一。各个回边复用原存储位置与局部资源释放职责，不进入循环后出口合流，不增加循环状态、IR／ABI 或设备提交。

bool条件在同一个Proof内按实际逻辑分量保存，记录／嵌套字段、固定数组已知元素、推导bool向量及普通Result活动载荷沿原构造、投影、赋值与合流交接；不再用单个标量槽承担整个普通值。false／true保留共享的不可变合取／析取结构，所有分量在原模块合同中共用节点表；实参替换逐共享节点完成，未改写分量沿原入口内容身份继承调用者条件，不新增装载或机器参数。实际消费先合入原环境真值／数值端点，排除矛盾路径后取共有事实；Result继续按原bool判别字选择活动载荷，普通字存储不撤回逻辑bool条件。整数顺序关系由原Fact保存，调用边界用真实实参Proof生成端点与索引域，不提前丢弃未知形参间的比较；资源身份仍由原长度及所有者提供。没有第二份事实权威、运行期条件对象、索引检查或后端协议；数据布局、写效果、函数副作用及Scope／Exit生命周期保持。条件载体在原模块接口明确区分格式，本轮同时采用的资源位置对象格式为COFF4。动态数组具体选择、一般数值分支返回、循环回边与任意完整关系求解仍需继续，不将当前推导能力当作语言边界。

每个分量在原 Proof 内保留实际来源及当前路径已证相等的快照。u32／i32 的显式等式进入原 Condition，传递关系交付非零事实，u32 另传递区间与索引／长度域；不同 OR 路径先分别取得等式闭包，再保留共有关系。合流取来源交集，写入替换对应分量；短路／选择式撤回临时条件时，只保留首次读取的实际来源，不把分支内等价关系带到未执行路径。资源身份及写权限保持，不建立独立的全局关系图或运行时状态。循环已写值的回边、浮点等价和外部资源重复装载仍需继续实现。

整数算术消费原 Proof 的同值快照：同一分量的实际来源集合有共同身份时，两侧属于同一整数值；当前路径显式相等的传递闭包也沿原来源集合交付。减法与 XOR 得到零，AND／OR 取两侧非连续数值集合的交集；除余仍先由原 binary 入口证明除数非零，再分别得到一与零。交集为空时保持空路径，不生成虚构端点。u32 同值 AND／OR 同时保留两侧真实索引及精确长度域，普通非同值运算继续使用原有保守推导。向量与标量广播按实际对应分量判断，不因区间相同或字段名相近认定相等；改写及调用效果仍按原快照生命周期失效。这些范围事实继续消费原 Proof；结果可确定等于某个实际整数操作数时，再按下述恒等交接继承该快照。浮点不套用整数规则，也不增加等价缓存、关系图、IR 折叠、运行期检查或独占写权限。

整数恒等运算在同一个算术事实所有者中继承实际操作数：加／减零、乘／除一、中性 AND／OR／XOR、低五位有效计数全为零的移位，以及已证同值 AND／OR，按真实对应分量选择结果等于的输入。中性值从原整数片段的单值取得，i32 按原有序偏置还原位模式；有效移位量沿原 shift_counts 求集合，不按未掩码数值猜测。结果先投影该操作数的原身份／非零／域事实，再与原运算的可达区间相交并合入已有正确域，最后共用 Proof::assign 交接分量，保留空路径和未处理分量。i32 中确实不改变原位模式的恒等结果也可保留潜在资源域，直接索引仍要求 u32；真正改变值的有符号运算不继承它。普通运算 IR、两侧求值和副作用顺序、统一性及真实当前位置写检查保持，继承的是已捕获的输入快照，后续改写仍由原位置／调用效果失效；没有新建第二份同值状态或执行器机制。

普通数值 for 的范围事实由 bounds::for_cursor 从已捕获 begin／limit 生成；没有当前循环 seek 时采用 begin 的数值下界，保留原有严格上界与长度／索引域。无符号正文游标小于 limit，末尾及 continue 的加一最多到 u32 最大值后退出，不发生回绕重入。只遍历当前正文和 if 的 seek，嵌套循环是各自的重入所有者；当前循环可 seek 时下界仍为零，既有 seek 赋值／Continue 与访问检查不变。该分析只生成原 Proof，不复制起点状态、不修改 IR 或运行期，也不将未实现的一般 seek 不变式当作已知事实。

普通 if、短路／选择式和循环的真实出口共用原环境合并：逐分量合并身份、区间、非零与索引域；标量 bool 按其两种结果保留共有关系，条件表达式另外消费原分支条件。删除分支后按变量名清空整份记录的处理，未写字段继续由同一位置持有自己的事实；某侧已经退出时不与不可继续的环境混合。确定初始化仍使用原继续路径的交集，写入及原有统一性标记保持。编译期已知的短路／选择式只交付实际路径的环境和访问效果，未执行的调用不构成阶段写入或撤销原 Count 关系；两侧仍沿原规则接受类型／能力检查。循环入口也按可能写入的投影撤回事实，未写分量继续使用原身份；已写分量的不变式及缓存谓词回边仍需继续实现。

写入遍历同时服务既有可变绑定判定与循环入口，保留直接赋值及 write／inout 参数的实际位置表达式。投影复用原字段／swizzle 类型映射，固定数组下标表示对应元素或可能元素的分量集合；不求值下标、不生成第二份代码。数据集名字访问当前独占元素时，按原 binding 与实际 word 对应其所有者。循环撤回与正常位置写入共用原 Proof 的逐分量更新；动态数组写入只撤回数组子对象，不清空外层记录的其他字段。没有另建事实所有者、运行时状态或校验流程，动态数组内部的具体位置关系与一般循环定点仍未完成。

IR 的 Scope／Exit 明确最近函数退出域；普通末尾返回不需要它，特化后唯一末尾退出也直接消除。活跃性、DCE、寄存器分配、tile 私有状态和全部集合 x64 入口共用这条退出边。Scope 的必要写入保留，未使用的纯返回计算可删除；无返回值函数不生成结果槽。

CPU 直接修补静态跳转到当前函数域末尾。GPU 使用恒定选择器的结构化 switch 域；不在循环中的 Exit 跳到当前函数域合流，循环内 Exit 先到最内层循环合流，再用该处 OpPhi 的 SSA 布尔值决定继续退出外层循环或到函数域合流。普通 break 的入边为 false，函数退出入边为 true；没有可变返回状态、逐语句条件包裹或结束 invocation 的 OpReturn。依据 [SPIR-V 2.11.3 结构化控制流](https://registry.khronos.org/SPIR-V/specs/unified1/SPIRV.html)，分支不能任意跨越嵌套 loop；嵌套函数各持有自己的 Scope。

普通函数退出后，parallel 元素和父级 tile 阶段继续。cooperative 仍不支持提前返回，编译期明确拒绝，避免用 lane 私有退出冒充整块一致协作。返回值与输出位置在编译期分别合流，阶段写集合和 Count 失效仍由原有事实源处理，不新增设备提交、任务服务或资源所有者。现有 GGX 直射函数在背光时提前返回零；这表达必要计算域，不改变几何、材质设置、内部采样或整体引擎完成状态。

## 数值泛型与静态类型展开

数值泛型属于自研前端的函数类型语义。AST 保存类型参数与有限类型集合，模块的 .h/.b 签名共同约束它们；加载后从原声明生成允许的具体类型组合，再用同一个独立函数检查入口检查全部实例；实际调用共用实例化入口。World 只保存原声明，各检查／调用上下文持有自己的 Arc 定义，没有全部展开实例的全局副本。只有源模板与这些编译期定义，没有运行时类型对象、特化缓存服务或第二套函数执行器。多参数分析量随类型集合笛卡尔积增长，通用符号泛型体分析仍待实现。

调用参数先按原访问模式取得 Value、DatasetView、TileView 或实际 Place，再从对应值／元素类型推导参数。相同类型变量必须精确一致，元素类型、形状、权限和来源没有被类型擦除。具体函数继续沿原静态内联、requires、写效果、返回与初始化规则进入既有 IR；普通原子位置与块内 tile 保持原内存作用域，真实资源完成点不因泛型改变。

泛型体中的类型声明和 T(...) 构造在前端替换为具体类型。原生代码只由实际 program 的调用产生，CPU／GPU 的指令、阶段、寄存器和资源 ABI 共用原后端；独立库检查所有允许类型不代表为未使用类型生成设备代码。现有中心力场已按 floating 集合表达，模拟仍推导 float3；代码和实测比较见问题列表，不能从泛型存在推导通用性能提升。

目前的集合覆盖 32 位数值标量及 2／3／4 分量向量，可用于普通值、位置借用、数值元素 dataset／view 和 cooperative tile 接口，并可作为下述记录参数。一般值域常量参数、开放接口约束、任意资源种类泛型、设备自主任务与完整语言仍未完成，B／Rust 的既有职责和资源所有权保持。

无参数泛型单位元可直接写 identity<T,Mode>，不再为了推导类型增加多余普通参数。引用本身不是普通值，不可存储或逃逸；目标期望类型不会反向补齐类型参数。一般高阶参数、动态分派和完整语言仍需继续。静态引用的原生代码成本与具体函数对照、数值与资源行为分别记录，不能从源抽象推断整体产品性能提升。

## 矩阵值与 B 的空间算法（2026-10-25）

固定 floatRxC 矩阵由原 Ty 持有完整名字、逻辑分量和 r0… 行字段，按行向量对齐计算大小及偏移；没有另建布局对象或运行期维度。编译器识别九种 2–4 行／列的 f32 矩阵，构造、转置及字段投影保留普通值和原位置语义，泛型继续使用既有类型集合、实例化及确定初始化。

## 固定数组的存储与编译期权限（2026-10-25）

## 缓冲区传输与加速结构的完成所有权（2026-10-25）

缓冲区／纹理上传、GPU清零、CPU输入的BLAS／TLAS构建及GPU实例TLAS构建现在复用同一个Execution／Completion。API返回已提交资源，不等待这次设备工作；后续计算与构建从实际数据／纹理／加速结构收集依赖，在原队列建立对应的内存访问关系。没有独立任务服务、完成计数镜像或另一套资源注册表。

Execution按真实操作持有命令、上传暂存、构建输入与scratch；资源本体持有相应的真实完成点。最后引用退出时，实际原生存储交回其完成所有者，不让执行反向持有自己的公开资源对象。查询提交持有TLAS，TLAS持有真实BLAS。GPU实例构建消费整个GpuDataset，将页表、数据页和地址数组交给构建完成点；不借用可能提前退出的输入，也不下载矩阵。

纹理返回前完成主机 mip 到 staging 的复制和原生提交，源 Texture2D 随后可以退出；staging 与上传命令由原 Transfer Execution 持有。共享图像所有者同时持有 image／view／sampler 与真实上传完成点，采样提交收集该点并由 Commands 保持图像到消费者结束；执行不反向持有自己的输出图像。Texture::is_complete／wait 只观察上传，后续采样仍由其提交完成点负责。最后图像引用退出时先结束实际上传使用，再销毁物理句柄，沿用既有原生完成处理。没有额外完成标记、全局图像表或后台回收；依据为 [Vulkan 图像寿命](https://docs.vulkan.org/refpages/latest/refpages/source/vkDestroyImage.html) 与 [同队列屏障语义](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdPipelineBarrier.html)。

Device::download_texture 借用本设备的真实不可变图像，将全部 mip 直接复制到 host-visible coherent staging，返回新的 CPU Texture2D；源 CPU 像素不作为图像镜像保留。图像创建声明采样及双向传输用途，上传与下载共用由实际尺寸／mip 数推导的紧密复制区域。当前单队列在本图像范围过渡 shader-read→transfer-src→shader-read，覆盖此前上传和采样访问，等待本次复制及布局恢复完成后返回；图像仍可由原共享引用继续采样。staging 只映射一次，各 mip 直接写入最终像素 Vec；缓冲区和纹理共用原映射／Transfer Execution 入口，不再重复构造提交完成对象。调用者可显式把 CPU 快照上传到另一独立逻辑 Device，两个原生资源和完成点分别所有；不按物理设备名称共享句柄或建立自动迁移／布局状态表。复制依据 [Vulkan 图像到缓冲区接口](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdCopyImageToBuffer.html) 与 [图像用途](https://docs.vulkan.org/refpages/latest/refpages/source/VkImageUsageFlagBits.html)。

BottomLevel／Acceleration的is_complete／wait观察其构建或显式 refit 完成；查询使用寿命由查询提交负责。显式下载、wait、当前引擎draw和呈现仍可等待；没有后续所有者时，最后析构须结束真实原生使用。直接跨设备传输、多队列、原地 refit、取消、自动背压和完整流送尚未完成。实现与原生记录见[设备实例](DeviceInstances.md)，不能据此宣称全引擎无等待。

## 加速结构的显式可更新构建与 refit（2026-10-27）

原 bottom_level／top_level／top_level_device 保持原静态构建；对应 *_updatable 入口明确声明 Vulkan ALLOW_UPDATE。refit_bottom_level／refit_top_level／refit_top_level_device 在同一 build_acceleration 中选择 UPDATE，以原结构为 source、独立新分配为 target，沿原依赖、barrier 和原生完成点提交；scratch 使用本次查询的 updateScratchSize。原结构及其共享查询保持原快照，新结果仍由相同 BottomLevel／Acceleration 所有者交接；没有原地改写、自动重建、另一套构建器或资源注册表。语义依据 [构建与更新的 source／target](https://docs.vulkan.org/refpages/latest/refpages/source/VkAccelerationStructureBuildGeometryInfoKHR.html) 及 [构建大小与更新 scratch](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetAccelerationStructureBuildSizesKHR.html)。

实际 AS 所有者保存原生 build flags、primitive／instance 数量及三角形 maxVertex，更新保留这些既有描述；设备归属、ALLOW_UPDATE 及形状由原资源边界处理。索引内容／顺序与活动状态、有限顶点／可逆实例矩阵仍是相应 unsafe 输入前提，不通过保存原 CPU 索引、逐元素校验或额外证明链重建第二份权威。GPU 实例输入沿原 64 字节页／地址数组直接构建和更新，共享只读 binding 继续持有原存储；CPU 与 GPU 输入可在符合原形状时交接。

UPDATE 的真实消费者会读取旧 AS 本体，仅引用其旧构建完成点不足以保持原存储。原 ExecutionResources::Acceleration 因而同时持有本次 source 结构、输入与 scratch，到更新实际完成后归还。新 TLAS 持有其实际新 BLAS 集合；旧 TLAS 和旧查询继续持有旧集合。资源沿既有完成回收入口释放，不将版本关系变成全局当前场景、后台回收或代码热更新机制。

当前覆盖 CPU／GPU 几何 BLAS、CPU 实例 TLAS 与 GPU 实例 TLAS 的显式新版本更新；GPU 几何入口见下节。原地更新、通用拓扑修改、压缩／重排、自动构建选择与完整流送仍开放。接口实现、原生查询、完整引擎采用、构建／遍历性能和峰值资源各自记录，不把 UPDATE 指令或新 API 当作性能优势的证明。

## GPU 几何直接进入原生 BLAS（2026-10-27）

bottom_level_device／bottom_level_device_updatable／refit_bottom_level_device 消费本设备的顶点与三角形 GpuDataset，复用原 bottom_level_inputs／build_acceleration 生成 BUILD 或 UPDATE。CPU 数组入口同样交给这一份几何描述；B 继续产生位置、拓扑及其计算关系，Rust 负责原生输入、AS、传输与真实完成。不改变 acceleration 查询 ABI，不下载顶点、索引或有效计数。

当前原生顶点输入在 offset 0／4／8 为三个 f32，按实际记录 stride 读取，允许位置后的其他字段及填充。三角形输入为紧密三个 u32、stride 12；例如含 array<u32,3> 的记录，不能将 stride 16 的 uint3 记录当作紧密索引。该布局来自当前 Vulkan 三角形接口，并非 B 的永久类型边界。入口消费完整物理记录域；全部记录已初始化、位置有限、索引落在顶点域内由 unsafe 消费者负责，refit 仍保持索引内容／顺序、活动状态、原数量和 maxVertex。

普通数据页具有原传输用途，没有 AS_BUILD_INPUT_READ_ONLY 用途。ray_input_device 因而沿原 Transfer Execution 将真实记录页按逻辑次序复制为连续、自有的原生 AS 输入；保留实际 stride 与 primitive 编号，不为所有普通分配追加 AS 用途，也不拆分 geometry。生产者写入到复制读取、复制写入到 AS 读取各用原队列内存依赖。被消费的源存储交给复制完成点，原生输入交给 AS 完成点；冻结来源直接传 binding()，共享持有与退出沿原 Owned／Read 入口处理。

GPU／CPU 几何可在满足原 UPDATE 形状时交接，顶点 stride 可随本次真实输入变化；原 AS 保持原快照，更新仍持有旧 source 到实际完成。Vulkan 输入地址、用途与更新条件见 [三角形数据](https://docs.vulkan.org/refpages/latest/refpages/source/VkAccelerationStructureGeometryTrianglesDataKHR.html) 和 [构建／更新](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdBuildAccelerationStructuresKHR.html)。大索引压力已查明存在超出实际 maxBufferSize 的原生请求，按下节修正；容量内的核显 AS 压力问题仍开放，原始失败记录保留。

## 原生缓冲尺寸与逻辑数据域（2026-10-27）

VkBufferCreateInfo::size 不得超过物理设备报告的 maxBufferSize，这是 Vulkan 缓冲对象的真实边界，见 [缓冲创建约束](https://docs.vulkan.org/refpages/latest/refpages/source/VkBufferCreateInfo.html)。原逻辑设备 Inner 在创建时取得 Vulkan 1.3 核心提供的该属性并持有唯一事实；Allocation::new 在调用 vkCreateBuffer 前对实际物理缓冲请求报告不支持，错误包含请求字节数、设备属性值与用途。不固定 2 GiB，不从总显存、动态预算、primitive 数量或经验值推导阈值，不建立额外审核、回收、重试或替代分配链。

该属性约束单个物理 VkBuffer，不是 B dataset、u32 记录域或 CPU 连续存储的逻辑上限。原 GPU 数据页继续按其已有布局分配，逻辑域可以跨多个合法物理缓冲；本轮两 GPU 均完整执行并读回 272629760 条 stride 16 记录、4362076160 字节、17 页。当前 AS 及其原生输入／scratch 需要各自的连续物理缓冲，native size query 超出该设备能力时明确不支持，不缩小 AS、不拆 geometry 改 primitive 编号，也不将原错误写成成功。Vulkan 1.2 下未取得该核心属性时保持未知，原生返回值仍如实处理；不把缺失属性伪造成 0、无限或另一台设备的值，也不提高已有 Vulkan 1.2 最低要求。

本机两 GPU 报告的 maxBufferSize 均为 2147483648，而 22369623 个三角形的 AS 请求分别为 4073406300 与 3638792616 字节，旧成功创建／查询不能作为合法容量证明。尺寸越界已在原资源入口修正；核显八百万三角形在各缓冲均处于该范围内时仍出现设备丢失及 Watchdog 141，CPU 输入亦复现，故压力问题未全部解决。该事实不导出固定 primitive 容量或超时参数，不修改系统 TDR、构建偏好或选择另一设备掩盖失败；原生记录及其剩余范围见 Issues。

## 直接生产依赖与完成后的资源归还（2026-10-27）

## C/C++ 与 Rust 宿主的 DLL 边界（2026-10-25）

固定长度常量与头文件保护宏由原 DLL 生成器直接按名称身份产生，不对原标识符做有损大写折叠。小写 a 至 y 转为对应大写、数字保持，其余合法 ASCII 字节以 Z 加两位十六进制编码；大写字母、小写 z 与下划线保持可区分，也不会在生成宏中产生双下划线。该编码只消费本次实际名称，不维护名称表或冲突后的改名路径；C 导出、参数、类型、布局及执行协议继续由原边界负责。

`blc -c ... --program name` 将已检查、无外部前置条件的具体入口编译成算法目标文件；`bllink input.obj -o output.dll` 再生成 Windows x64 DLL、C ABI 头文件、导入库与 Rust 安全包装器。B 前端、IR、原生代码、ABI 布局及执行框架静态代码的编译属于编译阶段；最终 PE 与原生依赖解析属于链接阶段。实际数据复制、CPU／GPU 执行、完成等待与本次资源释放仍属于 blcompute::ffi。DLL 内含最终机器码／SPIR-V，create 只装载代码／pipeline，不再编译 B 源码或值 IR。现有 Rust `dll::build` API 组合这两个正式阶段，原生 crate API 和公开 C/C++／Rust ABI 保持。

C++ 与 Rust 是并列宿主；Rust 原生 crate、类型及异步资源接口保持不变，不经 C ABI 中转。DLL run 同步完成本次纯值数据调用，返回前完成必要输出读回；宿主拥有数组，DLL 拥有自己的 handle，跨界不传递 C++ 对象、Rust Vec／String 或分配器所有权。view、纹理、AS 和外部 prefix 条件不伪装成裸值 ABI。完整接口、当前限制与部署见 [原生集成](NativeInterop.md)。

DLL 生成器直接消费原 Ty 的成员、分量及字节偏移，不维护另一份布局。展开 C／Rust 标量字段时，每个记录字段段按 `_f<原 ASCII 长度>_<编码名称>` 编码，原 `z` 写成 `z7a`、`_` 写成 `z5f`；数组下标、向量分量和结果判别／载荷保留原专用后缀。长度保留真实字段边界，字符编码避免产生 C++ 保留的双下划线，直接区分 `a_b` 与 `a.b`、用户字段与数组／向量／结果／矩阵成员。生成的成员名称随配套接口更新，实际布局、导出符号、参数协议、原生代码及资源所有者不变；不增加冲突登记表、运行时名称查找或重命名备用路径。

## 函数内动态拥有位置与真实循环出口

静态投影、动态下标、赋值及written输出现在共同消费原Place／Position身份和Returned资源树。资源叶仍对应实际Frame存储，不按所有候选一起移动或释放。赋值先捕获左侧位置与下标，再求值右侧；右侧可能移动原内容，旧内容释放因此读取右侧完成后的原树状态。移出的内容交给实际新所有者后，原位置只失去相应拥有关系；匹配补回后可继续读取。

条件拥有关系保留源码真实控制值，dataset内容初始化保持自己的来源与选择关系。构造一个动态位置不会初始化其他资源，也不把普通字段随句柄一起标为完成；非零默认变体仍须完整写入实际内容。CPU／GPU位置在函数内沿同一选择与分支事实解析，显式传输和原消费者完成保持各自职责。

循环出口不再以拥有交集为最终状态并插入提前释放。原Loop／If路径选择各出口的实际资源树和初始化事实；for／while的首次构造、继续边、break与正常出口按原上下文分析，恢复边同时恢复已经捕获的实际游标。既有位置写入分析包含write／inout调用；构造过程只在实际待构造位置或资源图新增知识时继续展开，不设置迭代上限，也不生成运行时拥有标记。最后释放沿真正执行的路径读取有效元数据，Frame及blcompute仍是唯一物理资源所有者。

普通返回、显式Err返回和独占输出只交接完整的活动拥有内容；实际view与位置借用不能跨越来源的移动或释放。PA3 Release已验证动态叶／聚合／嵌套数组／变体、稀疏与运行时范围初始化、for／while及write调用、break／continue、取出后释放余项、显式Err及函数内CPU／GPU混合位置；原始输入与输出范围见Issues，不据此声明通用无泄漏、性能达标或完整借用／资源阶段体系。

本节函数内增量交付时保持BLCO8／BLRI2，未把局部控制寄存器或初始化位置写入公共接口。跨函数及独立对象／归档的条件输出位置按下节交付；条件输入要求按后节交付；循环提前退出的跨函数输出关系按后节交付，保持显式传输及原调用语义。

## 跨函数模块的条件资源输出位置

动态拥有位置的选择条件、资源来源和CPU／GPU位置是同一编译期合同。选中元素移出并补入新资源后，返回载荷与written数组保留实际下标的关联；输入为统一GPU或CPU／GPU混合位置时，调用者可按同一公开下标只下载真正仍在GPU的资源。普通函数、多层转交和递归沿原函数图形成同一输出关系，源码、对象和归档导入采用同一表示。

各返回点先完成实际输出检查，再合流returned与written。合流后的模型直接进入正式函数合同；旧的函数末尾第二次written_model读取已删除，它曾把最后解析的Err分支环境重新当成整个函数的事实，覆盖成功分支的位置。动态取出也按每个真实候选的原选择条件交接位置，不能先合成一个无条件来源并集。

驻留表达式在原函数来源图中联合求解，未知位置和没有正常来源的空解分别保留。条件只绑定声明输入和存活输出的值编号；调用处代入实际参数与结果，检查仍消费当前路径。不能把不可用的局部选择当作同一个公开布尔量合并，不新增机器参数、位置镜像、运行时拥有表、数据副本、第二Frame或回收所有者。真实分配、显式传输、执行与完成后的释放保持在原Frame／blcompute。

条件输出位置交付时采用BLCO9；当前随条件输入升级至BLCO10。旧BLCO8／9对象和归档须重编，不混用；资源映像BLRI2、view的16字节／对齐8、函数引用参数和C资源入口保持。bllink仍只消费已编译产物，算法库内部计算变化可用原调用对象重新链接，不读取库.h／.b，也不以此声称稳定热更新。

条件输入要求按下节处理真实使用路径。循环提前退出后的跨函数输出位置关系按后节交付；完整资源阶段、自包含拥有view图、可写view、应用内GPU图构造、异步／远端和版本迁移继续开放。实际原生与交付范围见Issues，不作通用无泄漏或性能达标声明。

## 条件输入资源位置合同

原先Input→Target的全局要求把互斥使用路径合并：只按i读取一个CPU元素，也要求未访问的GPU元素在CPU。现在每次真实Use／Call保留原路径；位置要求以输入资源、CPU／GPU目标和生效条件表达，局部检查与公开要求消费同一来源，不再先建立无条件required再单独传播调用。

公共条件由已有值关系投影到声明输入快照，调用点再代入实际标量／字段Proof及调用路径。真实资源输出先在原函数图中闭合，输入要求随后沿原调用图收敛；普通转交与递归不增加机器参数、运行时位置表或按实参驻留生成的实现。条件补集在投影之后形成，避免把不可用的私有比较身份当作公开布尔条件。未来输出不进入输入前提。

同一输入在不同条件下可以分别要求CPU与GPU；实际重叠的相反要求仍拒绝。循环比较也使用这些条件，只在一个分支发生CPU访问并不能将入口全局假定为CPU。没有正常资源来源的路径不产生访问消费者，实际未知位置仍是未知，不能把未知来源当成无资源或CPU。

源码调用、无源码对象及标准COFF归档交接同一合同。元数据现为BLCO10，旧BLCO9及更早产物须重编；本次没有改变BLRI2、C资源入口、引用／view机器布局或Frame的分配、执行、完成与释放职责。

循环提前退出的输出关系已按下节实现，与条件输入分别记录；一般资源阶段及其他长期能力继续开放。实际验证与提交状态见Issues。

## 循环提前退出的跨函数资源关系

for／while资源循环先消费真实首次进入，后续继续边复用原构造进展与资源关系。局部bool由未知成为已知的进展保存在原LoopContext环境；自然退出、break、continue、嵌套与返回分别沿实际控制位置交接，带副作用的while条件仍在原执行点求值。普通值、拥有值和资源位置使用同一出口选择，循环后返回或write的bool可以准确报告实际显式传输。

返回点在原Proof／Returned中绑定实际布尔输出与资源关系，再投影到声明输入和存活输出。布尔值的真假事实及同值关系随原合同交接，原下标与Result标签保持；整数输出的全部范围不成为资源来源的额外前提。

递归资源输出曾按语法树不断替换，重复合取和同一来源路径使语义已稳定的关系继续增长。原来源求解现在合并相同真实来源的成立路径，Clause把各路径化为事实合取，合并重复上下界、移除矛盾路径及被已有路径包含的重复项。各来源的完整成立域继续保留；Absent没有正常资源消费者，Origins空集合仍表示实际未知位置。表示去重不依赖求解轮数或超时，不把只有一个可能来源当成无条件资源，也不猜CPU。

同一BLCO10表示交给源码调用、无库.h／.b对象和标准COFF归档；BLRI2及机器ABI保持。实际存储、显式传输、执行和最后消费者完成后的释放仍归原Frame／blcompute，没有运行时拥有标志、位置镜像、资源副本或第二Frame。PA3使用同版Release完成真实CPU／GPU、普通转交、自递归／互递归、混合输入、Result及旧对象私有重链接；完整数量和原始结果见Issues。这一范围不代表一般循环不变式、完整资源阶段、动态容器、自包含拥有view图、异步／远端或版本迁移已完成。

## CPU自包含拥有聚合与view生命周期（2026-10-29）

CPU拥有记录、固定数组、变体／Result及嵌套组合现在可以同时持有dataset和借用其中实际存储的不可变view。构造、局部移动、静态／动态部分取出与补回、覆盖、普通返回、write／inout及递归沿原Returned／Data树交接。移动元数据不搬迁Frame存储；同一聚合中的view随拥有值交接，本地仍存活的外部view可以继续读取同一资源。把拥有资源交给可能释放它的函数前，调用者不能留下仍将继续使用的外部view。

资源叶持有实际存储来源，普通值Proof只保存类型中真实view分量的关系。两者在原分支、下标、循环与调用图中使用同一选择条件。动态写入只在实际选中的位置替换view来源，未选中位置保留原来源；不能用所有候选来源的无条件并集代替写入。循环入口与回边消费拥有值自身更新后的关系，不用旧句柄身份覆盖新关系，也不把循环当成函数接口而抹去仍有效的局部条件。

每个真实返回点联合检查返回拥有资源、返回view和written输出。资源输出以自己实际交付的存储命名公共身份，view保留所有可能的真实输出所有者及其条件；既有输入来源仍属于输入，不按来源集合相等猜测两个选择相同。返回路径约束实际借用需求，不把当前路径的补集误当作没有交付所有权。

显式覆盖、临时拥有值结束与作用域退出沿原资源释放入口检查实际旧拥有值和仍存活的消费者，包括正在交付的输出。条件拥有只在真实拥有分支释放；不再先把动态候选拍成无条件资源集合再做一遍检查。view与位置消费者的寿命来自原AST可能后续使用，已消费的返回操作数不继续占用寿命；从临时聚合提取view也不能越过被释放的实际资源。物理分配、执行、CPU／GPU完成与释放继续由原Frame／blcompute负责。

独立对象与标准COFF归档导出相同资源／view来源和有条件访问合同；调用者可在没有库.h／.b时编译，链接器只比较实际已编译合同。私有实现变化且公共合同保持时可重链原客户端对象，实际合同变化则拒绝不匹配旧对象。来源条件和资源输出身份改变了实际元数据编码，当前对象为BLCO13，旧BLCO12及更早产物须重新编译；BLRI2、原C资源入口、view的16字节／对齐8机器布局及Frame所有权保持。前节BLCO10及更早版本记录对应历史交付。

本节是CPU自包含拥有聚合的当前范围；它不提供动态容器、拥有资源的dataset元素、持久dataset图的B构造、应用内GPU图构造、可写view、一般回边不变式、完整资源阶段、异步／远端消费者或版本迁移。普通C ABI的资源值范围也不因此扩大。PA3 Release、实际原生及现有消费者的验证范围和交付状态以Issues原记录为准，不作通用无泄漏、性能达标、引擎采用或稳定热更新声明。

## 按返回分支交接部分输出初始化（C-020.5.1）

普通on cpu函数通过既有ensures声明initialized(输出位置, 输入快照／returned条件)，具体语法见BLanguage.md末节。未声明范围仍完整输出；每个真实返回点检查声明条件下的普通分量、活动资源和dataset内容，普通返回值本身完整。错误结果不自动使所有输出无效，也不授予未写位置的读取权限。

原Position与ReturnExit／Returned交接初始化、拥有、资源位置和view来源，不建立另一份输出镜像或状态表。条件使用按值输入的真实快照和本次返回值；调用撤回声明位置的原初始化知识，按相同条件授予权限。动态拥有位置沿原Place及资源树交接，不用已加载的新句柄猜原资源；Builder的形参与后续dataset／内联初始化来源共用同一编号器的不同身份。

拥有资源只在正式声明的分支交付，未交付分支仍留有实际拥有内容时报B229，不能擅自释放、回滚或把未知当作没有资源。CPU／GPU物理存储、实际最后消费者和外部view继续归原Frame／blcompute及原借用所有者；普通C ABI的资源范围保持，不引入运行时初始化位图、隐藏传输、复制、注册表或第二Frame。

自递归和互递归先消费同一正式合同，再检查真实定义，不增加任意深度／轮数预算。内联、源码、无库.h／.b的对象及标准COFF归档交接同一关系。条件所用模块常量按实际类型／值及投影进入原函数合同，const实例按实际值代入；公开条件或其常量语义改变时拒绝旧对象，公共合同保持的私有实现可重链。对象元数据为BLCO15，研发BLCO14未提交，旧对象须重编；BLRI2和原机器布局保持，前文BLCO13对应历史交付。

外部C声明是实际信任边界，可准确声明返回状态对应的初始化范围；编译器不读取DLL机器签名或证明实现。BLEngine PeekMessageW／GetClientRect是条件输出需求来源，本轮原生消费者与实际采用分别记录，不能把Windows接口的一次成功执行写成引擎迁移。这里仅闭合普通CPU函数和其发起CPU／GPU工作的条件输出范围；完整错误资源阶段、异步失败、动态容器及其他执行位置的条件输出仍未完成，实际验证和交付见双台账。

## 用户拥有值的静态释放与现有资源树

CPU用户资源以`owned<T,F>`接入原Returned／OwnedValue资源树。T是实际载荷，F是类型中的静态自由函数身份；包装本身不存放函数指针，布局直接复用T。普通复制身份仍由handle等原类型表达，包装的按值传递则是移动。F接收T后沿原普通CPU调用执行，T自身的dataset／拥有聚合在该函数中继续由原Frame与blcompute清理，不建立外部对象登记表、第二Frame、运行时引用计数或关闭队列。

构造、覆盖、条件合流、循环及各实际出口复用原拥有状态。声明位置只为编译期确定用户拥有绑定的逆序清理；不进入机器参数或公共合同。记录／数组按字段／元素逆序处理。into_inner显式消耗包装并交付T，解除该包装的F调用；只读借用不能取得此权限。普通write／inout与已提交的条件输出合同共同传递拥有包装是否实际存在，不能只给出可读条件却丢失销毁关系。

静态释放是原借用图中的实际后续消费者。包含view的包装保持相应来源到F完成；原拥有条件也限制这次消费何时存在。执行释放或覆盖前，当前包装结束自己的待执行消费，其他仍活跃消费者及右侧新值继续沿原Proof参与资源交接。F获得资源前使用原application_movable规则，不能以跨函数调用跳过仍存活view或元素位置。数据最后消费者与真实CPU／GPU完成仍归原所有者，F的普通CPU控制位置不代表所有载荷都在CPU。

独立模块在.h公开相应静态释放声明，将类型身份、拥有条件及实际调用符号交给原模块／链接机制；源码和无库.b的对象／归档使用同一关系。当前组合已采用PA2条件输出、选择来源及长度类型修正。加入静态释放身份后，编译合同为BLCO16；Ty的实际资源编码随新增字段改为BLRI3，保持原C入口签名、标量机器表示、view布局及不透明Frame职责。先前章节列出的BLCO4至15、BLRI1／2是各子范围当时交付编码，当前产物须按BLCO16／BLRI3重编，不增加兼容、重试或链接期重编链。

该能力是通用资源库表达确定清理的语言基础。外部身份有效性、关闭结果、线程上下文及真实异步完成仍由相应API和资源库履行；静态释放不是面向对象、虚派发、运行时闭包或系统回调指针。普通C ABI不传递拥有包装。完整异步／远端拥有、异常展开、版本迁移及BLEngine各实际Drop的替换继续按真实缺口推进，不把本轮语言能力写成全面迁移完成。

## CPU拥有dataset的显式变长

完整操作语义由[语言规范同名章节](BLanguage.md#cpu拥有dataset的显式变长)维护。`resize`在原Frame的实际Dataset槽位调整CPU存储，前缀保留、新增普通值填入和最终释放归原所有者；原Vec复用容量，不额外建立容器服务、资源镜像或回收链。缩短逻辑长度不宣称立即向操作系统归还容量。真实存储所有者撤回受影响的prefix／Count域，编译器以新SSA身份交接长度版本，不能让旧下标域跨过改变存储的操作。

CPU所有权、原初始化与实际借用先解决，GPU先显式download；函数、泛型、Result及独立对象／归档沿原合同消费新值。资源C ABI因新增实际入口升为BLRI4，BLCO16及原view／普通值机器布局保持；旧资源产物重编。此处更新此前“当前BLRI3”的版本表述，历史记录不改写。普通动态存储已交付，动态拥有元素、递归容器、持久view图、异步和BLEngine实际采用仍开放，不把存储原语写成完整容器库或性能达标。

## 普通值动态序列库的唯一存储所有者

`blink.sequence`是正式B库，接口和实现位于`library/blink`；[语言规则](BLanguage.md#普通值动态序列库与数值来源)与[使用说明](../library/README.md)分别维护语义和入口。序列就是拥有dataset，逻辑长度来自原dataset元数据，物理容量、传输与释放来自原Frame／Dataset／Vec和blcompute。库只组织普通B算法及可失败访问，不增加计数镜像、宿主容器代理、资源表或另一条回收链；引擎的场景、几何、资产和业务算法继续归BLEngine。

编译器的普通拥有表达式由原Returned求值负责，dataset赋值从同一模型提取拥有值，删除重复的名称／构造／调用分派。数值关系归原Proof／Domains，实际返回合同只交接已存在的来源事实；合流后的未知来源不能因模型残留寄存器再次变成输入身份。编译期数值快照可以跨新长度版本保留，旧资源访问许可则不能保留。当前BLCO17交接新增数值关系，BLRI4、C资源签名与唯一物理Frame保持。

PA3正式Release已验证普通序列、无库源码对象／归档及CPU／GPU往返。该范围提供普通可复制元素序列库，不宣称动态拥有元素、一般while不变式、完整系统库、自举、热更新或BLEngine全面采用已经完成；这些缺口继续在P4双台账按具体范围维护。

## 算术结果与输入快照的同一关系

原Proof／Domains同时表达已证明不回绕的和与相对输入的常量偏移。关系只由实际算术所有者生产，在访问当前存储长度时消费；不增加另一份数值事实表、运行时检查或宿主代理。新长度相对原size的偏移与资源版本许可分别保存，不能因为改变dataset版本就丢弃仍真实存在的普通数值快照，也不能保留旧资源的访问许可。BLCO18保存新增偏移编码，BLRI4保持；完整while回边不变式仍未由本项交付。

## 宽数值与当前主线合同的交接（2026-10-29）

原Scalar负责实际名称、大小／对齐、符号及位宽，u64／i64占8字节且保持一个逻辑分量；CPU机器指令、GPU标准能力与原Ty物理布局共同落实存储、摘要、tile及普通／外部调用。原Value和Dataset的单标量字段写入按声明分量交接完整位模式，不复制引擎参数源表、ABI填充或资源所有权。句柄仍按原不透明身份处理，不与整数标量混为一种权限。

范围、比较、非零及条件输出沿原Proof／Clause／Returned交接实际Scalar和完整常量。原Facts按身份、标量类型与界值组织；合流顺序借用每组最强界，有真实等价关系时矛盾查询只排序原事实引用，不另持有数值、布尔或零值表。编译阶段活跃载荷安排与用户拥有／释放、view来源及Frame真实完成继续保持各自职责。

当前BLCO19／BLRI5反映实际宽值与编码变化；前述11至18／BLRI4为此前交付范围。旧对象及归档重编，真实格式／资源不匹配由原入口拒绝，不能以重编代替完整版本迁移。正式构建、原生组合、引擎实际采用、提交与发布分别记录；其他数值与系统能力及一般循环推导继续按具体缺口推进。

## while数值入口界的写效果所有者

循环中可能被改写的位置仍由原effects投影；同一分析按实际结构控制流合成可确定的相对位移及中途极值，不再对可证明保持的数值界一律清空。原while入口及真实continue／自然回边共同确定合法界，break／return不成为回边。界由原Proof持有，条件失败出口同样消费该界；当前读取身份、资源版本和位置写效果继续分别处理，不增加运行时检查、事实服务、回边标志或数值权威副本。

当前实现范围见语言规范“while单调位移与入口数值界”；一般非线性不变式、可变步长和动态别名仍按实际缺口记录，不用初始常量替代每轮当前值。原BLCO19／BLRI5及Frame保持，此范围没有新增模块编码或资源C ABI。

## 相同借用合流的生产职责

view::Borrow的两个完整关系相等时，原Borrow所有者直接交回原关系，停止生产不改变结果的选支路径。来源集合、边条件、循环与调用身份共同确定完整相等；真实不同来源仍保留选择条件。下游Clause规整及资源消费者无需接收这些冗余组合，不新增限额、条件截断、缓存或布尔系统。原源程序条件求值、资源所有权、最后消费者和BLCO19／BLRI5保持。

来源边首次写入保存原共享条件图，同一来源实际合流时再作原有规整；单条边不预先展开为路径项组合。条件语义、模块编码、收敛和资源消费者职责保持，不以数量上限截断关系。

## 普通返回合流持有真实来源条件

原Returned所有者在返回合流中统一交接普通Value、拥有聚合与dataset的真实view来源。各出口已持有的路径条件必须用于普通Value中的view分量，不能在普通值合流时丢弃条件、将互斥来源变成无条件候选集合，再让调用者承担不存在的借用。原Proof::join_view_borrows消费同一Condition；普通记录、固定数组、变体与静态释放载荷沿真实类型组合，不设另一份返回借用图。

输入快照、条件改写、循环及最后消费者沿原来源关系处理，未知保持未知；模块导出及实参代入消费同一合同。BLCO19／BLRI5、CPU／GPU存储、Frame及资源释放责任保持，此修复不新增编码、运行时状态或永久验证入口。

view::Requirement在实际写入／移动／传输与返回寿命拒绝处，直接消费原Clause::overlaps的重叠结果，删除把共有事实近似当作来源重叠结论的错误链路。重叠查询只持有当前路径的Facts、共享节点消费位置及实际备选续点；分支结束撤销其局部事实，本次查询返回后全部工作释放。普通possible与required／required_in继续作原保守推导，不为所有局部事实枚举路径；原事实身份、别名、矛盾关系、Borrow图和最后消费者保持，没有新的长期条件状态、第二求解服务、路径展开上限或缓存。

## f64的原数值与执行所有者

f64复用Scalar、Ty、Bits、常量求值、普通调用、模块合同及Value／Dataset的完整8字节交接。x64浮点指令及C double ABI直接按类型发射；SDK数学直接连接平台C ABI，原打印入口拥有位模式、位宽与格式化，没有增加转发层、数值表或资源副本。资源、传输及最后CPU／GPU消费者仍归原Frame和blcompute。

GPU以原DeviceRequirements和ExecutionStage交接shaderFloat64及64位浮点控制要求，原Vulkan所有者按实际物理设备查询、启用和拒绝。计算只使用调用者所选设备，不为缺失能力隐式换设备或增加CPU服务。GPU f64超越函数、严格完整数值策略及其他未实现能力保持明确缺口；不能通过降宽发出GLSL.std.450不允许的指令。

当前模块／资源编码为BLCO20／BLRI6；C Value的f64标签为6，16字节／对齐8和偏移8载荷保持。历史版本表述对应此前交付，完整版本迁移与热更新仍未实现。具体源码、构建、原生、BLEngine采用及P4／Git事实见双台账。
