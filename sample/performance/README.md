# 《并行编程的艺术》性能示例

这份配套程序把书中的同一种算法分别交给优化后的单线程 C++、Blink 原生 CPU 和 Blink 原生 GPU 执行。它复用项目已有的编译器、数据集和执行 API，供读者观察工作规模、数据驻留与阶段组合对效率的影响，不作为构建后的固定测试关卡。

## 编译与执行

使用 Windows x64 的 Visual Studio 开发者 PowerShell，确认 `cl`、`lib`、`cargo` 可用。在 Blink 项目根目录运行：

```powershell
$work = "$PWD/Saved/BookPerformance"
$env:CARGO_TARGET_DIR = "$work/target"
cargo build --release `
    --manifest-path `
    sample/performance/Cargo.toml
$bench = "$work/target/release/bperf.exe"
& $bench map 16777216 9 8
```

四个参数依次为案例、元素数、测量批数、每批连续执行轮数；省略规模时采用下表的书中规模。程序先对每个执行版本预热两批，再输出测量批次的中位数。所有耗时统一除以轮数，以每轮毫秒表示。书中使用 9 个测量批次、每批 8 轮。粒子、空间变换、材质和显示转换直接编译相邻 `BLEngine/Programs` 中的正式算法，需要相邻引擎工作区。

| 案例 | 算法 | 书中元素数 |
|---|---|---|
| map | 乘二加一 | 16777216 |
| reduce | u32 求和 | 67108864 |
| scan | u32 独占前缀和 | 8388608 |
| compact | 稳定筛选 | 16777216 |
| pipeline | 筛选、稳定排序、扫描、归约 | 4194304 |
| tiles | 32 元素块的总量、前缀与去中心 | 4194304 |
| publish | 变换发布与 32 元素块内协作 | 4194304 |
| algebra | 仿射变换的扫描与归约 | 16777216 |
| bodies | 引擎粒子积分与能量更新 | 4194304 |
| body_total | 引擎粒子更新及总能量 | 4194304 |
| transforms | 引擎法线矩阵 | 4194304 |
| shade | 引擎双线性纹理采样与 GGX | 4194304 |
| resolve | 8K 内部采样转换为 4K 显示输出 | 8294400 |

`resolve` 使用正式 GPU 专属入口，固定为 3840×2160 输出、2×2 内部采样；第二个命令行参数不改变它的尺寸。其他案例可用不同规模重复观察。每批 8 轮表示同一数据上的连续计算：这既适用于连续模拟，也展示了复用 GPU 提交和保持数据驻留的用法。

## 计时范围

- `cxx_ms`：C++ 单线程算法的墙钟耗时。MSVC 使用 `/O2 /arch:AVX2 /fp:precise`，保留自动向量化；没有关闭优化或加入人为延迟。
- `b_cpu_ms`：B CPU 从调用到完成的墙钟耗时，包含范围任务的调度、集合操作及等待。CPU 原生代码在计时前生成。
- `b_gpu_wall_ms`：数据和代码已在设备上，从提交前到实际完成后的墙钟耗时，包含命令组织、提交及等待。8 轮通过现有 `submit_steps` 提交；C++ 和 B CPU 同样执行 8 轮。
- `gpu_device_ms`：GPU 时间戳记录的设备程序跨度，仅作补充。书中的主加速比用 `cxx_ms / b_gpu_wall_ms`，不把 GPU 设备时间与 CPU 墙钟时间混比。
- `gpu_roundtrip_ms`：设备与程序复用，重新上传全部数据集、执行同样 8 轮并读回可写数据集的墙钟耗时，包含这些数据集的分配与传输；主存中的输入复制在计时前完成。
- `gpu_prepare_ms`：第一次创建设备、生成 GPU 程序、上传数据和纹理的耗时，单列一次，不除以轮数。

源文件读取、B 前端编译、数据种子生成、主存初始分配以及 CSV 输出均在计算计时之外。初始数据相同，各版本的预热和测量轮数相同。速度比较针对这一台机器上的单线程 C++ 与本项目的并行实现；C++ 并行库和 GPU 框架也能利用相应硬件。

## 数据与结果

`serial.cpp` 保存完整 C++ 串行对照，`src/main.rs` 负责现有 API 的绑定与计时。C++ 的筛选和块内协作使用直接循环，排序使用 `std::stable_sort`，仿射扫描一次遍历同时生成前缀和总变换。B 使用书中相同的集合语义与真实引擎入口。

map 输入为 `(i % 17) / 8`；求和与扫描输入循环 `[3,1,4,2]`；筛选保留偶数 id，键为 `(i*7+2)%3`，权重循环 1 到 7；块内输入循环 1 到 17；仿射输入的 scale=1、bias 循环 1 到 7，保证长序列的数值范围便于检查。粒子使用有限半径中心力场；矩阵可逆且包含非对角项；材质使用实际 256×256 浮点纹理、变化的 UV 与粗糙度；resolve 包含采样均值、色调映射、gamma 和 BGRA 打包的完整计算。

程序在计时之外比较最终输出，报告浮点最大绝对差和整数不一致数量。浮点归约的分组不同，会改变舍入；`body_total` 另列逐粒子 f32 能量的 f64 累加参考，便于观察串行线性累加与并行归约的数值差异。`resolve` 的 B CPU 时间显示 `NaN`，表示该正式入口仅支持 GPU。

本次机器：AMD Ryzen 9 9950X（16 核、32 逻辑处理器）、AMD Radeon RX 9070 GRE、MSVC 14.44、Rust 1.95.0，Release 构建。正式书稿包含精选规模的时间与加速比；原始 stdout/stderr、较小规模记录保存在本机 `Saved/BookPerformance`。
