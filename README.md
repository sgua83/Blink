# Blink 语言

Blink（简称 B）是一门自研原生并行计算语言，提供 CPU／GPU 执行框架，接口为 `.h`，实现为 `.b`。Rust 前端、并行 IR、优化及后端直接生成 Windows x64／SPIR-V；不引入第三方编译器、Shader 编译器或并行运行时。当前为明确的 v0.1 子集，完整语言与极大规模目标仍在研发。

B 也寓意 **Base**。Blink 希望像 C 语言为上一个计算时代所做的那样，成为 AI 超算时代的基础语言。并行计算、数据关系与协作应成为算法的基本表达，让同一套思想从普通计算扩展到大规模异构计算。

工程目录与 P4 标识沿用 `BLanguage`，编译器命令为 `blc`，源码接口 `.h`、实现 `.b`。

独立 P4 主线 `//BLanguage/main`，client `BLanguage_Gua`，本机根 `B:\BLanguage`。首个消费者 BLEngine 位于 `B:\BLEngine`，通过两个自研 crate 的路径依赖使用语言与框架；本项目不依赖引擎。

GitHub 发布仓库为 [sgua83/Blink](https://github.com/sgua83/Blink)。P4 与 Git 共用工作目录，P4 管理正式提交；`Tools/PublishGit.ps1` 在独立进程中读取已提交版本并发布到 GitHub，Git 提交中的 `P4-Change` 标明对应 changelist。发布过程不修改工作区源码或 P4 状态，构建产物与本地连接配置不进入 GitHub。Git 错误由发布任务单独报告。

## 构建与使用

Windows x64 MSVC，使用 Rust 标准库和 Windows／Vulkan 标准接口。GPU 能力由真实程序申请，纯编译不创建设备；源码 MIT，生成物不提交。

```powershell
cargo build --workspace --release
.\target\release\blc.exe check ..\BLEngine\Programs\math\field.b ..\BLEngine\Programs
.\target\release\blc.exe build ..\BLEngine\Programs\simulation\statistics.b Saved\Compiled ..\BLEngine\Programs
```

上例显式编译首个消费者的真实算法；源文件和模块根由调用方传入。blanguage 提供编译 API，blcompute 提供原生数据及执行 API。BLEngine 的 compute 命令位于引擎项目；普通语言开发只构建本工作区。

| 位置 | 职责 |
|---|---|
| crates/blanguage | 模块、类型／访问、并行 IR、优化、x64／SPIR-V 与 blc |
| crates/blcompute | CPU 范围执行、GPU 驻留、提交、同步和生命周期 |
| Docs | 语言规范、架构、问题及原始观测 |
| Saved、target | 本地研发数据与生成物，不提交 |

## 开放 const 与具体入口

函数、协作函数、program 和记录已支持 `const N:u32`，不再要求列出所有长度。普通数组、名义记录、固定 dataset 及纹理数组的静态形状可推导 N；具体入口通过 compile_entry 或 blc 的最后一个参数选择，例如 'run<uint3,37,11>'。实例沿原编译检查后直接生成原生代码，未使用的开放正文尚不做完整符号证明，详见 [语言规范](Docs/BLanguage.md#开放-u32-const静态形状推导与具体入口2026-10-25)。

## 已实现能力与原始观测

以下承接拆分前实现；引擎算法仍在 BLEngine/Programs，记录的规模不等于完整引擎或目标性能已经达成。

Blink 已实现 CPU／GPU 不可变 `view<T>`：数据引用具有元素类型、长度与真实资源所有权，支持嵌套读取、按值函数与有界遍历。主机冻结数据由 Arc 共享；显式上传／下载可复制完整闭合引用图并生成目标地址，同次批量传输保留跨根共享，读回后可直接供 CPU 原生程序使用，不能复制裸地址冒充所有权。渲染资产通过它共享三角形／法线，不再累计历史着色池。当前优先继续开发语言与并行执行基础。所有运行资产采用独立格式；FBX 和 UE 离线转换为正式需求，当前已完成 OBJ 字形转换，尚不能声称支持 FBX。

u32 普通索引支持逐分量数值区间、分支上下界和符号资源域，域信息随向量、记录字段、参数及返回值传递：任意工作域的 index()%17 可读取固定 17 项表，掩码、无回绕算术、字段、参数与返回值共用同一证明。动态长度已证明非零时，取余关系同时覆盖 dataset、tile 与不可变 view；编译器不补运行时索引检查或扩大写权限。动态 u32／i32 标量与向量除余由逐分量非零证明支持，u32 有界表达式也可直接证明除数非零。同分子／除数的商余可在直线块合并，CPU 复用一次除法，GPU 分别编码标准运算。完整语义与限制见语言规范。

Blink 的 atomic dataset 显式表达共享修改，支持 u32/i32 的加载、存储、加减、交换、强比较交换、极值与按位操作，以及静态 relaxed/acquire/release/acq_rel 内存序。CPU／GPU 均生成原生指令，普通读写与原子访问不能混用；原子返回的数字不自动获得散写或前缀域能力。已运行争用直方图、唯一票号、单获胜者、跨页原子及 Count 驻留 GPU 的筛选流水，具体依据与限制见语言规范和问题列表。

原生集合运算现有 map、用户值函数定义的有序归约与融合投影归约、数值标量／向量及整数按位全域／分段归约、整数 sum／min／max／AND／OR／XOR 连续与分段独占扫描、浮点标量／向量连续与分段独占前缀和、稳定 compact 与 u32／i32／f32 稳定键排序；块内 tile 和 GPU subgroup 另有各自的值协作。扫描可写入记录字段并保留其他数据，GPU 的递归摘要和有效计数留在设备。多种跨 256 MiB 页的输入／输出已完成 CPU／GPU 完整核对，具体规模与未完成项见问题列表。通用 `compute` 入口直接执行自己的公开 `.h/.b` program，语义和文件格式见 [语言规范](Docs/BLanguage.md)。

`compact` 按 bool 谓词稳定筛选完整记录，并在设备上产生有效计数；已实际完成 8388611 条记录的 CPU/GPU 原始字节核对和源／目标两侧跨页复制。有效前缀的原生并行域与 GPU 间接启动已完成，同一程序可直接消费设备上的有效工作量。

`parallel (item in prefix(data, count.value))` 只执行当前已生产关系的有效前缀，编译器检查当前生产关系。GPU 自行产生多维间接参数，提交拥有临时资源；已实际核对 8388611 条记录、二维／三维启动及同一提交的多步执行。接口级 `requires prefix`／`ensures prefix` 已实现，普通执行器接收编译器构造的无前置条件入口，条件执行器通过真实数据所有权消费域关系。


有效域现在可直接参与 `reduce_sum(prefix(data,count.value).field, ...)`、`scan_exclusive_sum(...)` 和 `compact(prefix(data,count.value), ...)`。GPU 一次产生递归层级的间接参数，集合与后续并行域继续组合；已实际核对 8388611 条跨页记录、容量尾部保持、三维启动和有效数量变化的多步提交。u32／i32／f32 稳定键排序已运行，此前 u32 的跨提交有效域组合也已运行；workgroup 原子共享值与静态根块屏障已实现，动态协作与引擎完整工作队列仍需继续实现。

`stable_sort_by_key(input.key, output)` 支持完整域及 `prefix(input,count.value).key`，中间只重排键／原始序号，最终搬运完整记录一次。CPU 自研 x64 与 GPU 自研 SPIR-V 的 u32 已核对到 33554433 条，i32／f32 已核对到 4194307 条跨页记录，相同键保持原顺序，容量尾部保留；排序程序明确请求 32 lane full subgroup／ballot 能力。功能完成与性能调优分别记录，见问题 C-007。

`DomainBindings` 以实际存储所有权携带有效域，独立 CPU 程序和同队列 GPU 提交可以继续消费。`submit_after` 不先等待前项，计数保持设备驻留；五项独立程序连续执行已核对到 16777219 条记录，CPU／GPU 结果与容量尾部逐字节一致。跨 CPU／GPU 的真实传输也保留关系，裸存储提取则放弃关系。继续提交时依据已有原生 Fence 释放完成的前序命令与临时页，必要数据沿实际消费者继续存活；不再累计全部历史资源。

多生产者可经 `submit_join` 直接汇合，逻辑参数顺序独立于原生队列次序。`Submission::partition`／`into_bindings` 可转移尚未完成的独立结果，不等待、不复制数据、不申请 GPU 数据页；各分支计算后可再次汇合。存储持有真实最后使用点，丢弃或失败分支不破坏兄弟分支，观察到完成后，命令资源可先于延后消费的数据释放。已实际核对两组各 8388611 条跨页记录，以及最长 1024 轮无中间等待的分叉与汇合；正常构建另完成 257 轮，并覆盖 pending 绑定直接 join。自动背压、只读 Count 共享、多队列和设备自主任务未实现。接口与寿命说明见 [语言规范](Docs/BLanguage.md)。

Blink 已有原生 subgroup 值协作：数值标量／向量的 sum、exclusive sum、min/max，bool 投票与前缀计数，活动 lane 选举与首值广播。`.b` 内直接调用并生成自研 SPIR-V，可封装成 GPU 值函数；编译期检查目标与类型，设备按真实能力绑定，不固定 wave 宽度。本机普通协作管线实际为 64 lane，已核对 2097155 条、stride=192 的跨页完整记录、分歧与循环、GPU 有效前缀及排序后协作；输出与独立宿主参考逐字节一致。tile_atomic 与显式根块屏障已实现；非原子任意共享写、动态屏障与任意 shuffle 仍未实现；Device 作用域的 u32/i32 存储原子已实现。

`tile_input(data 或字段, width)` 将同一逻辑分块输入用于 CPU／GPU 局部协作。快照在阶段入口生产，块内只读，尾块只公开有效长度；原地写入仍只修改当前独占元素。CPU 使用对齐范围和局部存储，GPU 使用 workgroup 共享存储与统一屏障，不要求源码手写同步。编译器按实际源 word 合并记录／字段视图，未使用的捕获不分配存储。已原生核对宽度 1／3／17／64／128、GPU 有效域、多维间接调度和 3355445 条跨页记录；整数、原记录、填充与尾部正确，浮点均值的实际舍入差异单列，未称所有 CPU／GPU 输出逐位一致。语义与限制见 [语言规范](Docs/BLanguage.md)。

`tile_publish(value, width)` 已接入同一 CPU／GPU 语言链：普通计算结果在块内发布为不可变版本，编译器处理同步、私有状态延续和共享字段寿命；GPU 在一个内核内完成多次发布。已核对多版本、结构体、向量、尾块、有效前缀和 4194307 条跨页记录；五次标量发布的 128 宽度程序实际复用为 1024 字节共享存储。当前仅支持 parallel 根块的静态发布点，循环内动态发布与非原子任意共享写仍未实现。

`tile_reduce_sum`／`tile_scan_exclusive_sum` 已为 CPU／GPU 提供 f32、u32、i32 标量与向量的原生块内集合。CPU 每块计算一次，GPU 共享树与各分量复用工作区，后续可继续发布与计算；无消费者局部值连同输入与工作区消除。已原生核对宽度 1–1024、有效域与 3355445 条跨页记录。百万条、128 宽度的同算法对照及浮点误差单列于 [Issues](Docs/Issues.md)，不外推为完整引擎帧率或成熟实现对照。

Blink 的 `.h/.b` 已支持 `cooperative` 函数、`tile<T>` 只读借用和显式 `cooperate` 调用。块宽度继承调用方，字段／swizzle 不复制输入快照；函数可嵌套组合归约、发布和扫描，静态展开到同一 CPU 范围／GPU 内核。已原生核对 1–1024 宽度、有效前缀及 3355445 条跨页记录，函数库可独立 check，原生 build 仍从 program 专门化。语义与当前限制见 [语言规范](Docs/BLanguage.md)。

`tile_atomic(value, width)` 原生表达逻辑块内的 u32/i32 原子共享值，`tile_barrier()` 明确整块阶段同步；cooperative 函数可用 atomic tile<T> 借用同一来源与字段。GPU 直接使用 Workgroup 原子，CPU 在独占块存储上生成无锁指令；与 Device dataset 原子、只读发布、块内集合和有效前缀流水使用同一 IR、布局与执行框架。同步位置、访问模式、类型和索引在编译期检查；原子读取不会冻结快照，算法仍须明确生产／读取／下一次修改之间的同步。具体实现与真实运行记录见语言规范和问题列表。

`clear_prefix`／`append` 现在原生表达有界工作输出：在已有 dataset／Count 上建立空前缀，以明确 bool 接纳完整记录，阶段结束后由 prefix 消费。CPU 直接生成容量比较与 CMPXCHG，GPU 按实际活动 subgroup 合并预留并使用明确的 maximal reconvergence 能力；没有裸票号散写、隐式扩容或新的宿主队列服务。已核对跨页完整记录、满容量、分歧／循环、多个输出以及无中间 Count 读回的跨提交追加；动态任务、通用 reservation 和完整并发队列仍在问题列表中。

Blink 普通函数现可用 `atomic T` 参数借用已有的原子字段，支持记录／向量投影、嵌套转交及显式原子别名；CPU 数据集、GPU 数据集与块内 tile 共用接口，真实内存作用域由实际来源决定。索引只求值一次，借用不能转成普通值或逃逸。静态内联仍生成原有原子 IR，两类地址空间的简单 helper 与直接原子操作导出逐字节相同；整份可写 dataset 借用和动态任务仍未完成。

Blink 函数现支持整份 `read dataset<T[,N]>`／`atomic dataset<T[,N]>` 借用，可封装查表、遍历和共享原子算法，并与 atomic 字段参数、cooperative tile 函数组合。编译器按真实资源身份保留形状、边界和当前阶段权限；同权限别名与多层转交不复制数据、不新增设备提交。含只读 view 的数组继续保留真实子资源；独占可写数组借用、第一类资源引用、动态任务和完整语言仍未完成。规范及实际执行结果见 [语言规范](Docs/BLanguage.md) 和 [问题列表](Docs/Issues.md)。

Blink 已把重复 dataset／tile 长度读取关联到真实资源身份；非空、最小长度与函数返回的 bool 可以用于后续普通索引和整数除余。for 的游标比较与 parallel 的实际执行域提供作用域内的非空事实，空域仍不执行正文；分支、资源和可变值的边界保持。前端复用原 Proof 和环境，不增加运行期检查、长度缓存或设备 ABI；等式闭包、重复数据装载和完整范围分析仍在问题列表中。

Blink 普通／cooperative 函数现可用 `requires nonzero(...)`、`nonempty(...)`、`index(...,...)` 声明整数非零、资源非空与索引前提，支持向量、记录字段和只读 view。编译器在调用点证明后直接内联，算法库可以独立检查，不生成运行期断言或额外分支。program 的 prefix 关系与原宿主输入规则保持，第一类非零类型、通用精化、后置条件与完整语言仍需继续完成。

Blink 函数现支持 `inout T` 独占位置借用，可直接修改当前并行元素或局部变量的原字段，支持多层转交、互不重叠的字段与 swizzle，并与 cooperative 和显式原子参数组合。编译器拒绝别名冲突，跟踪条件／循环中的写效果，直接生成原有访存与局部 IR。现有 BLBody 模拟已接入；整份可写数组、动态任务与完整语言仍未完成，详见规范和问题列表。

Blink 现支持 `void` 普通／cooperative 函数、`write T` 输出借用与 `T name;` 无初值局部声明。编译器按实际位置证明写前不读、函数输出完整和控制流上的确定初始化；输出不创建对象，声明不补默认零，void 不伪造返回值。BLBody 积分与能量输出已使用这些语义，实际执行与当前限制见规范和问题列表。

Blink 普通函数已支持 if／while／for 中的提前返回，覆盖多层循环、void／值／不可变 view 返回与 write 输出的逐返回点初始化。相同源程序直接生成原生 x64 和结构化 SPIR-V，return 只结束当前函数；调用方 parallel 与显式协作阶段继续执行。GGX 直射计算已使用背光提前结束。cooperative 提前返回、动态任务、完整语言与完整引擎仍未实现，原生执行记录见 [问题列表](Docs/Issues.md)。

Blink 已支持受约束的数值泛型函数，覆盖 12 种 32 位标量／向量、普通与 cooperative 函数，以及数值元素资源和位置借用。编译器检查全部允许类型，从实际调用推导后直接生成原 x64／SPIR-V，不做运行期类型分派。中心力场已接入；记录泛型见下文，有限常量参数与用户类型集合见下文，完整语言仍待继续，详见规范及问题列表。

Blink 已支持有限数值参数的泛型记录、显式构造、嵌套字段及从名义记录推导函数类型参数。BLBody 已改为 BLBody<T,Power>，正式模拟仍用 BLBody<float3,3>，物理字段布局保持；记录可作为既有 dataset／tile／view 元素，资源权限和寿命仍归原所有者。类型元数据不进入物理载荷，具体原生执行与未完成项见规范及问题列表。

Blink 已支持用户定义的有限类型集合：算法可在同一约束下处理布局不同的普通记录及具体泛型记录，全部成员在编译期检查，实际调用直接生成原生代码。BLBody 积分已使用 BLSimulatedBody 集合；集合成员不是运行期混合元素，开放接口约束／关联类型及完整语言仍待继续。

Blink 的泛型已覆盖函数、记录与并行 program：同一套有限数值／用户类型集合在编译期确定实际布局和算法，program 调用从原数据绑定推导类型，并沿原阶段、权限与有效前缀规则组合。simulation.bodies 的四种 BLBody 布局共用 integrate／energy／step，statistics 继续直接消费 BLBody<float3,3>。泛型入口按完整具体名字执行，例如 `step<simulation.bodies::BLBody<float3,3>>`；详见 [语言规范](Docs/BLanguage.md#泛型并行-program-与阶段组合)。一般值域、开放接口、动态任务和完整语言仍未完成。

Blink 现支持模块级 const、跨模块依赖和命名数据集形状；向量／记录／bool 常量可直接进入阶段组合，已知一元运算与转换在编译期折叠。引擎渲染现由实际输出目标专门化 W／H／S 和 dataset 数量，不再使用固定 render.dimensions；BLEditor 消费者仍明确保持实际 4K／内部 8K。初始化无法完全求值时编译失败，不执行运行期初始化；一般值域与一般编译期解释器仍未完成。

Blink 的函数／cooperative／program 已支持有限 u32 const 参数及显式类型／值调用，例如 `sum<T:numeric,const Width:u32 in {17,65}>` 和 `sum<uint3,65>(cells)`；也可只给值并推导类型。所有允许实例都编译检查，形状和块宽度在实例中固定，运行时不新增分派或参数。中心力场已用 Power∈{1,2,3} 专门化，现有模拟选择 3。一般值域、一般高阶参数与完整语言仍未完成。

Blink 的记录现可带有限 u32 const 参数，算法可从实际记录、嵌套记录和资源元素推导这些值，例如 BLBody<T,Power> 自动选择中心力场模型。CPU／GPU 消费同一具体实例；const 模型身份不增加记录字段或运行期模式参数。检查与调用从唯一原声明生成实例，已删除全局展开表；一般值域、符号泛型分析及完整语言仍未完成。示例与推导边界见 [语言规范](Docs/BLanguage.md#记录-const-参数与名义值推导)。

Blink 集合算法现支持显式泛型函数引用，如 identity<uint3,7>、compose<Affine<uint3,Mode>> 和 bind(project<Mode>,offset)。归约／扫描在编译期确定算法实例，CPU／GPU 继续直接执行原生计算；没有普通参数的单位元也能明确指定类型。完整示例和使用范围见 [语言规范](Docs/BLanguage.md#静态泛型算法参数)，一般高阶参数与动态分派仍未实现。

Blink 已支持九种 2–4 行／列的 f32 矩阵、行字段、行列乘法、转置、行列式及逆矩阵。math.transform 用 B 提供空间变换库，现有相机射线已经接入；矩阵直接降低到原生标量 IR，可用于函数、数据集和并行集合。布局、运算顺序及数值限制见 [语言规范](Docs/BLanguage.md#固定维度矩阵与空间变换)，一般维度矩阵与完整语言仍待继续。


Blink 已支持固定内联 array<T,N>、嵌套值／矩阵／不可变引用数组、固定长度泛型推导和已证明范围的动态下标。CPU／GPU 直接寻址，初始化、只读与独占冲突在编译期处理；三角形法线索引已接入同一数组布局。固定数组用于普通聚合，大规模存储继续使用 dataset／view；固定数组的动态 u32／i32 原子下标已支持，完整语言继续开发。示例与边界见 [语言规范](Docs/BLanguage.md#固定内联数组与原生下标2026-10-25)。


动态原子数组访问沿用原 dataset／tile、函数借用及显式内存序，可直接编写嵌套计数桶和块内并发累加。已运行争用票号／交换／比较交换、带填充聚合、GPU 分区和跨 256 MiB 页的逐记录状态转换；原子返回值仍不授予任意散写权限。64 位／浮点原子、设备自主动态任务与完整引擎仍未完成。

只读纹理数组可在资源参数位置以 `unsafe_read(maps,index)` 接收外部资产边界建立的编号关系，继续使用原生采样与只读函数借用。普通下标的静态证明要求保持；资源不进入普通值或逃逸，实际图像由原提交持有。BLEngine 已用该能力接入正式材质资产与全图 UV／分组采样，详见语言规范和引擎记录。
